Automating what you've done manually

The goal

Generate Instances produces design datasets from Attributes and their values. These rows are not executed tests; template mapping and instantiation are separate steps. Choose the method and scope according to required coverage, rather than assuming automatic generation establishes completeness.

How it works

Right-click a TestSheet, TestCase-Design Class or Attribute and choose Generate Instances with the desired method. You can Ctrl-select specific Attributes or Instances for a narrower scope. The documented default maximum is 1000 combinations; generation is not promised to be instantaneous for every dataset.

Generating at an Attribute or selected scope

Documented target and Instance collection

The generation article documents TestSheet, Class and Attribute targets without requiring a manually created empty folder. The Instances article states that creating the first Instance in an Attribute automatically creates its Instances Collection. The historical add-then-delete folder workaround is not established as a universal prerequisite by these accessed articles.

Generating

For a selected scope, hold Ctrl while selecting the Attributes or Instances, right-click one of them and choose Generate Instances followed by the method. Inspect the generated combinations and unused values; do not assume all other Attributes were included.

Linear Expansion requires a defined StraightThrough path. It builds baseline variations by switching one StraightThrough choice for a non-StraightThrough choice. Define and inspect that baseline before generating; the accessed docs do not describe a guaranteed fallback or exact error dialog when it is absent.

Generating at the TestSheet level

Generate at the TestSheet

Right-click the TestSheet and select Generate Instances followed by the desired method. Inspect the resulting combinations, nested data usage and scope. Generated rows are held in an Instances Collection beneath the relevant TestSheet.

Keep relevance and verification distinct: BusinessRelevant = Yes marks business-relevant data (the default), No marks non-business-relevant data, and Result is used for verification. Sub-Attributes inherit a changed parent relevance. Result is not an instruction to skip assertions. The accessed articles do not fully specify a universal exclusion algorithm for every generation method.

Generate Instances vs Complete Instances

Initial generation versus extending coverage

Use Generate Instances for generation with the selected method. When additional values need to join existing combinations without duplicates, the documented operation is Complete Instances. The accessed article does not justify calling every Generate operation a destructive rebuild.

Complete Instances

Complete Instances combines values not previously combined, without creating duplicates. Uncombined Instances appear in bold. Right-click a TestSheet, Class or Attribute, select Complete Instances, then choose the method. Inspect the resulting coverage; this does not guarantee completeness beyond the chosen method and scope.
