The four combinatorial methods

All Combinations

Every possible combination of Instance values across the combined Attributes is generated. This produces the highest number of TestCases — for 3 Attributes with 3 Instances each, that's 3 × 3 × 3 = 27 combinations. Thorough, but the TestCase count (and execution time) grows very fast as Attributes/Instances are added.

Orthogonal

Produces the lowest possible number of combinations. The only requirement is that every Instance value is used at least once. The number of resulting combinations equals the highest Instance count among the combined Attributes — for 3 Attributes with 3 Instances each, that's just 3 combinations. If Attributes have unequal Instance counts, values from the Attribute(s) with fewer Instances repeat until the Attribute with the most Instances is exhausted.

Pairwise

Combines every possible pair of values between two Attributes. Not a primary focus of this course.

Linear Expansion (Tricentis-recommended)

Starts from a StraightThrough baseline — the first TestCase uses the StraightThrough Instance from every combined Attribute (essentially the smoke test). Every subsequent combination swaps out exactly one StraightThrough Instance for a single non-StraightThrough Instance. This continues until every non-StraightThrough Instance has appeared at least once. Each generated TestCase therefore differs from the baseline in only one place, giving it a clear, isolated test focus.

Choosing a method

It depends on the project

The right method depends on the Requirement's specification level, regulatory/legal constraints, and project context. Some industries mandate All Combinations for specific high-risk Requirements. Where there's no such constraint, Tricentis recommends Linear Expansion as the default because of its balance between coverage and clarity of test focus.

Building combinations manually in Tosca

Instances as combination columns

Once generated, combinations appear as Instance columns on the level where they were built — at the TestSheet level, or at an individual Attribute's level. Each combined Instance column represents one TestCase-to-be. Under Linear Expansion, the first generated column is the all-StraightThrough baseline; each subsequent column swaps in one non-StraightThrough value.

Combining at Attribute level vs TestSheet level

Combinations don't have to be built only at the top TestSheet level — they can also be built lower, on an individual Attribute (e.g. combining just the sub-Attributes under 'Credit Card'). Once an Attribute-level combination exists, the TestSheet level only needs to reference the Instance name from that Attribute, and its values auto-populate. Attribute-level combinations show highlighted in light yellow at the TestSheet level, so you can see at a glance that a block of data was pre-combined lower down.

You must be focused on a particular level (TestSheet or a specific Attribute) to see that level's Instance columns.

Keeping a TestSheet manageable

Arrange Instances

Right-click the TestSheet, or use 'Optimize Instances' → 'Arrange Instances' in the Ribbon, to sort Instance columns into a consistent order: StraightThrough first, then Valid Inner, then Invalid, then Boundary, then Invalid Boundary.

Merge Instance Duplicates

Available in the Ribbon and the context menu — finds Instance columns that are identical and removes all but one, keeping the TestSheet lean.

Hover over the TestSheet icon to see how many Instances exist at that level.

Press F9 to hide/reveal the Instance rows in the TestCase Design section. This doesn't delete anything — it's purely a view toggle to make large, complex TestSheets easier to read at a glance.
