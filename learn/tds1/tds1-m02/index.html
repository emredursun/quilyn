TestSheets and Attributes

TestSheet

The highest-level object in the TestCase Design section. A TestSheet organizes the test data and logical test structure for one Requirement — as a rule of thumb, one TestSheet is created per Requirement, and the TestCases built from it will cover that Requirement.

Attribute

A characteristic or business object involved in the behavior being tested — for example, a credit-card drop-down on a checkout form. Attributes describe *what varies*; the specific values an Attribute can take (e.g. Visa, Mastercard) are added later as Instances (Lesson 3).

Structuring Attributes

Like Requirements, Attributes can be layered — every Attribute may have sub-Attributes, depending on how much detail the TestSheet needs.

AttrType: Logical vs Physical

AttrType is system-determined, not user-set

Every Attribute has an AttrType property with value 'Logical' or 'Physical'. This isn't something you choose from a dropdown — Tosca sets it automatically based on structure: an Attribute with sub-Attributes underneath it is Logical; an Attribute with none is Physical.

The four core Attributes

Recommended structure

Tricentis recommends starting every TestSheet with four top-level logical Attributes, so that any reader can immediately see the role each block of data plays.

BusinessRelevant property

Three possible values

BusinessRelevant is set by the user (unlike AttrType) and controls whether an Attribute's data affects TestCase combinations.

Setting BusinessRelevant on a parent Attribute propagates that value down to all of its sub-Attributes.

Building it in Tosca

BusinessRelevant is set on the Attribute's Properties tab (Yes/No/Result dropdown), or toggled with Ctrl+F7 or the corresponding Ribbon button. The Attribute's color changes in the tree to reflect its current value.
