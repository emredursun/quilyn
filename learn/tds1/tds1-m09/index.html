Design for reuse

Spot reuse early

Use a centrally managed Class for repeated Attribute structures. Unresolved references share changes in both directions: editing the reference also changes the Class. Resolve a reference before making a consumer-specific change; other consumers can remain shared. Decide on reuse from actual maintenance needs, not a mandatory two-use threshold.

An optional organizational layout

Independent Quilyn layout: Administration for non-business data, Precondition for setup, Process for actions and Verification for expected results. This four-group skeleton is one modeling choice, not a documented requirement for every TestSheet. Match the hierarchy and relevance to the test objective.

Structuring for Agile: Given-When-Then

Given-When-Then

A template for writing acceptance tests for user stories, useful when TestCase Design needs to reflect an Agile way of working. An acceptance test built this way has three parts: Given (the context and preconditions), When (the action being carried out), Then (the observable, expected outcome).

Worked example

Independent example: Given a returning customer is logged in and has a saved shipping address, When the customer opens checkout, Then the saved address is displayed for confirmation. Keep the observable address result separate from a later order-submission action; each assertion should state the behavior being tested.

In this optional layout, Given maps to Precondition, When to Process and Then to Verification. This is a conceptual mapping; Tosca does not automatically execute Gherkin merely because those Attribute names are used.

Building structure outside Tosca first

Why plan externally

For a large or complex TestSheet, it can be faster to sketch the Attribute hierarchy in Notepad or Excel first, then import it in one shot, instead of creating each Attribute by hand inside Tosca.

Try a small sample before importing a large hierarchy. Clipboard import creates structure; verify the data, combinations and template mapping separately.
