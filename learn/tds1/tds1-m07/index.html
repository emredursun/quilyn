Why link TestCase Design back to Requirements

Purpose

Linking gives an early-stage overview of how much of the planned test design work maps onto the defined Requirements — how much of the project has actually been thought through and structured, before a single physical TestCase is built.

How to link

Drag and drop

Drag Instances from the TestSheet onto their matching Requirement. If every Instance on the TestSheet belongs to that Requirement, the whole TestSheet can be dragged at once. If only some Instances are in scope right now — for example, only the ones planned for the current sprint — select and drag just those individual Instances instead.

TestCase-Substitute link

The result of linking Instances to a Requirement before any physical TestCase exists. It's a placeholder link showing how many TestCases will eventually need to be built in the TestCase section to cover that Requirement.

TestCase link

Once the physical TestCases are actually built (in the blue TestCase section) and linked to the same Requirements, the earlier TestCase-Substitute links become full TestCase links — reflecting real, executable TestCases instead of a planning placeholder.

TestSheet-to-Requirement ratio

Rule of thumb: one TestSheet per Requirement

A TestSheet should contain all the TestCases needed to cover its Requirement. In sprint-based projects this can differ slightly — one TestSheet might accumulate TestCases created across multiple sprints for the same Requirement, rather than being rebuilt each sprint.

Building the project dashboard

ExecutionLists link to RequirementSets, not individual Requirements

When ExecutionLists are created, they are linked to the whole RequirementSet rather than to a single Requirement. This rolls up progress across the entire set: which TestCases have been defined, which Requirements are actively being worked on, how far along the project is, and — once executions have actually run — which passed and which failed.

Together, this chain (TestSheet → Requirement → TestCase → ExecutionList → RequirementSet) is what turns the Requirements section into a live project dashboard inside Tosca Commander.
