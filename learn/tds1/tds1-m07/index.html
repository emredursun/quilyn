Why link TestCase Design back to Requirements

Purpose

Requirement links distinguish planned design data from physical TestCases and execution evidence. A TestSheet or selected Instances can establish planned coverage before executable tests exist; this is not proof that the application was tested successfully.

How to link

Drag and drop

Drag Instances from the TestSheet onto their matching Requirement. If every Instance on the TestSheet belongs to that Requirement, the whole TestSheet can be dragged at once. If only some Instances are in scope right now — for example, only the ones planned for the current sprint — select and drag just those individual Instances instead.

TestCase-Substitute link

Linking TestSheet, Class or Instance data creates a substitute for each linked Instance. A substitute represents planned test data, not an executed or passed test.

TestCase link

Creating a physical TestCase does not by itself replace its substitute. Drag the TestCase onto the corresponding substitute link. Alternatively, use Replace Substitutes by Testcases on the RequirementSet; the required TestCases must be used in an ExecutionList and that ExecutionList must be linked to the RequirementSet.

TestSheet-to-Requirement ratio

Organize coverage around Requirements

The documentation recommends TestSheet coverage for application Requirements. Choose a structure that keeps each Requirement traceable; the same Requirement can receive selected Instances or Class data. One TestSheet per Requirement is a useful organizational choice, not a prohibition on other documented link scopes.

Building the project dashboard

Link an ExecutionList to a RequirementSet

Drag an ExecutionList onto a RequirementSet to create its link. Merely creating the list does not establish this relationship. An ExecutionEntry can separately be dragged onto an individual Requirement to create a TestCase link. Its LinkExecutionEntryHandleExecutionList setting controls whether the associated ExecutionList is added to the set: AlwaysAdd, AskUser or NeverAdd.

The dashboard also needs current calculations. AutoCalculateRequirements is off by default. Use Update Outdated Values on a RequirementSet (or the Requirements menu for all sets), or enable automatic calculation in Commander > General > Advanced and restart Tosca. A blue exclamation mark indicates outdated values.
