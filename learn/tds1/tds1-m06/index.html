What a Class is

Class

A reusable Tosca object — conceptually similar to a Library in the TestCase section — that lets you define an Attribute structure (with its Instances and combinations) once and reuse it across many TestSheets via a Class Reference. A typical candidate is data that shows up repeatedly, like a Customer Attribute structure used by every TestSheet that touches customer data.

Why it matters

Class and reference editing are bidirectional: source changes update references, and editing an unresolved reference changes the corresponding Class. Resolve the reference first if you need an independent local variation.

Documented Class creation

Dragging an Attribute WITHOUT top-level combinations

If selected Attributes have no child elements, the documented prompt offers Create Class from Attribute (Class plus Instance collection) or Create Structure from Attribute (Class without an Instance collection). The reference does not describe this as importing all source TestSheet combinations.

Drag a Class onto a TestSheet, another Class or an Attribute to create its reference.

Working with Class References

Editing a Class

Once created, a Class can be modified exactly like a TestSheet — add or remove Attributes, create or delete Instances, adjust combinations, and set Character/Position on its Instances.

Resolve Class Reference

Resolve Class Reference removes the shared reference and returns it to an Attribute. Use this before making an independent local variation. Do not assume resolving one consumer removes other live references or makes deleting the source safe for all of them.

Unused Instances vs irrelevant Attributes

Unused combinations and deactivated Attributes are different concerns. Add the Relevance column, select a reference and disable the checkbox for an irrelevant Attribute. It becomes gray; F11 shows or hides deactivated Attributes. Deactivation is more than renaming or deleting a data value.
