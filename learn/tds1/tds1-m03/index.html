What is an Instance

Instance

A concrete variation/value of an Attribute — for example, if 'Credit Card Type' is the Attribute, then Visa, Mastercard, and Amex are its Instances. Instances are added via the Ribbon, 'Add Instance' in the Mini-Toolbar, or the shortcut Ctrl+N, Ctrl+I.

Unlike Attributes, Instances cannot have sub-Instances — they are always a leaf value.

Character: Valid, Invalid, StraightThrough

Valid (default)

A white Instance icon with an 'I', outlined in red. Applying a Valid Instance should NOT produce an error in the process.

Invalid

Same icon style but with an 'X' instead of an 'I'. Applying an Invalid Instance SHOULD produce an error or error message — this does not mean the TestCase fails; a correctly-appearing error message is a pass for an Invalid TestCase. Example: testing login with an invalid password should verify the user is NOT logged in and the correct error message appears.

StraightThrough

A special category of Instance chosen according to specific criteria: it should be high-risk if it failed, easy to implement, and have the fewest dependencies (so it can combine with as many Instances from other Attributes as possible). Often called the 'happy path' and typically included in the smoke test.

Toggle Character via right-click → 'Toggle Character' (click once for Invalid, twice for StraightThrough) or the shortcut F7.

Position: Inner vs Boundary

Boundary Value

A value at the edge of a valid range. If an accepted age range is 1-99, the values immediately around each edge (0, 1, 99, 100) are Boundary Values — they carry a high probability of error because off-by-one logic mistakes (e.g. '>1' coded instead of '>=1') tend to surface exactly there.

Why Boundaries are usually one-time tests

As long as the range doesn't change between releases, a Boundary error is a one-time class of bug — so Boundary Values are typically used in one-time tests rather than every regression run.

Inner Value (default)

Any value in the range that isn't immediately around a boundary — e.g. 2 through 98 in the age example. These don't need to be tested one by one; instead, group them into a single representative Instance called an Equivalence Class (e.g. one Instance covering 2-98, optionally randomized at execution time using a Tosca RND expression). Equivalence Classes are a good fit for regression tests.

Toggle Position via F8, or 'Toggle Position' from the context menu. Boundary Instances show small red dashes around the 'I' in their icon; Inner Values look like a normal Instance icon. Both can be either Valid or Invalid.

Equivalence Classes aren't mandatory for every Attribute — if an Attribute only has a small number of specific discrete values rather than a range, just define those specific values directly.
