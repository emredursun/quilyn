From combinations to physical values

Why more filling-in is needed

Generated combinations still need the input, metadata and expected values required by your test implementation. Independent Administration/Verification labels describe their intended purpose; filling them does not by itself create or execute assertions.

Inspect the resulting dataset after changing values or structure. Do not assume an unchanged row count proves that every association and expected outcome is still correct.

Fill Empty Values

Fill Empty Values → Specific

The documented Fill empty Values → Specific action fills empty fields using a selected value; if an Attribute has no Instances, you can supply a custom value. Orthogonal filling instead uses child Instance values. Confirm the target selection and the resulting fields before generating tests.

Filtering before filling

When one value per row isn't enough

Independent example: use different stage labels for selected tests according to your plan. Boundary checks can belong in regression; they are not automatically one-time tests.

Using the Filter Column

Add the Filter column with Column Chooser to filter Instances at TestSheet or Attribute level. Inspect the active selection and resulting values rather than relying only on display color.

Hovering over the TestSheet shows filtered values. Remove an active filter with Reset Instances Filter. Verify intended data edits; these source pages do not establish that every bulk-fill command is confined by the current visibility filter.

Direct values and template data binding

Custom values

The dynamic-menu reference allows a user-specific value when an Attribute has no Instances. Confirm that the selected data scope and intended row agree; the previous blanket claim that higher-level entry always corrupts combinations is not established by the accessed documentation.

Template binding

For automated tests, link the TestSheet or Class to a TestCase Template. SchemaName identifies the linked source. Automatic XL paths require empty TestStepValues whose names uniquely match Attributes; manually check those paths before creating the TemplateInstance.

Review before generation

Independent checklist: inspect actual values, clear accidental filters, check expected results and XL paths, then generate and inspect the executable tests. Original Academy video/exercises require authentication and were not reviewed.
