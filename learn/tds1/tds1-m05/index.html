From combinations to physical values

Why more filling-in is needed

The previous lesson combined the business-relevant Process data needed to determine how many TestCases exist. Now the TestSheet still needs its non-business-relevant and Result Attributes populated (typically Administration and Verification) — these are the actual values that will later be linked to TestStepValues when the physical TestCase Template is built in the blue TestCase section.

Adding new Attributes or Instances that are not business relevant (or are Result) does not change the number of combinations already generated — only BusinessRelevant = Yes Attributes drive combinatorics.

Fill Empty Values

Fill Empty Values → Specific

Right-click an Attribute and choose 'Fill Empty Values' → 'Specific' to populate every empty cell in that Attribute's row with one chosen value in a single action — for example, setting 'Test Designer' to the same name across every TestCase column at once. If Instances already exist for that Attribute, simply pick the desired Instance from the dropdown and every empty cell is populated.

Filtering before filling

When one value per row isn't enough

Sometimes different TestCases in the same row need different values — e.g. the StraightThrough should be tagged as a smoke test, Inner Valid Instances as regression tests, and Boundaries as one-time tests. Filling the whole row at once won't work here; filtering first does.

Using the Filter Column

Make the Filter Column visible via the Column Chooser. On the level you want to filter (e.g. the TestSheet level, to filter its Instances), a dropdown lets you deselect 'ALL' and choose specific Instances, or filter by Character/Position (Inner, Valid, Boundary, etc). With the filter active, only the matching columns are visible/editable, so you can enter values just for that subset.

A filtered row — and the TestSheet itself — turns blue. This is a deliberate visual warning so you notice if a filter was left active on a lower level and forgot about it. Reset by re-selecting 'ALL' in the filter dropdown, or right-click → 'Reset Instances Filter'.

Value Attributes

What a Value Attribute is

A Value Attribute is simply an Attribute with no Instances and no sub-Attributes defined. Instead of adding Instances and selecting them, you type the actual value directly into the cell on the TestSheet — for example, typing a real email address rather than creating an 'Email' Attribute with Instance values.

The critical rule: enter at the lowest combined level

A Value Attribute's data must be entered at the lowest level on which its related Values were already combined — not necessarily the TestSheet level. For example, if an email address is tied to the 'Registered' Instance of a 'Type of User' Attribute, the email must be typed in at the 'Type of User' level. Entering it at the TestSheet level instead makes Tosca think you're defining a brand-new, different 'type of user' variation — which breaks the existing combinations rather than attaching data to the one that already exists.
