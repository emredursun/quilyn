Why this comes up

The scenario

Applications evolve — new features get added to the system under test after a TestSheet already exists. When a new feature affects existing test data, the TestSheet needs a new Attribute (and its Instances) integrated into the structure that's already in place, without starting over.

Where to add it

Create the new Attribute wherever it logically fits in the existing structure — it can be added right alongside Attributes that already have combinations, even if that means the existing combination set now needs to account for it.

Updating combinations at every level

The core rule

After adding the new Attribute and its Instances, combinations must be completed at every level, from the lowest Attribute up to the TestSheet. Depending on the case, this can mean two different things.

At every level touched, double-check there are no missing values — this applies to lower Attribute levels and the TestSheet level alike.

Worked example: adding a Shipping Method

The change

A WebShop adds a new 'Shipping Method' choice at checkout, affecting shipping cost. This requires a new 'Shipping Method' Attribute with Instances for each option: Ground Shipping (the default/StraightThrough — 'Standard'), Next Day Air, Second Day Air, and an 'N/A' Instance for cases where shipping doesn't apply (e.g. In-Store Pickup, No Shipping).

Updating the lower (Checkout) level

Existing Checkout-level Instances need the new Attribute's value filled in: the existing 'Standard'/StraightThrough Instance gets 'Ground', and the existing In-Store Pickup / No Shipping Instances get 'N/A'. Because Next Day Air and Second Day Air don't correspond to any existing Checkout Instance, two brand-new Checkout-level Instances are created for them — populated with StraightThrough values everywhere except the new Shipping Method field, which takes the respective new value.

Updating the TestSheet level

The existing 9 TestSheet-level Instances each need the correct Checkout Instance selected for their row. Then, matching the two new Checkout-level Instances, two new TestSheet-level Instances are added — all StraightThrough values, except the Checkout Attribute, where each selects its corresponding new Checkout Instance (Next Day Air / Second Day Air).

Don't forget: re-link to Requirements

Newly created Instances are NOT automatically linked to Requirements. After integrating a new Attribute, manually link the new Instances to the Requirement(s) they test, so the corresponding TestCase-Substitute links are created (see Lesson 7).
