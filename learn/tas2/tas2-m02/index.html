Why Templates?

Independent example: four selected size combinations share an automated flow. A Template models that flow and linked data supplies its variations; generate concrete tests through a TemplateInstance.

Designing cars: some are blue, some black, some silver; some manual, some automatic. It would be wasteful to design every variant from scratch. Instead, you design ONE base car (the blueprint) and spin off variations from it. A Template is exactly this blueprint — a base TestCase that spins off into a series of similar TestCases, each with a slightly different test focus.

Template

Centralize the common flow in the Template. Existing generated tests need reinstantiation to reflect later model/data edits; merely editing the Template does not update every generated case. Review manual changes before regeneration.

Converting a TestCase into a Template

Use the independent size-data example from the preceding lesson. Reusable block references are supported in Templates; resolving all references is not a universal conversion prerequisite.

Preserve a recoverable copy before changing model structure. Do not assume that saving defines a universal Undo boundary.
