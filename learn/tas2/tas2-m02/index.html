Why Templates?

Creating one individual TestCase per TestSheet row works, but it's repetitive and each TestCase needs individual maintenance — especially when a change falls in an area not suitable for a ReusableTestStepBlock. A Template solves this: it's a single TestCase that automatically generates a whole series of TestCases from the data in a TestSheet.

Designing cars: some are blue, some black, some silver; some manual, some automatic. It would be wasteful to design every variant from scratch. Instead, you design ONE base car (the blueprint) and spin off variations from it. A Template is exactly this blueprint — a base TestCase that spins off into a series of similar TestCases, each with a slightly different test focus.

Template

Designed to contain all possible paths of a linked TestSheet. When the Template is modified to reflect a SUT change, those modifications automatically feed through to every TestCase generated from it — centralizing maintenance and making full risk coverage far more time-efficient.
