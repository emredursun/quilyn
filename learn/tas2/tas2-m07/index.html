Scenario: Discount Codes

The developers added a Discount Code feature: entering the correct code (exact syntax) unlocks a benefit — one code removes shipping costs, another gives a flat $5 discount regardless of order total. An incorrect code must be rejected with a message, and no discount applied. You must test that the right discount applies for each valid code, and that invalid codes are rejected with no discount given.

Before attempting this exercise, re-watch Lesson 2 (Building a Template), Lesson 3 (Linking Values and Instantiation), and Lesson 5 (Setting Conditions) — this lesson combines all three into one end-to-end task.

End-to-End Recap: Building a Working Template

Exercise 7a: Build the Template

Not every folder gets its Reference resolved when building a Template from a more advanced TestCase. "Precondition_Reference" and "Order Product_Reference" stay as References here — only the folders that need Template-specific changes get resolved.

Exercise 7b: Link Values

{MATH[]} and {B[]} syntax

{MATH[...]} runs an inline calculation in a TestStepValue — e.g. multiplying a buffered price by a buffered quantity to get the Sub-Total. {B[Name]} reads back a value that was buffered earlier in the TestCase (via a "Buffer" TestStepValue), so the Shipping, Discount, and Total rows can reuse {B[SubTotal]} and {B[Shipping]} instead of recalculating them from scratch.

The Discount TestStepValues need a leading minus sign in their {MATH[]} formula — a discount must verify as a negative number, since it's subtracted from the order total.

Hints from the exercise: clear a TestStepValue's existing value before dragging a new XL reference onto it — Tosca appends the new XL to the end of the current value rather than replacing it. If a {MATH[]} calculation isn't evaluating correctly, check whether the TestStepValue's DataType needs to be switched to "Numeric". Tosca's decimal separator and other number formats live under Settings → TBox → Number formats.

Exercise 7c: Set Conditions & Instantiation

Invalid Instance symbol

Recall from Lesson 1: an Invalid Instance is symbolized by an X in the center of a square and contains a value the SUT should reject. For a Discount Code TestCase, once the invalid code is rejected, the verification is complete — the order process should stop there rather than continuing needlessly.

On the TestStepFolder level, an invalid-Instance TestCase should stop right after Verify Application, skipping the Workflow and Verification folders entirely and jumping straight to the Postcondition.

Writing one long Condition string with an OR operator for every possible Instance is impractical, hard to read, and high-maintenance.

The Instance.Character != "Invalid" trick

Instead of enumerating every valid Instance with ORs, set the Workflow and Verification TestStepFolder Conditions to 'Instance.Character' != "Invalid". This single, business-readable condition means: run this folder every time the current Instance is NOT Invalid — automatically covering every valid case without listing them individually.

Unlike Conditions built from TestSheet Instances, the Instance.Character condition can't be dragged and dropped — it must be typed manually into the Condition column.

Wrap Attribute names that contain spaces in single quotes in the Condition column (e.g. 'Workflow.Discount Assignment'). Attribute names without spaces can skip the quotes. Drag and drop the relevant Instances onto the Condition fields first, then adjust the logical statement.

If Tosca reports "No matching tab was found", the module is usually unstable — rescan the module and remap the elements to fix it.
