Why Conditions Are Needed

You want to validate that a green car is automatic and a blue one is manual. If both validations sit in the same TestStep, the TestCase would try to check for BOTH transmissions at once — and always fail, since a single car can't have two competing validations.

Conditions solve this: they tell Tosca to apply a validation (or any TestStep/Folder/Value) ONLY when a specific prerequisite is met — e.g., verify the green success message only when a positive quantity was entered, and skip it when a negative one was.

Three levels Conditions can be set on

Conditions instruct Tosca when to use — or skip — certain elements:

  • TestStepFolder level — the rule applies to running the ENTIRE folder's contents.
  • TestStep level — applies to that one TestStep.
  • TestStepValue level — applies to just that specific Value.

Using Conditions well means only ONE Template is needed to cover multiple paths — instead of maintaining several near-duplicate Templates by hand. Changes only need to be made in one place, and they apply automatically to every generated TestCase.

Setting a Condition

Operator / StatementMeaningExample
==The element must equal this value for Tosca to run the TestStep.Instance must be 'Valid' for this TestStep to run.
!=Not equal to / everything except — runs for every value EXCEPT the one specified.'Take the exam' != 'Teacher' → only students take the exam.
ANDALL listed conditions must be met.Used when multiple conditions must simultaneously hold.
ORANY ONE of the listed conditions must be met (Tosca's default when combining 2+ conditions).Avoid stacking many ORs — it gets hard to read/maintain.

Real example from the Payment Process Template: 'Workflow.Payment Method.Credit Card' != "No Credit Card used" runs the TestStep for ANY credit card used, using a single != condition instead of one OR per card type — far more business-readable.

Prefer != over stacking many OR conditions. Piling up several OR layers to cover 'everything except X' makes the Condition set hard to read and maintain — a single != achieves the same result more simply.

How to tell if an element already has a Condition set: check whether its icon has changed in the Navigation pane — Tosca visually marks TestStepFolders, TestSteps, and TestStepValues that carry a Condition, so you don't have to open each one to check.
