Linking a TestSheet to a Template

A TestSheet or Class supplies data to the Template. The Template models the flow; a TemplateInstance contains the generated concrete tests.

With the Template selected, Jump to Schema Definition (Ctrl+J) navigates to its schema. SchemaName also identifies its linked TestCase-Design source.

Linking Values (the XL Reference)

Tosca can create XL paths automatically for empty TestStepValues whose names uniquely match source Attribute names. Inspect those generated paths. Other values need an explicit path; linking a source does not guarantee every mapping is complete.

Check Template

Check Template compares the model against its schema, including Attribute references, specified conditions, custom properties, TCPs and InstanceName. It does not prove correct business logic or successful live-SUT execution.

A successful schema check is not an execution test. Review expected results and run the generated cases.

Manual XL paths such as {XL[Attribute.SubAttribute]} are supported. Automatic mapping or drag-and-drop can reduce typing, but neither guarantees semantic correctness; inspect the source path and expected meaning.

Instantiating the Template

Instantiation needs a Template, a linked data source and correctly mapped values. WorkState is inherited by generated cases; Completed is not listed as a universal prerequisite for creating the TemplateInstance.

For the hypothetical four-combination example, inspect the generated set rather than assuming each Attribute value becomes one test. Conditions, Break and selectors may affect the generated subset; the Template and data links remain model dependencies.

Independent Practice: Mapping and Generation

Use synthetic login combinations. Link their TestSheet, inspect each XL path, check the model and generate a TemplateInstance. Compare a representative valid and negative case with the intended assertions. Original Academy exercise instructions were inaccessible and remain unverified.
