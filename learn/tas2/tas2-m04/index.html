Scenario: A New SUT Feature to Verify

Independent hypothetical requirement: positive quantity 4 should produce a success message, while -4 should produce a defined validation error. Model the expected output in an Attribute with BusinessRelevant = Result and map it to a Verify TestStepValue. The Attribute property alone does not change a TestStepValue’s ActionMode. Review the assertion’s expected text and the actual control/property being verified. This example does not certify the current Demo Web Shop behavior.

Modifying an Existing Template

Inspect the intended model and data changes. Keep shared Library reuse unless a deliberate local copy is needed. Confirm SchemaName and the TemplateInstance data source rather than assuming a new schema link redirects every existing instance. Inspect all XL paths, map expected output to Verify, and run Check Template. Preserve manual edits and relevant execution evidence before regeneration; deleting the old TemplateInstance is not a universal prerequisite. A TestStepValue can contain a composed expression, so it is not universally limited to one XL reference. When deliberately replacing its mapping, edit the expression and inspect the resulting path.

Instantiate vs. Re-Instantiate

Create TemplateInstance generates a container of concrete tests. Reinstantiate Instance repeats generation for the selected existing TemplateInstance and needs its data source. It is not a guaranteed additive merge that preserves all manual edits or stale cases. ChangedManually records edits since generation and resets when cases are generated again. Inspect the selected data source, selector and intended generated subset; compare the resulting cases before execution.

Independent Practice: Update Expected Outcomes

Independent practice: add a hypothetical expected login outcome to synthetic user data. Map it to Verify, inspect paths and conditions, regenerate the selected TemplateInstance and trial-run representative cases.
