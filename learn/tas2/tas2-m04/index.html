Scenario: A New SUT Feature to Verify

The SUT (built with Agile) added a new feature: after clicking Add to Cart with a chosen quantity, a message appears — green/success for a positive whole number, red/error for a negative one. You already have Modules, Template, TestCases, and TemplateInstances from the previous version; you now receive an updated TestSheet with new Verification Attributes to test this message.

Verification Attribute

A new type of Attribute — shown in green — that is NOT an input to the SUT. Instead, it holds a value Tosca compares against the SUT's actual output. If the two values match once entered into the TestCase, the verification succeeds; otherwise it fails.

In the new TestSheet, the Quantity Attribute has 2 Instances: +4 (valid) and -4 (invalid). For +4, the Verification Attribute checks for the message "The product has been added to your shopping cart"; for -4, it checks for "Quantity should be positive". After modifying the Template and Instantiating, this produces 2 TestCases that validate the system message.

Modifying an Existing Template

Changes and new values are NOT reflected in existing TemplateInstances until you Instantiate again. Skipping this step means your 'updated' TestCases still run on old data.

A TestStepValue can only hold one link at a time. Before linking a NEW Attribute to a TestStepValue that's already linked to a different Attribute, you must first delete the existing Value — otherwise the new link won't take.

Instantiate vs. Re-Instantiate

SituationWhat to do
Test Design Specialist provided a brand-new TestSheetLink the new TestSheet (removes old link) → delete the old TemplateInstance folder → Instantiate (Ctrl+N, Ctrl+I).
Test Design Specialist amended the EXISTING TestSheet (same file, new rows/values)Modify the Template if needed → use Re-Instantiate — it refreshes existing TemplateInstances AND adds any new ones, without deleting anything manually.

Re-Instantiate can be run by right-clicking the TemplateInstance folder → ReInstantiate. It's the safer, additive option when the underlying TestSheet was just updated rather than replaced.
