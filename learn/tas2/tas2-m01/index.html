Scenario: Testing the Shirt Size Selector

You must test the Shirt Size field on the DemoWebShop: log in, navigate to Apparel & Shoes, select the "Men's Wrinkle Free Long Sleeve" shirt, and choose a size to add it to the cart. You need to check that all valid sizes (S, M, L) work, and that an invalid size (XL — not available for this shirt) correctly returns an error.

TestSheet

The basic framework of TestCase-Design. A TestSheet is a central, structured repository of test data — Attributes and Instances — that specifies every combination you need to test. Think of it as a high-level guide through one slice of your SUT. Double-click the TestSheet symbol in the Navigation pane to view its contents.

Attributes vs. Instances

Attributes

Express a feature of a person or thing (e.g. a laptop's Attributes might be design or price; a person's might be hair color or height). Represented by a red square icon. An Attribute also acts as an organizational element for its child/sub-attributes.

Instances

The different variants of an Attribute (e.g. hair color Instances could be blond, brown, black). Represented by a flat white box with a capital "I". Instances have two roles: at the TestSheet level they represent individual TestCases; under an Attribute, they represent that Attribute's specific variant.

If you can only see Attributes and not Instances, press F9 — it hides/unhides all Instances in the TestCaseDesign (red) section of Tosca.

ValidValues, StraightThrough, and Invalid Instances

ValidValues / StraightThrough

The leftmost column of a TestSheet is called "ValidValues" — the most important, most frequently used, or easiest path with the least dependencies (similar to the "Happy Path" concept). In Tosca terminology this column is the StraightThrough.

Invalid Instance ≠ Failed TestCase. A TestCase FAILS when the actual SUT values differ from what's expected. An Invalid Instance simply verifies that the SUT correctly rejects a bad value (shows the right error message) — if the error message appears as expected, that TestCase PASSES. It would only fail if the SUT incorrectly accepted the invalid value (e.g. let you order a size that doesn't exist).
