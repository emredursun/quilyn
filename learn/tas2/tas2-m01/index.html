Scenario: Testing the Shirt Size Selector

Independent scenario: a sample product accepts sizes S, M and L and rejects XL. Design input values and expected results for each path. This is a hypothetical specification, not a verified statement about the current Demo Web Shop catalogue or its UI ability to submit an unavailable size.

TestSheet

A TestSheet organizes test data into a logical testing structure. It can use Attributes for data-oriented cases or Steps for process-oriented cases; it is not itself a completed execution run.

Attributes vs. Instances

Attributes

An Attribute represents a business object characteristic and can contain sub-Attributes or Instances. Its icon color reflects business relevance, which can be changed; do not identify its meaning solely from a fixed red icon.

Instances

An Instance supplies a concrete variant. Attribute-level variants supply values; TestSheet-level Instances describe complete combinations for later generation.

If you can only see Attributes and not Instances, press F9 — it hides/unhides all Instances in the TestCaseDesign (red) section of Tosca.

ValidValues, StraightThrough, and Invalid Instances

ValidValues / StraightThrough

Straight Through is the Instance Character for the frequently used path with fewest dependencies; it is required for linear expansion. ValidValues can be an example name, but neither that name nor the leftmost column position makes an Instance Straight Through. Set Character deliberately.

Invalid describes input expected to trigger an error; it is not an execution failure status. A negative test can pass when the specified rejection and every other assertion succeed. It may fail for a missing error, wrong message or another failed assertion—not only when invalid input is accepted.
