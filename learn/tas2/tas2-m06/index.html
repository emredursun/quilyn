From Templates to Execution

Create an empty ExecutionList within an ExecutionLists folder using Create ExecutionList, the applicable ribbon command or Ctrl+N, Ctrl+E. Alternatively, dropping a TestCase or TestCases folder onto the ExecutionLists object creates a list with entries. Empty-list creation and drag-and-drop creation are distinct workflows; do not treat manual folder preparation as the only supported route.

Object Roles and Linking Scope

A TemplateInstance contains generated concrete tests. A Requirement expresses a criterion and a RequirementSet groups criteria. An ExecutionList arranges test references for execution. Recognize their object roles rather than relying only on icon color. Individual TestCases and whole folders can both be linked; folder linking is useful for maintaining a generated group, not mandatory for every case.

Linking TemplateInstances (Best Practice)

Link the intended generated TestCases or folder to the specific Requirement, or to its placeholders. In a multi-user workspace check in new objects before linking. Completed is not a universal linking prerequisite. Assign truthful WorkStates; these influence weighted coverage. Drop the selected tests/folder onto an ExecutionList and link that list to the relevant RequirementSet. Inspect generated cases before running. Changes to existing TestCases synchronize automatically; added cases, rearrangement or folder renames require explicit Synchronize on the affected list/folder. Do not assume synchronizing one list refreshes every other list.

Reading the Results

Coverage Specified (%) measures linked-test creation progress using relative weights and WorkState, not successful execution. Execution State (%) separates result categories with weights and WorkState; neither metric contains the exact failed-step diagnosis. Inspect the execution logs for that detail. These aggregate metrics are configured in Requirements via Column Chooser. Update outdated Requirement values when automatic calculation is disabled. Planned and In Work contribute partial specified coverage, so a link is not proof of completed testing.

Independent Practice: Run and Inspect

Independent practice: generate a small set, review its assertions, link it to a specific hypothetical Requirement and an ExecutionList, run it, inspect detailed logs and refresh aggregate values. Original Academy exercise instructions and source workspaces remain inaccessible and unverified.
