The passed deadline interval

Passed deadline interval

Defines WHEN to take further action after a Step or Case exceeds its deadline. It measures time elapsed SINCE the deadline for a STILL-OPEN Assignment — the goal/deadline say 'you’re late'; this interval keeps acting until the work is done.

A passed-deadline interval rule is like an alarm clock with a repeating snooze: when the deadline is first missed (the alarm goes off), the interval timer starts. At the end of each interval, a new escalation action fires (alarm goes off again) — ringing louder each time until someone finally resolves the case and turns it off permanently.

It repeats (unlike goal/deadline)

Key distinction from goal and deadline intervals:

  • Goal and Deadline fire ONCE only
  • Passed deadline interval can REPEAT — a FIXED NUMBER OF TIMES or UNTIL the Assignment is completed
  • On each repeat: can increase Urgency and trigger escalation Actions

Configured only in Dev Studio

Configure the passed deadline interval in Dev Studio on the SLA Rule. App Studio-created SLAs auto-generate an SLA Rule — goal/deadline come from App Studio, but the passed deadline interval must be added on the Rule.

Urgency cap and escalation Actions

Urgency maximum is 100

Urgency is capped at 100. Once an Assignment reaches Urgency 100, Pega IGNORES further Urgency increments — but CONTINUES other escalation Actions. Example: if Urgency is already 100, Pega skips the increase yet still sends the notification.

Escalation Actions (reused each interval)

Actions triggered on every passed deadline interval (same as goal/deadline):

  • Notify (assignee, manager, or participants)
  • Reassign (to another user or Work Queue)
  • Resolve the Case
