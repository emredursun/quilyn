Configuration Settings and Configuration Sets

Configuration settings

A unified, low-code framework for customizing application behavior parameters without Rule overrides. Configuration settings minimize the need for custom Rule changes, making applications easier to maintain, upgrade, and deploy — shortening time-to-market and reducing bugs.

Configuration Set

A named group of Configuration settings for a specific feature or Case Type, created in App Studio. Rules (classes, Data Pages, properties) are auto-generated in Dev Studio. Name stored as pyLabel of a class Rule (max 64 chars).

Think of a Configuration Set as a settings panel on your phone — you can change ringtone, brightness, and font size (Configuration settings) without opening the phone's codebase. Managers and users adjust behavior at runtime without touching any design-time rules.

DSS → Configuration settings (key migration note)

In previous Pega Platform releases, Dynamic System Settings (DSS) provided dynamic behavior functionality. Configuration settings REPLACE DSS — they provide enhanced functionality and simpler maintenance.

Navigation, Access, and Deployment

Where to access

App Studio → Settings tab → Configurations landing page. Configuration Sets allow runtime customization by users without switching to a design-time environment (App Studio or Dev Studio).

Role-based access

Three access roles for Configuration Sets and settings:

  • Administrators (PegaRULES:SysAdm4): Read/Write/Delete on both Configuration Sets and settings
  • Managers (PegaRULES:WorkMgr4): Read/Write/Delete on Sets, Read-only on individual settings
  • Users (PegaRULES:User4): Read-only on both

Deployment

Configuration Sets are defined in the Pega-Configuration class structure and included in the deployment file generated by product Rules. Configuration settings are included only when the 'Include associated data' checkbox is selected during product file creation.

Referencing Configuration Settings

Condition Builder reference

Reference Configuration settings throughout the application using the Condition Builder. The Condition Builder provides a menu to select a Configuration Set, then the specific setting within it. Allows business logic to react dynamically to setting values without hardcoding.

Runtime customization example

Show additional guidance text to new users via a Configuration setting (value = true). Once experienced, update the setting to false — guidance text is hidden. No Rule change, no redeployment required.
