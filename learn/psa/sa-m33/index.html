Configuration Settings and Configuration Sets

Configuration settings

A low-code framework for exposing selected application-behavior parameters. Use it to reduce hardcoded configuration and unnecessary Rule overrides; it does not eliminate every Rule change or guarantee an application has no defects.

Configuration Set

A named group of Configuration settings for a specific feature or Case Type, created in App Studio. Rules (classes, Data Pages, properties) are auto-generated in Dev Studio. Name stored as pyLabel of a class Rule (max 64 chars).

A settings panel separates a feature’s adjustable parameters from its implementation. Changing a guidance toggle is simpler than rewriting its visibility Rule each time. Access still matters: being a manager or user does not automatically grant permission to edit every setting.

DSS → Configuration settings (key migration note)

For the application-behavior customization described in this lesson, Configuration settings are recommended in place of DSS. This is not evidence that all platform DSS records disappear or that every system setting should be migrated blindly.

Navigation, Access, and Deployment

Where to access

Use App Studio → Settings → Configurations to develop the groups. Authorized users can customize exposed values at runtime without switching to design-time tools. A newly created Set appears on the landing page only after it contains a setting.

Role-based access

Three access roles for Configuration Sets and settings:

  • Administrators (PegaRULES:SysAdm4): Read/Write/Delete on both Configuration Sets and settings
  • Managers (PegaRULES:WorkMgr4): Read/Write/Delete on Sets, Read-only on individual settings
  • Users (PegaRULES:User4): Read-only on both

Deployment

Configuration Sets are defined in the Pega-Configuration class structure and included in the deployment file generated by product Rules. Configuration settings are included only when the 'Include associated data' checkbox is selected during product file creation.

Referencing Configuration Settings

Condition Builder reference

Reference Configuration settings throughout the application using the Condition Builder. The Condition Builder provides a menu to select a Configuration Set, then the specific setting within it. Allows business logic to react dynamically to setting values without hardcoding.

Runtime customization example

A guidance setting can control instruction visibility. An authorized operator changes the value after users adopt the Process. This avoids changing the Rule for that value adjustment; it is not a promise of instantaneous propagation to every open session.
