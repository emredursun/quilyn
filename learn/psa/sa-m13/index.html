The Approval Step

Approval gate

A user decision controls the approval path. Choose the reviewer and configure both outcomes.

Think of a budget checkpoint: choose the person allowed to decide, then write down what an acceptance and a rejection mean. The checkpoint alone does not promise email, escalation or automatic approval.

Default versus configured rejection

Default rejection resolves the request as Resolved-Rejected. Revision requires an explicit destination; it is not implied by the word Reject.

Outcome configuration

Approval can continue work or select a Stage, with an optional status update. Rejection can resolve, continue, or select a Stage.

Outside the application

Enabled email or mobile approval lets the routed stakeholder decide outside the application. Check the recipient and enablement rather than assuming every Step sends these notifications.

Configuring a single approval

One decision or a series

A single approval may use a named recipient, request-dependent routing, or a shared queue. Several required decisions need an explicit sequence or a cascade.

Routing policy

Choose between one particular reviewer and any eligible reviewer. Do not turn a shared Assignment into a claim that all queue members receive independent approvals.

Cascade models

Reporting structure follows manager relationships. Authority matrix supplies an ordered list and can include other departments. The next module explores both.
