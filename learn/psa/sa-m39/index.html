Savable Data Pages — Purpose and Configuration

A savable page is like a draft form with a submission operation: edits and persistence are distinct. The save implementation determines how failures and transaction boundaries are handled; this analogy does not promise universal rollback across external systems.

Savable Data Page — purpose

Pushes data FROM a Data Page TO a System of Record (SOR). Works for both Pega Platform's internal database and external SORs. Edit mode must be set to 'Savable'. A data save plan specifies how and where data is saved.

Transaction handling

Flow and Flow Action invocation manage the Pega transaction automatically. An Activity invocation can choose its transaction boundary; custom Activity persistence must handle consistency and errors. Do not assume every remote API participates in an atomic rollback.

When Conditions in the data save plan

Configure When Conditions on each save target to commit to multiple data tables simultaneously. If a When Condition is true → the data commit runs. If all When Conditions are false → the Otherwise Condition runs.

Savable Data Pages — Save Options

Save option: Database save

Database save persists a Page-structure record to a configured database row. A Data Transform can prepare or map data when needed; it is not universally mandatory. The database operation has transactional integrity.

Save options: Database update and Database delete

Internal SOR (system of record) operations:

  • Database update: modifies an existing record in the internal SOR within the same transaction scope
  • Database delete: removes a record from the internal SOR

Save option: Connector (REST only)

Saves data to an external SOR using REST-based integration. REST ONLY — not SOAP. Use when the external system exposes a REST API.

Save options: Robotic Automation and Robotic Desktop Automation

RPA-based save options for external systems:

  • Robotic Automation: unattended RPA to write to an external system
  • Robotic Desktop Automation: desktop-driven RDA for UI-based external systems that have no API

Save option: Activity

Activity supports custom persistence, including supported integrations such as SOAP. The implementation is responsible for transactionality and error handling; prefer dedicated options where sufficient.

Savable Data Pages — Data Handling

Update vs. Create — key and source

Two savable Data Page operations driven by whether a key exists:

  • UPDATE — key IS PRESENT → use Lookup as source
  • CREATE — key NOT PRESENT → use Data Transform as source (one savable Data Page can support both)

Auto-populated property + savable Data Page: Copy

The current source recommends Copy data from a Data Page for this pattern. Refer can accidentally overwrite unsaved edits before the save is triggered. Use the associated-property save configuration to persist the edited property.

Update Details Action

Provides a simple way to update data object information without complex configuration. Supports additional validation and pre/post-processing of data.

Save Data Page Automation

3 ways to trigger the save plan

① Add a Save Data Page Automation Step in a flow (AFTER an Assignment). ② Add post-processing for a Flow Action. ③ Call Save-DataPage in an Activity. When triggered from a flow or Flow Action, Pega manages transaction handling automatically.

Save Data Page Step — placement

For the lesson’s user-entered-data flow, place saving after the Assignment that collects the values. This is a sequencing recommendation for that flow, not a ban on other valid save invocation points.

Multiple SOR commits in one flow

The source recommends multiple Save Data Page Steps for multiple data sources. Do not generalize this into a ban on multiple conditional save options within one page’s save plan.

Explicit vs. Implicit Data Page reference

Two ways to reference a Data Page:

  • EXPLICIT — enter the Data Page Name directly; any parameters can be specified
  • IMPLICIT — Use associated property selects an auto-populated page/page-list property; parameters come from its property Rule.
