Data Objects

Data object

A structure that groups related fields to model a single entity and establish common context (e.g., a Customer grouping First name, Last name, Email, Phone). Data objects are reusable across an application's Case Types.

Data relationships in Pega are like a library catalog: each book (data object) has its own record, and the catalog links books to topics, authors, and borrowers. An Embedded data relationship is like a book with a built-in bookmark ribbon — the data only makes sense inside that specific book. A Page List is like a card catalog drawer — one card per item, all managed together.

Extending a data object

You can extend a data object by referencing another data object; the referenced object's fields become part of the referencing object. Any object can be referenced once or many times.

Reuse, inheritance and sourcing

Prefer a suitable existing data object, extend it when necessary, and create a new one when none fits. Related objects can be nested. Source records locally in Pega or externally; Case participants can also enter Case-owned values without a system of record.

Data Relationships

Data relationship

A container that associates related fields. Unlike a data object or field, it does NOT store data — it relates data-storing elements to the elements that need that data to resolve a Case (object↔Case, object↔object, or Case↔Case).

Single record vs. list of records

Two ways a data relationship references data:

  • SINGLE RECORD — one related set of fields and values.
  • LIST OF RECORDS — multiple related records. A list Data Page uses pxResults; an embedded Page List uses its own property name and indexed entries.

Data Relationship Field Types

Embedded Data

Use Embedded Data to capture Case-specific input. The values are owned by the Case rather than shared source records. Ownership does not specify a universal physical table layout; the Academy credit-card example describes a persisted keyed record associated with the Case.

Data reference

Use when you need to REUSE another data object from OUTSIDE the Case — data sourced from locally-stored Data Records or an external system of record (e.g., reference the facility where a medical appointment is booked).

Case reference

Use when you want to REUSE data from another CASE (e.g., a user selects from a list of Service Cases from the Service Case Type).

Query

Use for READ-ONLY access to information that is external to the Case; the Query Field Type allows PARAMETERS to query for specific data (e.g., return a medical professional's next appointment, or all appointments in a given time frame).
