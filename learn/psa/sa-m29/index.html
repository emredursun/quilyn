Optional Actions

Optional Action vs. Optional Process

Two types of user-initiated additions to a Case workflow:

  • OPTIONAL ACTION — a single Step users can invoke at any time
  • OPTIONAL PROCESS — a series of Steps users can optionally trigger

Optional Actions in Pega are like condiment choices at a burger restaurant: the core burger (required process) is always served, but ketchup, mustard, and pickles (optional actions) are available at any time — never forced. The kitchen (Pega) makes each condiment available through the case action menu without putting it on every burger automatically.

Case-wide vs. Stage-only

Scope determines when the optional action is available:

  • CASE-WIDE — available throughout the ENTIRE Case lifecycle
  • STAGE-ONLY — available only during a specified Stage

Runtime access — Actions menu

At runtime, optional Actions are accessible from the Actions menu in the Case. Users choose whether to invoke them during Case processing.

Promoted Actions

Optional Actions promoted to the Case Page for higher visibility — they appear as buttons on the Case summary rather than only in the Actions menu. Examples: 'Edit details', 'Update contact'. Gives users quicker access without opening the menu.
