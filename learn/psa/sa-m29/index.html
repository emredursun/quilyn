Optional Actions

Optional Action vs. Optional Process

Two types of user-initiated additions to a Case workflow:

  • OPTIONAL USER ACTION — one Step users can invoke in its configured Case-wide or Stage-only scope.
  • OPTIONAL PROCESS — a series of Steps users can invoke in its configured scope.

Think of an on-demand task menu: an agent can update a contact detail or launch cancellation when the task is applicable. Optional describes how the task is invoked, not a guarantee that its configured effect leaves the Case unchanged.

Case-wide vs. Stage-only

Scope determines when the optional action is available:

  • CASE-WIDE — lifecycle scope rather than restriction to one Stage; availability still respects applicable configuration and user access.
  • STAGE-ONLY — offered in the configured Stage context, such as cancellation before shipping.

Runtime access — Actions menu

At runtime, optional Actions are accessible from the Actions menu in the Case. Users choose whether to invoke them during Case processing.

Promoted Actions

The reviewed runtime selects a promoted user Action for a button on the Case summary panel: the first Stage-wide Action other than Edit details, or the first Case-wide Action if no Stage-wide Action is available. Optional Processes are not supported as promoted Actions; prominence does not grant access or execute the Action automatically.
