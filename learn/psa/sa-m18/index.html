Work Groups and Work Queues

Work Group

A CROSS-FUNCTIONAL team — a manager plus a Work Queue — whose members share work regardless of their business unit. Note: an 'Operator' in Dev Studio is a 'User' in App Studio.

Think of a project team drawing people from several departments, with a supervisor and a shared inbox. Team membership supports collaboration without reorganizing the company.

Shared team queue and default queue

The introductory Teams of users topic describes one shared queue for the team. Configuration uses a Default Work Queue field. Follow the documented setup for your version; do not infer additional queue or permission configuration solely from this simplified team model.

Work Queue vs. Worklist

Two Assignment container types:

  • WORK QUEUE — a SHARED list for all operators in a Work Group
  • WORKLIST — holds only work assigned to ONE specific operator
  • An Assignment moves from the Work Queue to a Worklist when ready to be worked

Operators and Work Groups

An operator must belong to AT LEAST ONE Work Group and can belong to MORE THAN ONE. Work Group membership controls work sharing without changing the organizational hierarchy. Configure users in App Studio; Dev Studio offers advanced options.

Queue processing roles (advanced configuration)

The linked configuration reference distinguishes access to a queue from processing work. If Roles are configured on that queue, processing requires at least one listed role. Team membership alone does not establish every permission.

Managers and Authorized Managers

Work Group manager

A Work Group names ONE operator as its PRIMARY manager. The system uses manager information for NOTIFICATION Tasks, APPROVAL Tasks, ROUTING Tasks, and ESCALATION. Managers assign, monitor, and report on the group's work using the Web Portal.

Authorized Managers (and their limits)

Authorized Managers assist with assignment transfer. This management relationship alone does not grant approval authority or unrestricted processing access.

  • They need not be members of the group.
  • The introductory source excludes approvals from these duties.
  • An authorized manager outside the group cannot complete its queued assignments under this lesson model.
