Channel Interfaces

A Portal is like a company office building. The Channel defines the type of building (glass tower = web portal, satellite van = mobile). The Portal is the building's internal layout. Landing pages are specific rooms (lobby = Dashboard, workroom = My Work). Widgets are the furniture and equipment in each room. The Enterprise layer is the company's interior design standard — applied everywhere for brand consistency.

Channel interface

A Channel allows you to create tailored interactive UIs for specific interaction types. Examples: messaging service, voice service, web portal, mobile portal. Channels are created from templates with predefined layouts and navigation.

Conversational Channels

Facebook Messenger, WhatsApp, Apple Messages, SMS/MMS (Twilio), Embedded chat window, Amazon Alexa, Email. IVA (Intelligent Virtual Assistant): understands user intent across channels. Email Bot: auto-detects email intent and routes.

Channels landing page

Create, view, and edit all Channel interfaces from one place. Download additional Channels from Pega Marketplace. Lock icon on a Channel = the Channel component has NOT yet been added to the application (not a permission restriction).

Persona-Channel associations in Case lifecycle

Drafting Persona-Channel associations in the Case Life Cycle Stages does NOT configure that Persona's Channel access. By default, a Persona has access to ALL pages in the application. Channel access is configured separately in the Portal configuration.

Portals and Landing Pages

2 Portal types in Constellation

Choose a Portal type based on user profile:

  • Standard work Portals: for professional users completing complex, recurring workflows requiring collaboration and data analysis
  • Self-service Portals: minimalistic design with a guided experience for simple, goal-oriented tasks

Landing pages

Consolidate Case-related information. Contain data lists, Widgets, Views, and Insights. Out-of-the-box pages: Dashboard, Home, Explore Data, My Work, Self-service Main page. Landing pages added to the Portal menu appear in Portal navigation.

Landing page templates

4 templates: Default page (column-based with/without banner), Tabbed page, Dashboard page, Inline Dashboard page. The Default page supports both column-based layout and dynamic layout (drag, drop, and resize widgets).

Dashboards

Dashboard structure

Dashboard = a landing page accessed in the Portal. Contains Widgets that consolidate summary info and KPIs. A Template divides the work area into Regions (containers for widgets). Each Persona gets a tailored dashboard view.

Dashboard visibility — 3 options

Three visibility levels for dashboards:

  • Private: only the creator sees it
  • Shared — Users with Access: all users or a specific Access Group
  • Public: all users in the application

Out-of-the-Box Widgets

Widget locations

Widgets appear in two places: Portal landing pages AND Full Case View (Utilities pane). The Utilities pane is HIDDEN when no Widgets are added — it doesn't show an empty state.

Portal landing page widgets

Four configurable widgets for Portal landing pages:

  • Pulse: team collaboration (posts, comments, attachments) — available in landing pages AND Full Case View
  • To do: configurable to show My Worklist, team members, or Work Queue
  • Quick create: creates a new Case directly from the landing page
  • App announcement: custom welcome text + link

Home landing page defaults

The Home landing page includes three widgets by default: Pulse, To do, and App announcement.

Utilities pane widgets (Full Case View)

Attachments, Case History, Case operator, Tags, GenAI Coach, Followers, Prediction, Stakeholders, Related Cases.

Themes and Enterprise Layer

4 ready-to-use Constellation themes

Pegasus, Aries, Self-Service, Bootes. MUST SAVE UNDER A NEW NAME before customizing any of them — you cannot edit the original built-in themes directly. Configure at App Studio → Settings → Themes. The Themes landing page also provides accessibility configurations.

Enterprise layer = COE layer

The Enterprise layer and the Center of Excellence (COE) layer are the SAME concept. Implement the shared design system here — themes, web fonts, icons, design templates — for easier branding updates across all applications.

Design tokens

Store component styling in one central place. The system auto-generates platform-specific styling from those tokens, ensuring visual consistency across mobile, desktop, and other surfaces. All Constellation library components use design tokens.
