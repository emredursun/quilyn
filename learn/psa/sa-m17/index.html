With whom? (recipients / Send to)

Three questions for correspondence

Three questions to answer when configuring automated email:

  • WITH WHOM — who receives the email (Recipient: a field value, user reference, or participant)
  • HOW — the message content (Correspondence template referencing Case data)
  • WHEN — when in the Case life cycle (Send Email automation Step placement)

Email correspondence rules in Pega are like pre-written letter templates at a law firm: the partner (developer) writes the template once with [CLIENT_NAME] and [CASE_NUMBER] placeholders. When a case reaches the trigger point, Pega merges the template with real case data and sends the letter — 500 personalized letters without retyping each one.

Recipient (Send to) options

Send to a SPECIFIC email address (fragile if the address changes), or resolve at runtime from a FIELD value (e.g., Customer email field), a USER REFERENCE, or a PARTICIPANT. Runtime resolution is preferred.

User reference (incl. Create/Update Operator)

A field pointing to one specific user, defined in the Case Type data model. CREATE OPERATOR and UPDATE OPERATOR are user-reference fields automatically defined for every data type associated with the Case Type.

Participants (Owner / Customer / Interested)

Default Case participants (Pega resolves their email from participant info):

  • OWNER — the user who created the Case
  • CUSTOMER — the person the Case is for
  • INTERESTED — tracks progress only; not responsible for any action

How? (compose the message)

Rich text editor

Pega provides a RICH TEXT EDITOR to create formatted email and REUSE Case data — e.g., greet the customer by referencing the first-name and last-name fields captured in the Case.

Correspondence templates

You can reuse out-of-the-box CORRESPONDENCE TEMPLATES that include Case processing data such as the Case ID (.pyID) and Case status (.pyStatusWork), instead of composing every email from scratch.

When? (send the email)

Send email automation

Add Send email at the workflow point where correspondence is required. Reaching this Step initiates sending to the configured recipient. A read receipt or reply dependency needs a separate design; this description does not guarantee successful delivery.

Case-level notifications

Enable Case-level email notifications for Assignment routing to a Worklist. The routed user is the recipient. Distinguish this event from arbitrary Case status changes and shared Work Queue routing.
