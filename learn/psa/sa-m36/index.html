Data Transforms — Concept and Operations

Porter vs. translator — A porter carries a suitcase as-is (copy). A translator converts the message into another language (convert). A Data Transform does both: moves a value to a different field, or changes its data type entirely.

Data Transform — what it does

Copies, converts and drives application data. It can calculate values, change formats and set defaults as well as copy between objects. Do not confuse setting or deriving a value with enforcing a blocking validation error.

Copy — move a value

Copies a field value into another field. Example: copy customer details from the checkout form into the shipping address fields.

Convert — change data type

Changes the data type of a value. Example: convert the string 'December 4, 2021' to the date value 12/04/2021. Data Transforms don't just copy — they convert too.

Parent-child tip — reference over copy

Consider references when later parent changes should remain available to a child. Use a copy when a snapshot or separately manipulated value is the actual requirement; reference is not mandatory for every parent-child field.

Data Transforms — Execution Methods

Method 1 — Run Data Transform Automation

Added as an Automation Step in the Case Life Cycle. Runs automatically at runtime — no user interaction required. A new Data Transform can be defined inline (e.g., 'Convert string to date').

Method 2 — Pre-processing

Configured on a Step's Pre/Post Processing tab. The Data Transform runs BEFORE the Step executes. Use case: populate fields before the form is displayed to the user.

Method 3 — Post-processing

The Data Transform runs AFTER the Step completes. Use case: clean up or convert data after the user submits a form.

Default Property Values

Pre-filled form at the doctor's office — when you arrive, the form already has your name, date of birth, and insurance details filled in. The Data initialization page works the same way: when a Case is created, fields arrive pre-populated with known values.

Data initialization page — where to find it

App Studio → Case Type → Settings tab → Data initialization. This is where you configure default property values assigned when a Case is created.

Example use cases

① Pre-populate user's First Name and Last Name from the OperatorID clipboard page. ② Set a date field to today's date. ③ Speed up iterative testing in development by pre-filling required fields.

pyDefault and pySetFieldDefaults — when are they created?

The first View creation described in this lesson generates pyDefault and pySetFieldDefaults. Distinguish this generation event from when each transform is later invoked.

pyDefault vs pySetFieldDefaults — different trigger times

Two built-in Data Transforms with different trigger points:

  • pyDefault — invoked when the Case is CREATED; calls pySetFieldDefaults as part of its logic
  • pySetFieldDefaults — runs each time a View is LOADED (can run multiple times per session)

Best practice — Data init page for simple, pyDefault for complex

Simple defaults → use the Data initialization page (it updates pyDefault). Complex default logic → edit pyDefault directly. Either way, never touch pySetFieldDefaults — it is system-managed and manual edits can be overwritten.

Pages & Classes — the OperatorID example

The illustrated pyDefault example reads First Name and Last Name from the OperatorID Clipboard Page and declares that page on Pages & Classes. Follow that example without generalizing it into a rule that every Data Page reference must be declared or always fails at runtime without a declaration.
