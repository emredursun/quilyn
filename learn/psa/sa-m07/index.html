Fields and Field Types

Field

A named, reusable UI component that stores a value associated with a Case. The field name and stored value form a data element. Its Field Type controls the kind of information stored and its display format.

Fields and Views work like a spreadsheet: each field is a labelled cell holding one value for the Case, a calculated field is a formula cell, and a View arranges the cells a user needs for one task. The same stored value can appear in several Views without being entered twice.

Field Type

Determines the information stored and how it is formatted. Pega predicts a type from the field name and defaults to Text (single line), but the author must verify the type before submitting.

Simple and specialized Field Types

Choose the type for the business value, not for its appearance:

  • Simple types: Text (single line or paragraph), Boolean, Currency, Date & time, Date only, Time only, Decimal, Integer, Percentage, Email, Phone, URL, Picklist, Address, User reference and Prediction
  • Email, Phone and URL are action-oriented: the stored value is displayed as a link that opens mail, a phone call or the browser
  • Fancy types: Attachment stores documents or files; Location accepts an address or automatic geolocation
  • Prediction requires decision nodes (Pega Process AI); Address shows country-specific fields after the Country selection
  • An Integer stores the value from its first non-zero digit. Use Text for numeric-looking values that need no arithmetic, such as identifiers with leading zeros

Calculated Values

Calculated value field

A calculation sets a field from one or more input fields, for example an item total from unit price and quantity. Calculation occurs whenever a user updates an input, which removes manual arithmetic and reduces errors. The App Studio configuration shown in this topic marks the calculated field as read-only; users change its inputs rather than typing over the result.

Recalculation

Each calculation joins the application's calculation network. A calculated field can feed another calculation, so one input change (such as item quantity) can update several dependent fields. In the documented App Studio calculated-field configuration, the result is read-only. This UI setting does not establish whether the value is persisted or describe every declarative property configuration in Dev Studio.

Three calculation approaches

App Studio offers three approaches. Functions Sum of, Average of, Maximum of and Minimum of iterate over items in a data relationship and support Decimal, Currency and Integer fields. Expressions combine simple fields, fancy fields and data relationships. Decision tables test field values and return a result.

Expression context

Reference fields with the dot operator, which lists fields available in the current Case; prefix a field with its data relationship when needed. Operators include + - * /, parentheses, Boolean AND and OR. Text can be concatenated with quoted static text. Expressions are available for every simple type except Email, Phone and Picklist.

Decision tables and where calculations live

Create a custom decision table in App Studio only in a Constellation application, or reference a Dev Studio decision table that a System Architect has marked as a relevant record. Calculated fields are added on the Data model tab of either a Case Type or a data object, depending on the use case.

Views

View

A reusable configuration of fields and other UI elements that collects or displays information. A View states what users need to see and when; Pega supplies a consistent, responsive presentation. Each field and its value is a data element that can be shown editable or read-only.

Views, forms and field settings

A form is a View that collects user input and processes work, usually with submit, cancel or navigation actions; not every View is a form. A Multi-step Form splits many fields into several focused Views. Other Views show read-only summaries or confirmations. For each task choose the fields, value types and order, and whether each field is editable or read-only, visible or hidden, required or optional.
