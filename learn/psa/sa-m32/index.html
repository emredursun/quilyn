Wait Step — Overview

Wait Step

An automation shape that deliberately pauses Case processing and resumes it when defined conditions are met. Two Wait types: Case Dependency and Timer. Added to a Process in the Case Life Cycle like any other automation Step.

Think of the Wait Step as a red traffic light in the middle of your workflow — it deliberately stops the car (Case) until the condition changes (light turns green). Sitting in traffic waiting for a slow pedestrian to cross is NOT the same — that's a user-action delay, not a red light (Wait Step).

Case Dependency Wait Type

Case Dependency — how it works

Place the Wait Step on the parent. Configure whether any or all children of the selected type must meet the dependency. The related children must already exist when the parent reaches the Step; with no dependent Cases, the flow skips this wait.

Target status or resolution

A target can be a standard status such as Pending-Approval or an application-defined custom status. The To be resolved option instead waits for a status beginning with Resolved; it does not mean any still-open Case. Configure current-status consideration or subsequent changes as required.

Cancelling the wait

You can allow users to cancel the wait conditions and continue processing the parent Case without waiting for the child to resolve.

Timer Wait Type

Timer — two configurations

Pauses a Case until a time condition is met. Two options: (1) Set date/time interval — pause for a fixed duration (e.g., 24 hours). (2) Reference date/time — pause until a specific date/time stored in a Case field is reached.

Timer use cases

Common Wait shape scenarios:

  • Fixed interval: a configured 24-hour pause before review.
  • Reference date: the Case field containing the intended valuation cutoff.
  • Example duration: a configured 72-hour processing delay; this example is not legal advice or a regulatory requirement.

Wait Step vs. User Action Delay

Critical distinction

A Wait Step is a DELIBERATELY configured automation that pauses Case processing. A user action delay is when Case processing stalls because a user has not completed an Assignment — NOT a Wait Step. These are completely different concepts.

User action delay examples

A Case that appears paused because a user hasn't acted on an Assignment or submitted required data. NOT a configured Wait Step — just the natural flow of waiting for human action. Examples: awaiting manager approval, or uploading photos.
