Users and Personas

User

An individual who interacts with the application to perform work. Each user is represented by an Operator ID record that stores their profile and credentials and links them (via an Access Group) to an application, portal, and roles.

Persona

A CATEGORY of users who interact with a Case in the same way and share the same access needs — for example Customer, CSR, or Manager. Many individual users can be assigned to a single Persona for role-based access.

Users-to-Persona relationship

Assign individual users to the Persona appropriate to their responsibilities. A Persona includes an associated role and groups common security and Assignments. Configure and verify permissions, routing and Channel access; assigning a Persona is only one aspect of application security.

A Persona is a job title (e.g., 'Dispatcher') with a defined set of door keys; a user is the individual badge. Assigning a user to a Persona programs their badge with that title's keys (access).

Managing Personas and Channel interfaces

Channel interface

The user interface through which people interact with the application, such as web or mobile. Associate Personas with suitable Channels; multiple Personas can share one Channel, and Persona/Channel access can be configured for each Case Stage.

Managing Personas/Channels in App Studio

In App Studio, open Users > User Management > Persona to add a Persona. The application starts with the Users Persona. A new Persona receives default permissions and a Work Queue, which can be modified along with its Channel experience.

If the Persona is the role on the cast list, the Channel is the stage door they enter through (web, mobile, messaging). The same Case can be reached through different doors per Persona.

Inviting a user and adding a Persona

Inviting a user

In App Studio, open Users > User management > People, create a user with an email address, and assign an appropriate Persona or developer role. Use an account unique to each individual. Do not assume the invitation sends credentials or bypasses the configured authentication method.

Adding a Persona to a user

Assign a business user to the appropriate Persona and verify the associated permissions and work configuration. Each Persona has an associated role, but not every role has a Persona. A Persona and an Access Group are distinct concepts; do not assume a universal one-to-one mapping.

Inviting a user is issuing them a badge; adding a Persona is programming which areas that badge unlocks.
