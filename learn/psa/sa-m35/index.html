Validation Tools Overview

Receptionist vs. Compliance Officer — A receptionist (App Studio) asks one question: 'Is your name on the list — yes or no?' A compliance officer (Dev Studio) checks the format of your ID, applies different rules based on your clearance level, and demands extra documents only at certain checkpoints. Same goal — very different capabilities.

App Studio — the described comparisons

The low-code Validation Conditions described here compare field values with constants or other fields. The advanced examples use Dev Studio for pattern checks, input-qualified validation sets and additional validation functions. This is not a claim that App Studio cannot enforce any format requirement through its controls.

Validate Rule — Case-level, fires on form submit

Ensures data meets Case conditions before it advances. Assigned to Flow Actions. In Dev Studio you can extend App Studio-created rules or create new ones in the Process category.

Edit Validate Rule — property-level, Java, client-side

An Edit Validate Rule checks an individual property against a pattern using Java code. The lesson describes property attachment for value-change validation; calling it from a Validate Rule instead runs it when that containing Rule runs on submission. Do not infer validation on every automated property assignment or every keystroke.

Two ways to apply an Edit Validate Rule

Two application points, each with a different trigger:

  • Property Rule → Advanced → Use Validate: the property-attached, value-change validation described here.
  • Call from a Validate Rule: coordinated validation when that containing Rule runs on submission.

3 Dev Studio Use Cases

Use Case 1 — Format validation by business logic

For a location-specific postal-code pattern, the example calls an Edit Validate Rule from a Validate Rule. Matching a format is not proof that an address exists or belongs to the user.

Use Case 2 — Different rules per input value

When validation logic depends on user selection. Example: experienced investors can add margin trading (low risk); limited experience = high risk; retirement accounts prohibit margin regardless. Use Validate Rule + Input tab qualification on experience and account type.

Use Case 3 — Operations beyond true/false

Dev Studio's Validate Rule provides a library of Validation Functions with customized configuration fields. Examples: check if a date falls within the past 4 or 8 weeks; check if a specific attachment category is attached.

Input Tab — 4 Qualification Types

Input Property — qualify by user-entered value

Applies a different validation set per value the user selected. Example: Experience level = 'Extensive' → validate broker license; 'Limited' → validate suitability score.

Proposed Work Status — qualify by Case Status

Choose validation based on the status that the application proposes to apply. Example thresholds can differ when moving to Pending-Qualification versus Approved; do not describe this solely as the stored current status.

Flow Action — qualify by the user's action

Applies different validation per triggered action. Example: 'Onboard Employee' → start date must be in the future; 'Annual Review' → must be in the past.

Stages — qualify by current Stage ★ also in App Studio

Applies different validation per Stage. Example: Submission → estimated income OK; Approval → confirmed value required. Only qualifier available in BOTH Dev Studio and App Studio (as Stage-entry Validation).
