The Tracer — Overview and Reading Events

Like a flight recorder, Tracer records the sequence surrounding a fault. The final failed event may be a symptom, so inspect earlier events rather than assuming the last event is always or rarely the cause.

Tracer — purpose and access

Troubleshooting tool that traces events that led to an error during application runtime. Access: App Studio → hover lower-right corner → Toggle runtime toolbar. OR Dev Studio → Developer toolbar.

Tracer event color codes

Each event is logged as a separate row. Gray = Activity processing. Orange = Events from flow, Decision, or declarative Rules. Light blue = PegaRULES database and cache operations.

Status: Good vs Fail

Good and Fail describe processing-step outcomes, not unit-test assertion statuses.

  • GOOD — step completed successfully
  • FAIL — error occurred; a failed step may be only the LAST in a chain — trace backwards to find the root cause

Constellation request IDs

Constellation uses stateless DX API requests. The Tracer results organize events by request ID to distinguish simultaneously active requests.

Tracer Settings Management

Performance and limits

Key Tracer constraints to know before use:

  • ⚠ CAUTION: Tracer is resource-intensive and DRAMATICALLY slows application performance
  • Only ONE Tracer per operator, per node is allowed
  • Pause logging until ready to trace the specific section
  • Toolbar (upper-right corner): Pause, Clear, Save buttons

Refining event logging

Filter options to narrow Tracer output:

  • Filter by: event, event type, Ruleset, break Conditions
  • Can exclude local variables or view only activities (not their steps)
  • Selection options: Events to Trace, Break Conditions, General Options, Event Types to Trace, Rulesets to Trace

Break Conditions

A Tracer settings option (NOT a toolbar button). Stops the Tracer automatically when the system generates an error. Different from Breakpoints — Break Conditions are passive error-triggered stops; Breakpoints are manually placed on specific activities.

Breakpoints

In a supported tracing context, a breakpoint pauses tracing and its processing thread at the configured activity event. Resume with Play; the source also describes automatic resumption after an hour. Breakpoints and Watch are unsupported for Service Rules and Constellation applications.

Watch Function

Monitors specific property value(s) for changes. Useful for tracing calculation consistency and value-change patterns. Tracer highlights the property change in YELLOW and shows the Property Inspector. NOT supported for Service Rules and Constellation applications.

Developer Tools for Examining Applications

React DevTools

Browser extension; adds Components tab to console. Select any element to highlight screen. Run $r.props.getPConnect() to view component metadata. Used for Constellation application UI debugging.

Redux DevTools

Free browser plugin; adds Redux tab. Logs every action (type and payload). Visualizes state changes. Inspect state tree at any point. Client-side Data Pages are NOT in Redux — stored in the datastore.

Client-side Data Pages — NOT in Redux

Client-cached Data Pages reside in the application datastore, not Redux. PCore.getDataPageUtils() logs cached-page information. PCore/PConnect APIs are unavailable in the App Studio shell; launch the Portal from Dev Studio for these methods.

Xray, DebugPegaAPI, and UI Inspector

Three supplementary debugging tools:

  • Xray overlays screen metadata, field metadata and state properties.
  • DebugPegaAPI is a dynamic system setting: verbose DX API inputs, actions, error fields/descriptions/codes and exception numbers in Pega logs.
  • UI Inspector exposes UI hierarchy, metadata, field properties and View properties.
