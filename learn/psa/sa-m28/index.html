Conditional Execution of Processes and Stages

Purpose

Define conditions to control whether a Process or Stage runs in a Case. A condition consists of a property, an operator, and a value — evaluated at runtime against Case data.

Think of an optional checklist section: the configured condition decides whether it applies to this Case. Check the business criterion explicitly; skipping work is not a blanket exemption from other requirements or a user’s arbitrary choice.

Default Stage behavior: Never skipped

In the described Stage configuration, the default is Never. A configured true skip condition bypasses Stage entry and the work that would start there. This is not a claim about cancelling work already started or every possible navigation mechanism.

Default Process behavior: Always starts

By default, Processes ALWAYS start. To make a Process conditional, select the Process in the Case Life Cycle and configure a run condition. When the condition is not met, that specific Process is skipped.

Multiple conditions — AND logic

The source example requires both Was a party injured = Yes and Expense total > USD50. Its condition is a conjunction. Do not generalize that example into a claim that Pega cannot represent OR logic or that every condition editor has the same controls.

Configuration location

The described App Studio procedure configures the selected Stage or Process in the Case Life Cycle properties panel. An inline field/comparator/value comparison does not require users to author a separate Rule; reusable conditions and their editors are distinct configurations.
