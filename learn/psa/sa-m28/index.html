Conditional Execution of Processes and Stages

Purpose

Define conditions to control whether a Process or Stage runs in a Case. A condition consists of a property, an operator, and a value — evaluated at runtime against Case data.

Conditional execution in Pega is like the fast lane at an airport checkpoint: regular passengers go through full screening (all stages/processes run), but pre-approved travelers skip directly to the gate (the stage/process is skipped). The fast lane is configured by the airport authority (the Skip condition), not by the traveler — the system evaluates the condition at runtime and decides automatically.

Default Stage behavior: Never skipped

By default, Stages are NEVER skipped. To make a Stage conditional, select it in the Case Life Cycle and configure a skip condition. When the condition = true, the Stage and ALL Processes within it are bypassed.

Default Process behavior: Always starts

By default, Processes ALWAYS start. To make a Process conditional, select the Process in the Case Life Cycle and configure a run condition. When the condition is not met, that specific Process is skipped.

Multiple conditions — AND logic

You can add more than one condition to a Stage or Process. ALL conditions must be true simultaneously. Example: 'File personal injury claim' Process runs only when 'Was a party injured' = Yes AND 'Expense total' > USD50.

Configuration location

Both Stage and Process conditions are configured inline in the Case Life Cycle — select the Stage or Process to access its condition panel. No separate Rule form is required.
