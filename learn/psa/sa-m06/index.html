Pega Blueprint Overview

Pega Blueprint

Blueprint supports collaborative workflow design using industry templates or generative AI. It proposes a starting point that teams review against their requirements.

Think of Blueprint as a draft building plan: align the team on structure, then refine and implement it. A proposal is not proof of production readiness or a guaranteed delivery time.

Standalone SaaS tool

Blueprint is SaaS, independent of a Pega Platform development instance and Operator login. SaaS sign-in and collaboration access still apply; knowing a URL does not imply unrestricted access. Its interface evolves continually.

Augments, not replaces

Blueprint accelerates initial design; App Studio and Dev Studio support implementation and review after import. Templates are starting points, not substitutes for configuration and testing.

Generating a Pega Blueprint

Describe in business terms

Provide industry, sub-industry, department, purpose and a functional description. Use Other for an unlisted industry. Choose a template or GenAI, supply organization/language details and upload relevant supporting assets.

Generate and modify

Review Case Types with stakeholders. Edit Primary/Alternate Stages, Processes and Steps; use Notes for routing, SLA and conditions. Preview my app supports design review. Check fields, types, descriptions, primary fields, single/multiple records and user-input/calculated sources.

Best-practice templates

Templates offer an industry starting point. Review Personas, access needs, Channels and release effort, then check the summary for workflow, data and integration completeness. Export PDF for reference or .blueprint for import; revision history and dashboard support ongoing changes. A live-demo option can provision an instance and import the design.

Importing a Pega Blueprint into Pega Platform

Export and import

In App Studio, create an application with Build from a Blueprint and upload the technical file. Verify its details and intended built-on stack. Using an existing application through the New Application wizard requires saving that application as a template.

Who imports it

The authorized implementation team imports and reviews the application. Assign technical responsibility within the project; the source does not impose an LSA-only permission or a separate import ceremony.

What import creates (and the exception)

For the documented new-application workflow, created assets except Access Roles go into a Branch. This is about placement, not whether Access Roles are created. Base Rulesets are locked; use the provided password for appropriate merges and store it securely.

PremBridge not required

Pega GenAI PremBridge is NOT required to import Pega Blueprints into a new or existing application.

Review import choices

For Case Types choose build, inherit or skip. For data objects choose build, inherit, reuse or skip: inheritance creates a new object; reuse links to the built-on object without its own new class. Build or skip Personas. Check class layers and Case/data classes before Submit, then inspect the result and add users with Personas.

Post-import validation

Check existing-app overlap before extending it. After import, prepare developer configuration and merges, refine Decision shapes, Flow Actions and locking, and validate database mappings, Data Pages and properties. Test alternate paths, approvals, automation and child Cases.

Using Blueprint for an Industry App (Customer Service for Insurance)

Industry templates

The insurance example starts with a Customer Service template and adds a golf-cart Case. It inherits existing service Case Types and builds the new Case Type; infrastructure Cases also appear. A weather Step and field are separate design changes. After import, change the field to Picklist and add it to a View. Configure data, integrations, Channels and user groups, then simulate an interaction and review wrap-up/recent Cases. The example’s creation time is not a project guarantee.
