Calculated values and the calculation network

Calculation / calculated field

A calculation sets a field's value based on one or more other fields (e.g., Total = Quantity × Price). The calculated field is read-only — the system owns it. Calculations update automatically when any input field changes.

A Decision Table is like a tax bracket chart: find the row where your income falls (condition), intersect with the column for your filing status (second condition), and the cell gives your tax rate (result). Pega evaluates exactly the same way — no code, just organized rows of conditions and a corresponding output. When tax law changes, you update the table, not the code.

Where calculated fields live

Create the calculated field in the Data model of a CASE TYPE or DATA OBJECT, depending on the use case. Configuration includes field name, type (e.g., Currency), and the 'This is a calculated field (read-only)' option.

Calculation network

A calculated field can be the input to another calculation, creating a dependency chain. Pega resolves the chain in the correct order — downstream fields update automatically when upstream inputs change.

The three App Studio calculation types

Functions

Functions iterate over a data relationship (list) and aggregate values. Supported for Decimal, Currency, and Integer. App Studio provides Sum, Count, Average, Maximum, Minimum.

Expressions

An expression calculates a field value from a combination of fields, functions, and data relationships. Reference fields with the dot operator (.FieldName). Expressions are evaluated at runtime whenever their inputs change.

Concatenation (text expressions)

Assembles a string by joining field references and static text with '+'. Example: "Appraiser " + .AppraiserID + " appraised " + .ItemName + " at " + .AppraisedAmount + ".". Field references are replaced with live values at runtime.

Decision tables

A Decision table evaluates conditions to return an appropriate result — for example, select a discount percentage based on customer tier. Rows define conditions; the matching row's result is returned. Check 'Evaluate all rows' to return multiple matching results.

Constellation caveat

Only applications based on CONSTELLATION support the creation of CUSTOM decision tables directly in App Studio. In non-Constellation apps, the Dev Studio decision table (marked as a relevant record) is how you make the logic available to App Studio.
