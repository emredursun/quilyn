Microjourney, Case Types, and Cases

Microjourney

A unit of work (a Case Life Cycle) that takes a customer from a beginning to a specific desired outcome — part of the broader customer journey tied to a concrete result. Case Types represent a Microjourney.

Case Type vs. Case

Fundamental Pega terminology:

  • CASE TYPE — an ABSTRACT model of a repeatable business transaction (the template)
  • CASE — a SPECIFIC instance with a unique Case ID; assigned to operators who perform the work

Three pillars of an application

An application is captured as three pillars: Case Types (and Strategies), Personas and Channels, and Data and Interfaces. The Case Life Cycle is the Case Types pillar — the visual model of the Microjourney.

A Case Type is the cookie cutter; each Case is one cookie. The Microjourney is the recipe describing how the batch goes from mix (creation) to plate (resolution).

Case Life Cycle: Stages, Processes, Steps

Stage

The top-level organization of work — a distinct phase or milestone. You begin Case Life Cycle design by organizing work into Stages arranged left-to-right in the order work generally proceeds (e.g., Submission, Processing, Delivery).

Process

A Stage contains one or more Processes; each Process groups a sequence of Steps. A Case moves to the next Process after completing the current one (unless Processes are configured to run in parallel).

Step

The smallest unit: a user action (a Collect information Step / Assignment, shown green) or a system action (an Automation Step, shown yellow). Steps define exactly what happens within a Process.

Stages are chapters, Processes are scenes, and Steps are the individual lines — together they narrate the Case from creation to resolution.

Case Life Cycle Design (Stage types & transitions)

Create Stage

The first Stage (green), which holds Steps to capture initial data on creation. It cannot be deleted or repositioned, and the Case ID is assigned upon creation. Stage transitions cannot be configured on the Create Stage.

Primary Stage vs. primary path

Two related Case Life Cycle concepts:

  • PRIMARY STAGE — a defined Stage that leads to the expected/successful outcome
  • PRIMARY PATH — the complete route through all Primary Stages without deviation; most Cases take this path

Alternate Stage

Handles deviations/exceptions from the primary path (optional); often a negative resolution or a place to fix issues and re-enter the primary path, typically reached via a Change Stage automation.

Resolution Stage

Marked red; defines end-of-life-cycle behavior. Every Case Type should have at least one Resolution Stage; a Case can resolve through more than one (e.g., approved vs. rejected). Case statuses ending in Resolved- (e.g., Resolved-Completed, Resolved-Rejected) typically close the Case.

Color cue: GREEN = Create (start), RED = Resolution (end). The primary path is the highway; Alternate Stages are detour ramps for exceptions.

Multi-step Forms

Multi-step Form

A single Assignment completed by a single user, broken into multiple focused, concise Views shown in sequence — a guided, linear set of screens. The default Create Process in the Create Stage is a Multi-step Form.

Navigation

Multi-step Forms support three styles: horizontal, vertical, and standard. All use Next/Previous; Submit appears on the last screen. Users can move back and forth unless required fields block them or the form is submitted.

A Multi-step Form is a checkout wizard: one purchase (Assignment) split into tidy pages (contact, items, payment) so the user is never overwhelmed by one giant form.

Draft Mode

Draft mode

A design state for rapidly outlining a Case Life Cycle — adding Stages, Processes, and Steps WITHOUT fully configuring each element. Ideal for capturing the shape of the Microjourney with stakeholders before detailing every rule.

Draft data objects

When you reference data that isn't built yet, Pega creates a Draft (placeholder) data object — no fields or integration settings — so the life cycle can progress in design; complete it later on the Data Objects landing page.

Draft mode is sketching the floor plan in pencil: you lay out all the rooms (Stages/Steps) fast, then go back and finish the wiring and plumbing (configuration) room by room.
