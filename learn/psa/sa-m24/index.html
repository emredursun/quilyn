What Automations are

Automation

An action the system performs automatically — no user input required. Examples: send a confirmation email, create a child Case, copy data. Automations and Collect information steps are the two shape categories in a Case Life Cycle.

Automation shapes are like robotic arms on an assembly line: instead of a human pressing a button to send a notification or run a calculation, the automation shape executes automatically when the process flow reaches that step — invisible to the end user but essential to the workflow. Remove one and the product comes out missing a component.

How to add an Automation

Two paths to add an Automation shape:

  • Case Life Cycle view: select a Step → More → Automations
  • Process modeler: Add → Automations (then configure with parameters specific to its purpose)

Automation vs. user Step

Two Step categories in a Pega workflow:

  • USER STEP (e.g., Collect information) — requires a person to act; creates an Assignment
  • AUTOMATION SHAPE — runs automatically when the Case reaches the Step; no user interaction needed

Automation shapes available in App Studio

Stage navigation shapes

Change to a Stage = move to a SPECIFIC Stage. Change to next Stage = advance automatically. Change to previous Stage = return to the previously visited Stage. Three distinct shapes — each behaves differently.

Case action shapes

CREATE CASE — creates child Cases. UPDATE A CASE — updates current Case or all descendants. PERSIST CASE — converts a temporary Case to a permanent DB record. SEARCH DUPLICATE CASES — auto-checks for duplicate submissions.

Document & content shapes

ATTACH CONTENT — attaches file, URL, or note. CREATE PDF — creates a PDF from a specified View and attaches it. GENERATE DOCUMENT — generates Case documents. Note: Create PDF and Generate document are separate shapes.

Communication shapes

SEND EMAIL — formatted emails to custom recipients. SEND NOTIFICATION — notification over multiple Channels. PUSH NOTIFICATION — iOS/Android mobile alert for a pending Case action. POST TO PULSE — posts a message to the Pulse feed.

Logic, AI & flow-control shapes

Key Automation shapes available in the Process modeler:

  • Run Data Transform: executes a Data Transform at runtime
  • Connect Generative AI: calls a GenAI model and maps the response
  • Decision: branches the flow via a When rule or Decision Table
  • Wait: pauses the Case until a condition or timer fires

Use cases and selection

Send email — use case

Send automated email correspondence to all relevant parties with no user interaction. Example: an online store emails a customer about new offers. You configure how the application determines the recipient and compose the email content.

Run Data Transform — use case

Run a selected Data Transform rule at runtime to set/copy/initialize Case data. Example: at checkout, if the billing address equals the shipping address, a Data Transform copies it automatically instead of making the customer re-enter it.
