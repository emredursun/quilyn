Child Cases

Top-level Case vs. Child Case

Two Case relationship roles:

  • TOP-LEVEL CASE — has NO parent but CAN become one (e.g., Accident Claim)
  • CHILD CASE — created within a parent Case (e.g., Vehicle Damage, Medical, Rental Car — each handled by different parties)

Child cases are like sub-tasks on a project plan: the parent project (case) cannot be marked complete until all sub-tasks (child cases) are done. In Pega, each child case runs its own independent Life Cycle and can be assigned to different teams — but the parent case waits for all children to resolve before it advances. One sub-task delay holds the whole project.

When to use child Cases

Use child Cases when work is performed by DIFFERENT PARTIES, follows DIFFERENT REPORTING OPTIONS, operates on DIFFERENT TIME FRAMES, or is COMMON TO MULTIPLE Case Types (reuse).

Create Case Step

Add a Create Case Automation Step to the Case Life Cycle to create a child Case. When executed, it creates a child Case of the specified Case Type. Dev Studio provides additional options, including contextual Case creation.

Data propagation — Copy vs. Data reference

How parent data is shared with child Cases:

  • COPY DATA — snapshots parent data at child creation; child is NOT updated if parent changes later
  • DATA REFERENCE — child data stays synchronized with the parent; requires advanced configuration in Dev Studio
