Child Cases

Top-level Case vs. Child Case

Two Case relationship roles:

  • TOP-LEVEL CASE — has NO parent but CAN become one (e.g., Accident Claim)
  • CHILD CASE — created within a parent Case (e.g., Vehicle Damage, Medical, Rental Car — each handled by different parties)

A project can have separate repair and inspection workstreams. Each follows its own plan and reporting needs. In the parallel child-Case model described here, finishing the parent requires the children to finish; this does not mean every intermediate parent Step is blocked. Design the coordination points rather than assuming a universal pause.

When to use child Cases

Use child Cases when work is performed by DIFFERENT PARTIES, follows DIFFERENT REPORTING OPTIONS, operates on DIFFERENT TIME FRAMES, or is COMMON TO MULTIPLE Case Types (reuse).

Create Case Step

Configure a Create Case automation in the parent Process to instantiate the intended child Case Type. Creation happens when that Step runs. Additional Dev Studio options include top-level creation and multiple children; the shape is not inherently child-only.

Data propagation — Copy vs. Data reference

How parent data is shared with child Cases:

  • COPY DATA — propagates selected values at creation; later parent edits do not synchronize the copy automatically. The child copy can still be edited by its own configured work.
  • DATA REFERENCE — use referenced parent data when later parent updates should remain available; advanced Dev Studio configuration is required. Do not infer a specific data-page implementation or write permission from the relationship alone.
