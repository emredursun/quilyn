Duplicate Search

Search duplicate cases

Automation Step for checking whether existing Cases resemble the current submission. Place it at the point in the Process where duplicate review is needed; a match is a candidate for review, not proof that two requests are identical.

Think of a reservation desk checking a second booking request. First it filters out unrelated reservations, then scores the useful similarities. A staff member examines the candidates and either rejects the duplicate submission or continues processing a distinct request. Finding a similar reservation does not combine the two records.

Basic conditions — candidate filter

Each configured basic condition must evaluate to true before an existing Case reaches the scoring stage. An equality comparison can require identical dates of birth, for example. A failed basic condition excludes that candidate; extra weighted matches cannot rescue it.

Weighted conditions — scored match

A true weighted condition contributes its assigned weight (1–100). After the basic filter passes, add the matching weights and compare the total with the configured threshold. Equality with the threshold qualifies; the score is not a probability or a promise of display order.

Resolving a duplicate

The review lets the user confirm a duplicate (Resolved-Duplicate, ending current processing) or ignore the suggestions and continue. Opening the original Case to update it requires customized behavior; detection alone does not merge records or transfer their data.
