SLAs: goals, deadlines, milestones

Service-Level Agreement (SLA)

Establishes a work-completion deadline to enforce on-time performance. Can be defined on an ASSIGNMENT or the overall CASE, and uses MILESTONES (goal, then deadline) to mark expected turnaround times.

Think of a delivery target and a late threshold. Reaching either milestone only performs what was configured: a priority change, a notification or another action. A deadline is not a universal instruction to close the request.

Goal vs. Deadline

Goal and deadline use the SLA’s configured start reference. Case-resolution configuration can refer to this Case, its parent or the top-level Case.

  • GOAL — desired completion time, normally the earlier target; calculate from the configured start reference
  • DEADLINE — the longest time work MAY take before it is 'late'

Escalation actions at milestones

When a milestone is missed, the SLA can increase Urgency AND run an escalation: NOTIFY (assignee, manager, participants, or Case creator), REASSIGN to another user/queue, or RESOLVE the Case. Repeating post-deadline escalation is covered by the passed deadline interval.

Three timed responses: worked example

For a calendar-time policy, Goal at day 3 can notify; Deadline at day 7 can reassign; a passed deadline interval of three days with one event can resolve still-open work at day 10. Configure every action explicitly and account for processing delay and calendars. The post-deadline Rule configuration is covered in SA-M16.

Urgency and prioritization

Urgency (Case vs. Assignment)

Urgency is numeric priority with maximum 100:

  • CASE Urgency — priority of the Case itself
  • ASSIGNMENT Urgency — initial value equals Case Urgency (default 10); Stage/Process-level SLA adjustments affect Case Urgency

Setting and increasing Urgency

Set the Case Type’s initial urgency in Settings. Updating a Case’s urgency supplies the new value for new Assignments, not existing ones. This does not prevent an existing Assignment’s own SLA from adjusting its urgency.

Get Next Work

Pega prioritizes work by Urgency. GET NEXT WORK hands users the highest-Urgency Assignment they can perform first, so high-priority work finishes on time. Design SLAs/Urgency so the right work outranks the rest.

Applying and configuring SLAs

Where SLAs apply (and the Create Stage exception)

SLAs apply to Case Types, Stages, Processes, and Collect-information/Approval Steps. EXCEPTION: the Create Stage cannot have a goal, deadline, or escalation — it collects data before Case processing begins.

Configuring a goal & deadline

Use the appropriate Case or lifecycle-element Goal & deadline configuration. Case resolution offers Custom SLA, Existing SLA or Never, and This/Parent/Top-level Case anchors. Do not assume every lifecycle panel exposes all Case-resolution options. The linked 24.2 challenge configures the Schedule repair Step; the supplemental topic now uses Pega Infinity Studio terminology.

Configuring escalation actions

Configure notification recipients and message at the relevant goal and deadline. The supplemental Case/Stage/Process instructions describe Creator and Participants. General SLA escalation also includes reassignment or resolution; available controls depend on the selected context.
