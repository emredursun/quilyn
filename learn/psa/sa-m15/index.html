SLAs: goals, deadlines, milestones

Service-Level Agreement (SLA)

Establishes a work-completion deadline to enforce on-time performance. Can be defined on an ASSIGNMENT or the overall CASE, and uses MILESTONES (goal, then deadline) to mark expected turnaround times.

SLAs in Pega are like a pizza delivery guarantee: the 'Goal' is the target delivery time (30 minutes — aim for this), the 'Deadline' is the breach point (45 minutes — must not exceed this). When the goal is missed, the urgency counter climbs (yellow). When the deadline is missed, it turns red and the system escalates automatically — whether that means reassigning the task or sending a manager alert.

Goal vs. Deadline

Two SLA time targets, both measured from when the Assignment (or Case) started:

  • GOAL — how long work SHOULD take (desired, earlier target); interval is always shorter
  • DEADLINE — the longest time work MAY take before it is 'late'

Escalation actions at milestones

When a milestone is missed, the SLA can increase Urgency AND run an escalation: NOTIFY (assignee, manager, participants, or Case creator), REASSIGN to another user/queue, or RESOLVE the Case. Repeating post-deadline escalation is covered by the passed deadline interval.

Urgency and prioritization

Urgency (Case vs. Assignment)

Urgency = numeric priority (0–100, MAX 100):

  • CASE Urgency — priority of the Case itself
  • ASSIGNMENT Urgency — initial value equals Case Urgency (default 10); Stage/Process-level SLA adjustments affect Case Urgency

Setting and increasing Urgency

Set INITIAL Urgency on the Case Type's Settings tab. Each SLA interval defines an increase value (1–100). IMPORTANT: updating Case Urgency applies to NEW Assignments only — existing Assignments keep the Urgency from when they were created.

Get Next Work

Pega prioritizes work by Urgency. GET NEXT WORK hands users the highest-Urgency Assignment they can perform first, so high-priority work finishes on time. Design SLAs/Urgency so the right work outranks the rest.

Applying and configuring SLAs

Where SLAs apply (and the Create Stage exception)

SLAs apply to Case Types, Stages, Processes, and Collect-information/Approval Steps. EXCEPTION: the Create Stage cannot have a goal, deadline, or escalation — it collects data before Case processing begins.

Configuring a goal & deadline

In App Studio (Case Types → Settings, or a Lifecycle element → Goal & deadline): pick 'Use SLA' = Custom/Existing/Never. Choose a time anchor (This/Parent/Top-Level Case). Enter Goal and Deadline as Days + HH:MM:SS with an urgency-increase value.

Configuring escalation actions

On the Goal and Deadline sections you add NOTIFY recipients (Creator and/or Participants — manage the participant list), choosing a default or composed message; you can also reassign or resolve. Escalation actions cannot be set on the Create Stage either.
