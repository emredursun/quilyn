Preparing a physical Android device

USB debugging is the step most often missed. A device can charge normally and even appear as a storage device in the OS, yet remain completely invisible to TMA — the symptom looks like a Tosca problem but is a device configuration one.

Creating an Android emulator

Android Studio and the AVD Manager

Tricentis recommends Android Studio for emulators. Its AVD (Android Virtual Device) Manager creates emulator profiles by pairing a device definition (e.g. Pixel 7) with a system image (a specific Android version and CPU architecture).

The emulator must run on the same machine as TMA. Tosca cannot reach an emulator running on a different physical or virtual machine than the TMA instance it's talking to.

Platform-specific gotchas

The Android Emulator does not exist for Windows on ARM. Google ships no ARM64 Windows emulator package — the SDK Manager simply never lists an emulator package, and AVD creation fails with 'Dependant package with key emulator not found'. On an ARM Windows machine, the only paths are a physical device, or running the emulator on a different (x86_64 or Apple Silicon) host machine with TMA installed alongside it.

Getting AppPackage and AppActivity

Why these two values matter

To open an already-installed Android app, Tosca's Open Mobile App Module needs AppPackage (the app's unique identifier, like a reverse-domain name) and AppActivity (the specific screen/entry point to launch). These are Android's own identifiers, unrelated to Tosca — the same values any Android automation tool would need.

adb ships bundled with TMA — on Windows under C:\Program Files\Tricentis\Mobile Agent\app\android-sdk\platform-tools, and it is also included with any Android Studio install under ~/Library/Android/sdk/platform-tools on macOS or the equivalent Windows path. A separate Android SDK install is not required just to use adb.

Leave Application, BundleID, and Application Path empty in the Open Mobile App Module when the app is already installed on the device — those fields are for installing a fresh app from an APK file, not for opening one that's already there.
