From the concept to the configuration

Where this picks up

Tosca documents a DeviceName value that requests Appium dynamic selection of a connected Android or iOS device. This independent local guide explains that setting and operational checks; it does not reproduce an unavailable Academy exercise or certify a scheduling policy.

Configuring documented dynamic selection

DeviceName selection value

Set DeviceName to TOSCA_DYNAMIC_DEVICE_SELECTION to request that Appium dynamically select a connected iOS or Android device. This is a documented literal value, not arbitrary wildcard syntax or a criterion expression. The guide does not establish a Ready/non-Busy scheduler, fairness, queue timing or reservation guarantee.

Select a platform and supported configuration appropriate to the test. Inspect the resolved device and application state rather than assuming every connected target is interchangeable.

Validate the selected target

Dynamic target selection

The documentation assigns dynamic selection to Appium. Do not infer that TMA implements a particular queue, filtering or reservation algorithm. Record the selected target from available execution/session evidence and validate the required application state.

Avoid assuming that a dynamically selected target repeats a previous device’s display or installed state. Fixed targeting can make a device requirement explicit, but even a fixed device still needs availability and state checks.

Availability and test assumptions

These are independent operational checks, not guaranteed diagnoses. Use logs and actual target/capability evidence to distinguish capacity, configuration, driver and application problems.
