Why iOS needs a Mac

XCUITest is Xcode-only

iOS automation runs on XCUITest, Apple's own UI testing framework, which is only accessible through Xcode — and Xcode only installs on macOS. There is no Windows or Linux equivalent, so TMA cannot drive an iOS device or simulator unless it is running on a Mac.

This is a hard platform constraint, not a Tricentis limitation. Every iOS automation tool built on Appium's XCUITest driver — not just Tosca — shares this same requirement.

Preparing a physical iOS device

Developer Mode is off by default on every iOS 16+ device and is easy to miss because it doesn't appear in Settings at all until Xcode (or an app signed for development) has attempted to run something on the device at least once. If the toggle isn't visible, connect the device to Xcode first and try running/installing something to surface it.

Using the iOS Simulator

Simulator vs physical device

The iOS Simulator, launched through Xcode, runs an iOS runtime on the Mac itself rather than on real hardware — no cable, no Developer Mode toggle, no Trust prompt. It's the fastest way to get started, but it cannot exercise hardware-dependent behaviour (camera, real biometrics, cellular, certain sensors) the way a physical device can.

Identifiers: UDID and BundleID

UDID — identifying the device

Every physical iOS device and every simulator instance has a UDID (Unique Device Identifier). For a physical device, it's visible in Xcode's Window → Devices and Simulators panel, or via the command line with xcrun xctrace list devices. Simulators are identified the same way, listed alongside physical devices in that same command's output.

BundleID — identifying the app

iOS apps are identified by a BundleID (a reverse-domain string like com.company.appname) — the iOS equivalent of Android's AppPackage. Unlike Android, iOS has no separate 'activity' concept to also supply; the BundleID alone is enough to tell Open Mobile App which installed app to open.

As with Android, leave Application and Application Path empty in the Open Mobile App Module when the app is already installed — supply only the BundleID. Those Application/Path fields exist for installing a fresh .ipa, not for opening an app that's already on the device.
