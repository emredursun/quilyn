Why iOS needs a Mac

XCUITest is Xcode-only

The TMA 2025.4 support matrix lists macOS as the supported iOS host and requires matching Xcode support for iOS 17+ devices. Use a Mac Agent host for this documented setup; Tosca Commander may connect to that host remotely.

This is a version-specific supported topology, not a universal claim about every iOS automation product. Some Agent preparation pages retain Windows instructions; do not treat those as overriding the 2025.4 support matrix without vendor confirmation.

Preparing a physical iOS device

Apple documents that pairing makes Developer Mode available in Settings; an attempted app run is not the only trigger. Development-signed installation can also expose the setting. Ordinary App Store/TestFlight installation is a different workflow.

Using the iOS Simulator

Simulator vs physical device

Simulator supports development and UI checks on a Mac, but it does not reproduce all physical-device features or performance. Simulated biometric success/failure responses are different from validating real biometric hardware. Use real devices for hardware and performance evidence.

Identifiers: UDID and BundleID

UDID — identifying the device

Keep the target device or simulator identifier separate from the application identifier. Select and confirm the intended target in Xcode/Agent device management; do not substitute an app’s BundleID for the device identifier.

BundleID — identifying the app

BundleID identifies the installed iOS application to open. Tosca’s iOS opening method does not require Android AppActivity; the device connection and automation driver still need their own configuration.

Use BundleID for an installed iOS app. Application Path is the alternative installation method: .ipa for a physical device and .app for Simulator. Obtain a build for the correct target rather than treating a physical-device IPA as a Simulator application.
