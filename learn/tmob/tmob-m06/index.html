The Mobile Scan wizard

One wizard, three app types

Mobile Scan creates Modules for native, hybrid and mobile web applications. Prepare the environment, select a connection, device and application, then select controls. Adding device/application entries is optional when suitable entries already exist.

A scan connection does not validate all execution settings. Compare effective configuration and use the documented endpoint format without assuming a universal trailing-slash parsing defect.

Configuring Capabilities

The wizard's three panes

Select connection, Select device and Select application organize the target choices. Local/Remote TMA connections can show installed apps, not merely apps scanned before.

Desired Capabilities

Set capabilities opens named capability sets. Configure supported names and values for the actual driver; Appium extension capabilities use the appium: namespace, while standard WebDriver capabilities are distinct.

Capability Sets — reusable, named bundles

Add capabilities set creates a named group; Add capability adds an entry to the selected group. Select Capability Set applies that group to the scan. It is not a separate one-off versus reusable mechanism.

For a UiAutomator2 Android session, autoGrantPermissions applies to supported runtime permissions and has target SDK/API requirements; special permissions need separate handling. For XCUITest on iOS, autoAcceptAlerts includes privacy alerts. They are driver-specific examples, not a universal two-setting bundle or proof that permission behavior has been tested.

Scanning a native app

What gets captured

Select controls in Live View or via Advanced View checkboxes and inspect the properties actually exposed by the application/engine. Choose an identification strategy that uniquely identifies the target; do not assume every app exposes the same useful metadata.

Control identification quality depends heavily on how well the app under test exposes accessibility metadata. A poorly-labelled app (generic resource-ids, no accessibility labels) produces weaker, less stable identification — the mobile equivalent of a web page with no useful CSS selectors or test-ids.

Scanning a hybrid app

Native shell, embedded webview

A hybrid app wraps one or more web views inside a native shell. From the outside it looks and behaves like a native app, but part or all of its content is actually rendered as HTML/CSS/JS inside an embedded browser engine.

Context switching during scan

When Mobile Scan detects a hybrid app, select Native for its native controls or Web and the appropriate webview for embedded content. Re-select the context when scanning another screen if prompted.

Missing web controls can involve the selected context, WebView debugging, browser compatibility or application configuration. Check the actual context and prerequisites; do not infer a single cause from the symptom.

Scanning mobile web

The device's own browser, scanned in its device context

Mobile Scan opens a website on the selected device, emulator or simulator. This exercises that target’s browser environment; a resized desktop viewport alone does not validate the same browser/device behavior.

An emulator or simulator scan is not a physical-device test. Scanning identifies controls; runtime gestures and user behavior still require execution and validation.
