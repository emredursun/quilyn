Beyond the local machine

Where this part picks up

Mobile tests can run in parallel on multiple devices, and can use DEX or CI orchestration. Tosca Cloud artifact upload is a separate integration path; execution still depends on supported agents, connections and target infrastructure. Earlier local examples do not restrict the platform to one TestCase or device.

Tosca Distributed Execution (DEX)

TestEvents and ExecutionList configurations

A TestEvent contains ExecutionLists and configurations. The Distribution Server assigns lists to Agents whose configuration matches; users can explicitly configure eligible Agents and lists. In Tosca 2026.1 LTS, DEX is no longer enabled by default and requires activation.

Agent matching does not replace mobile session configuration. For parallel mobile execution, verify licensing, target isolation and driver port requirements; dynamic target selection is not mandatory.

Tosca Cloud

Uploading an ExecutionList

Upload creates a copy in the selected Tosca Cloud workspace, without bidirectional synchronization. A supported uploaded ExecutionList is represented as a playlist, available under Build > Playlists and Run > Playlists. Upload does not certify mobile execution readiness; infrastructure and permissions must still be configured.

Only changed selected objects can reduce re-upload work, but uploads overwrite existing Cloud objects and do not synchronize Cloud changes back. Check supported artifacts, excluded resources and version restrictions: TestEvents and configuration objects are excluded even though stored configuration TCP values can be included.

What this means for mobile specifically

Distribution raises the stakes on device configuration

Plan separate usable targets and supported session/port configuration for concurrent runs. Fixed device assignment can be valid when targets are isolated; dynamic selection is an option, not a DEX/Cloud prerequisite. Application state and compatibility still need validation.

Preserve orchestration, Agent, driver and Tosca evidence with timestamps and available session identifiers. A console is not necessarily gone, and one log source or ID is not guaranteed to reconstruct the whole run.
