What a capability actually is

Session-level configuration, not TestCase logic

Appium capabilities are supplied when a session starts and cannot be changed during that session’s lifecycle. Driver-supported Settings APIs can change some runtime behavior without changing the session capabilities; distinguish those mechanisms. Tosca scan capability sets and execution Set/Add Desired Capabilities Modules are separate configuration paths.

Standard W3C capabilities such as platformName and browserName do not need the Appium extension prefix. Appium-specific capabilities use appium: (or supported appium:options grouping). Verify the actual driver/version’s capability support rather than treating all names as universal.

Grouping them by what they control

Why grouping helps

Grouping helps navigate documentation, but a symptom does not prove one capability is the cause. Inspect the target, focus, application state and driver logs before selecting a supported change.

The cost nobody mentions

Automatically accepting alerts or granting permissions can reduce deliberate coverage of their appearance, text and acceptance/denial paths. It does not prove that every alert becomes impossible to observe in logs or other instrumentation, nor guarantee uninterrupted execution.

Choose configuration for the test objective

For a workflow that needs granted permissions, a supported automatic grant may be appropriate. For permission or alert behavior coverage, use controlled initial state and explicitly verify the required dialogs and outcomes. Suppression is not a universal recommended default for the whole suite.

Treat this as independent coverage guidance. Verify which behavior was exercised, rather than treating a higher pass rate as proof of equivalent coverage.

Capability Sets versus one-off entries

Naming a bundle you will reuse

In the scan Capabilities window, Add capabilities set creates a named group and Add capability adds an entry to the selected group; it is not a separate ungrouped one-session mode. For execution, place Set Desired Capabilities first, with ActionMode Select, before Open Mobile App/OpenUrl; Add Desired Capabilities can extend the pending values before opening.

Tosca documents capability carry-over between sequential TestCases: use Set Desired Capabilities first in each TestCase, leaving Name/Value blank when none are needed, to prevent unintended carry-over. Validate execution setup separately from scan configuration.
