Test configuration parameters (TCPs)

The same TCP mechanism used elsewhere in Tosca

TCPs configure test environments on supported Tosca objects. Child objects inherit values and can override them; Configurations bundle reusable TCP values.

Static vs Dynamic device allocation

Static allocation

Specify the verified device identifier to target one device. Availability and successful connection still need checking; pinning an identifier does not guarantee a run will start.

Dynamic allocation

Use TOSCA_DYNAMIC_DEVICE_SELECTION for the documented dynamic selection mechanism. It is not an arbitrary wildcard in DeviceName. Dynamic selection does not by itself enable parallel execution or guarantee coverage of every matching device.

Choose a specific identifier for device-specific reproduction. Configure supported selection and parallel-execution settings separately when using a device pool.

Validate the documented address format

The documented Remote (TMA) address format ends with a slash: http://<ip_address>:<port_number>/. Use the configured endpoint and port. This format alone does not prove how every version builds URLs or explain a particular session error.

A successful scan is useful evidence, but does not prove that the execution uses the same effective configuration. Compare inherited TCPs, selected device, endpoint and session logs rather than assuming a universal scanning-versus-execution parsing difference.

Local vs Remote, set up for real

Local (TMA)

In a local setup, the Agent and Tosca run on the same host. Some locally connected scenarios do not require explicit TMAServer or DeviceName values; check the platform-specific requirements.

Remote (TMA)

In a remote setup, the Agent and Tosca run on different computers. For TMA 2025.4 iOS hosting, follow the macOS support matrix rather than assuming all older host descriptions remain supported.

The documented remote CLI setup uses start --rest-address <IP>:<port>. Configure the Appium endpoint separately with its own port; reaching the web interface alone does not prove an automation session can start.

Diagnosing device-side vs Tosca-side

Use evidence from each connection layer

A device listed in the Agent is discovery evidence, not proof that application launch, driver setup, session negotiation and network routing all work. Record the failed operation and logs before assigning responsibility.
