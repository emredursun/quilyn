Opening the application after capability setup

Application opening and capability ordering

Use Open Mobile App to begin native/hybrid application steering. Desired Capabilities setup is the documented exception: Set Desired Capabilities, and any additions, precede application opening. Mobile websites use OpenUrl.

Do not generalize this ordering to every Engine or resource-opening Module. Check the specific application and capability workflow.

What Open Mobile App actually does

It's more than a click-through step: Open Mobile App creates the mobile device session (via TMA) for the TestCase, and it can install the app on the device at the start of that session if an install source (a local .apk path, or the equivalent iOS install path) is configured — or, for an app already on the device, open it directly by its identifier: BundleID for iOS, or AppPackage/AppActivity for Android.

Switch Mobile App

For TestCases that move between apps mid-flow (e.g. testing a deep link handoff, or a share-sheet interaction that opens a different app), Switch Mobile App changes the active app context without needing a second Open Mobile App step.

Gestures: when there's no control to click

Coordinates need validation against the actual layout. Click/Swipe support percentages as well as pixels; relative coordinates can scale with the screen but do not automatically locate a moved control. Prefer stable scanned identifiers when suitable.

Text entry and the keyboard

Send Text Input To Focused Control

Enters text into whichever control currently has focus — typically used right after tapping a text field, mirroring how a real user would tap then type.

Set Autohide Keyboard

Set Autohide Keyboard controls iOS onscreen keyboard auto-hide: True enables it and False disables it. Check the actual platform and resulting keyboard state; do not present this as a universal Android/iOS dismissal guarantee.

Running with LiveView

Watching execution happen

For local mobile execution, LiveView=True displays a screenshot preview when the TestStep changes. It is not a continuous video or proof of the exact screen at every failure instant.

Use preview alongside execution logs and assertions during debugging. Choose preview settings for the run’s needs rather than assuming a measured performance improvement from switching it off.
