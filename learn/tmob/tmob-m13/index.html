Documented mobile image-based workflow

The Mobile Engine does not support Edit images. For resolution variations, configure Tbox_Engines_ImageBased_ImageSearchMethod: MultiScaleTemplate scales images at a performance cost; Feature is an alternative when that method cannot find a match.

Why image-based identification exists

The gap it fills

Image matching can help when stable usable control properties are unavailable, including some custom-rendered surfaces. Inspect the actual hierarchy and identifiers first: a canvas, map or chart does not universally imply that no accessible target exists.

What IBTA matches on

A captured target image and optional additional reference images help locate an on-screen control. Accuracy controls how closely the image must match. Successful identification locates a target; separate assertions are still needed to verify business behavior.

Properties and image matching use different identification evidence. This local decision guide recommends validating uniqueness, rendering variation and outcome assertions whichever method is chosen.

What breaks an image match

A changed image match does not by itself classify a product build as passing or failing. Separate expected rendering changes, identification maintenance and actual defects using the requirement and assertion evidence.

Matching tolerance

Higher Accuracy requires a closer match; lowering it allows more differences and may admit unintended regions. Additional reference images and supported resolution search methods can help. Validate both intended matches and competing similar regions; do not blindly lower accuracy until a run passes.
