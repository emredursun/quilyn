Two jobs, one mechanism

Connection TCPs versus tuning TCPs

Documented mobile TCPs configure connection, target and execution behavior. TMAServer and DeviceName are connection/target examples; LiveView, ScreenFlow, ScrollToVisible and TapByCoordinates control other documented behavior. Type is a Mobile Scan selection, not a generic execution TCP listed in the mobile TCP table. Invalid values in either group can produce errors; failure timing is not a guaranteed classification.

Treat these categories as an explanatory aid, not a rule that connection mistakes always fail immediately while all other mistakes remain silent. Inspect actual effective values and failure evidence.

Parameters that shape a run

Reset application and test independence

Establish the application, account and relevant backend state required by each test. A driver-specific application reset may be useful, but a scan checkbox does not certify execution reset, complete backend cleanup or independence of every subsequent test.

Scoping, and why it starts mattering here

The same TestCase, several environments

TCPs are supported on multiple Tosca objects, including the project root, relevant folders, TestCases, ExecutionLists and ExecutionEntries. Child objects inherit values and lower-level values can override them. Bundled configurations support reuse; inspect effective values for each environment rather than inventing a fixed Project → Configuration → environment hierarchy.

For otherwise equivalent scenarios, reuse TestCases and maintain connection differences in supported configurations to reduce duplication. Different workflows or target capabilities may still require purposeful test variants.
