Troubleshooting as its own skill

Why this deserves a dedicated part

Device, Agent, network, driver, application and Tosca configuration can all contribute to a failure. This independent local diagnostic guide uses accessible technical documentation; choose checks from observed evidence rather than assuming one universal fastest sequence.

A layer-by-layer method

A successful check narrows a hypothesis but does not rule out an entire layer. Prioritize the error and reproduction evidence, then retest the smallest relevant operation.

Reading TMA's own logs

Why go past the console

Agent and driver logs can provide information about failed sessions beyond a status summary. Tosca’s Log Viewer adds execution evidence and supports text/regex search. Logging detail and retained history vary; preserve the relevant run before logs expire.

TMA 2026.2 documents Agent Settings → Agent Logs → Download Logs, a cadence up to five days, and selectable iOS, Android and Appium log types. This UI is version-scoped: it is not certified here for TMA 2025.4. Compare evidence from the actual installed version.

Session correlation

Use a session ID where present together with timestamps, target information and the failing command to correlate a run. Do not assume every log line contains that ID or that a session-creation failure produced an ID. Correlation helps locate evidence; it does not edit controls or TestCase data.
