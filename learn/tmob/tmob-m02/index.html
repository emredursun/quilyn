Getting TMA installed

A separate installer from Tosca Commander

TMA ships as its own installer, downloaded from the Tricentis Support Hub or Tosca Downloads area, and installed independently of Tosca Commander. It can live on the same machine as Tosca Commander (Local setup) or on a different machine entirely (Remote setup) — the installer itself is identical either way; only where you run it differs.

TMA is officially documented as supported on bare-metal hardware, not inside a virtual machine. It can still work inside a VM in practice, but that puts you outside supported territory the moment something misbehaves — worth knowing before troubleshooting a VM-hosted setup.

Starting TMA: tray launch vs command line

Tray / Start Menu launch — local use only

Launching TMA from the system tray icon (or the Start Menu / Applications folder) starts the agent bound to the local machine. This is sufficient whenever Tosca Commander and TMA run on the same machine.

Command-line launch with --rest-address — required for remote use

When Tosca Commander and TMA run on different machines, TMA must be started from the command line with the --rest-address flag, binding its REST API to a network-reachable address instead of localhost only: tricentis-mobile-agent start --rest-address <IP>:<port>.

Starting TMA from the tray/GUI does NOT enable remote access, even if the machine is reachable on the network. Only the --rest-address command-line start exposes the REST API beyond localhost. Seeing the TMA console load from another machine's browser is not proof remote mode is active — the console and the automation REST API are not the same thing.

Ports and firewalls

Default port 8585

TMA's default REST port is 8585. In a Local setup this rarely matters since traffic never leaves the machine. In a Remote setup, that port (or whichever custom port is chosen) must be reachable from the Tosca Commander machine — meaning any firewall between the two machines needs an explicit allow rule.

A REST call to http://<TMA-host>:<port>/api/devices is the fastest way to prove the port is reachable and TMA is responding, independent of anything in Tosca — covered in full in the Connecting Tosca to TMA lesson.

The TMA console

Device Management

Once TMA is running, its console (reachable at http://<TMA-host>:<port> in a browser) lists every device, emulator, or simulator TMA can currently see, along with a status: Ready, Busy, or Offline. Confirming a device shows Ready here — before opening Tosca at all — isolates device-layer problems from anything Tosca-side.

Keeping TMA up to date

Version alignment with Tosca

TMA and Tosca Commander are versioned and released independently, but a very old TMA against a very new Tosca (or vice versa) can produce session-start failures that look like device problems. When something that used to work stops working after a Tosca upgrade, checking for a matching TMA update is a reasonable early step.
