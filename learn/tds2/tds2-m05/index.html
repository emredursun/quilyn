One module, every function

TestData - Expert Module

Rather than assembling a TestCase from several separate Standard Modules (Create, Find, Update...), the Expert Module performs all of those functions itself, plus extra ones the standalone modules don't offer — ReadOnly, deleting individual records, and deleting entire types. It's included in the Standard.tsu subset, under Standard modules → Test Data Management → Test Data Service.

Test data task*

The Expert Module's key TestStepValue is a dropdown listing every supported function: Create, ReadOnly, Find, Update, DeleteType, DeleteRecord, DeleteAll. Whichever is selected tells Tosca exactly what to do with the data in that TestStep.

The seven Test data task options

DeleteType removes one type and its records. DeleteAll wipes the whole repository — every type, every record. Don't reach for DeleteAll when only one type needs clearing.

ReadOnly: the one function that doesn't lock

What makes it different

Every other Test data task locks the record it touches by default. ReadOnly is the exception: it reads the data without modifying it, and explicitly does NOT lock the record — leaving it free for others to use.

When to reach for it

ReadOnly fits data meant to be reused across many TestCases at once — contract data, user ID numbers, reference data, or credit card numbers. For example, a bank transaction test might just need 'any' valid Visa card number, with no requirement that it be unique to that test. In a distributed environment, several testers on different workspaces need to be able to borrow that same reference record simultaneously.

If reusable reference data like this were locked by default, concurrent TestCases could fail simply because they collided over the same record — ReadOnly exists specifically to avoid that.

Worked example: order Hoodies, then cancel

Step 1 — Create

Add the Expert Module, select 'Create' as the Test data task*, name the TDS type 'SampleOrders', and set the Alias name (record) to 'order'. Entering the data structure Attributes — OrderID, Product name, quantity, Price, Order Status, Year of Manufacture — creates those as separate columns in the TDS repository.

Step 2 — ReadOnly

Add another Expert Module, this time selecting 'ReadOnly', to read the order just created. This automatically unlocks that record — meaning, in a real project, the order number could then be picked up and reused by anyone else who needs it, rather than staying locked to this one TestCase.
