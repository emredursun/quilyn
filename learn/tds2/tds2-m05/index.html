One module, every function

TestData - Expert Module

Combines operations offered by dedicated TestData modules and adds reading and lock-management tasks. It belongs to the Standard subset under Test Data Management → Test Data Service. Security-enabled installations may restrict operations by user group.

Test data task*

Select the operation through Test data task. Tosca 2026.1 LTS documents Create, ReadOnly, Find, Update, DeleteItem, DeleteType, DeleteAll, LockItem, UnlockItem, LockType and UnlockType. Check the module shipped with your installed version.

Choose the task and its scope

DeleteType removes one type and its records. DeleteAll wipes the whole repository — every type, every record. Don't reach for DeleteAll when only one type needs clearing.

ReadOnly does not reserve an item

What makes it different

ReadOnly reads without acquiring an item lock. It is not the UnlockItem operation and should not be used to release a lock acquired earlier. Find reserves the retrieved item for exclusive use; documented automatic release occurs after execution or at a new loop iteration, including failure.

When to reach for it

Use non-locking reads for shared reference values when the test does not require exclusive consumption. For example, several tests may read the same synthetic product-category record. Reading without reservation does not guarantee the data remains unchanged by other tests.

Choose Find when the test needs an exclusive item. Use explicit UnlockItem when releasing a known lock; do not assume ReadOnly releases it.

Independent synthetic order example

Step 1 — Create

Set Create, type SampleOrders and alias order. Under Data structure, add OrderID and Status values with ActionMode Input. This creates an item containing those attributes.

Step 2 — ReadOnly

Set ReadOnly and constrain OrderID to the intended item. Use Verify to check Status or buffer a value for later use. This read does not acquire a lock; it does not automatically unlock a previously reserved order.
