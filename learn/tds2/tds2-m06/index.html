Repository administration

Configuration versus test items

A repository connects Test Data Service to a data store. Creating or changing its configuration is different from finding or updating an item within it. API Scan can also manage test data; item operations are not exclusive to the Standard Modules.

This is an independent documentation-based workflow. The Academy video and its endpoint examples have not been verified. Use the Swagger definition of your installed service for exact methods, paths and payloads.

Generate the API Scan message tree

Use the installed definition

On the Tosca Server machine, open the Test Data Service Swagger documentation and download swagger.json. Select Home > File in API Scan to load that definition. Check the base path before scanning it. The documented examples use API v2.

The Gateway documentation address is http://<server address>:<port>/testdataservice/swagger/index.html. With an HTTPS binding, the documentation instructions instead use the local Test Data Service port on the server machine. Select a definition to inspect the desired API version.

Create a repository: inspect the contract

Avoid a universal payload template

Select the create operation in the installed Swagger definition and inspect its method, request schema and required fields. Do not assume a four-field SQLite example is valid for every database type.

For a JSON request body, use the media type declared by its API definition. A Content-Type header alone does not authenticate the request or grant repository permissions.

Independent practice exercise

In a disposable environment, prepare a repository named PracticeData using the installed schema. Inspect the response, then verify its configuration in Test Data Management. No successful API execution is claimed by this lesson.

Read repository details safely

Collection versus one repository

Inspect the definition for the read operation, including whether it returns a collection or targets one repository. Use its documented path parameters and response schema. A collection address should not be assumed to return one named repository.

Update repository configuration

Check supported changes

Use the installed API definition to identify the update contract; do not guess that it is the same as Create. In the documented Test Data Management editor, only Name and Description can be changed because other changes require migration.

An edit is not a migration

The web editor does not support editing InMemory repositories. These web UI limits do not establish a different API contract; consult the installed definition before automating configuration changes.

Delete a repository: check the data effect

Repository versus database deletion

Deleting repository configuration must not be confused with erasing the underlying data. The documented web dialog has a separate Also delete database option for permanent database deletion. Inspect the equivalent API operation and parameters before using it.

Independent verification exercise

Use only disposable practice data. Check the request target and response, then verify which configuration and data remain. A missing repository tile alone is not proof that its database was erased.

Save the project or export messages

Home > Save as saves an API Scan project; Home > Open reopens one. API TestCase exports selected messages to Tosca Commander. These are separate operations: do not promise that Save as creates a .tsu subset importable into every workspace.
