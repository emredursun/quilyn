Why manage TDS via API

Beyond the web portal and Standard Modules

Everything so far — creating, retrieving, updating, deleting — has gone through TDS Standard Modules or the Test Data Management web page. This lesson demonstrates doing the same repository-level operations directly through Tosca's API Scan, calling REST endpoints instead.

This lesson operates one level up from the earlier lessons — it manages the REPOSITORIES themselves (creating/updating/deleting a whole TDS repository), not individual records inside one.

Setting up the API Scan

Getting started

In the API Testing tab, click API Scan. Rename the default folder to 'Manage Repositories' — every message in this lesson lives inside it.

Create Repository — POST

Building the message

Rename the default 'Create Message' to 'Create Repository'. Set the Method to POST, and the Endpoint to the repository path. Paste the standard message format onto the Payload tab, filled in with the new repository's values.

Under Headers, add Name = 'Content-Type' with Value = 'application/json' — required for every one of these calls, not just Create.

Verifying it worked

Run the message, then open (or refresh) the Test Data Management page on the Tosca Server — the new repository appears there as a tile.

Retrieve Repository — GET

Reading repository details

Right-click 'Manage Repositories' → Create Message, rename it 'Retrieve Repository', and set Method to GET with the same repository path in the Endpoint used during creation. Running it returns the repository's details in the Payload tab — no message body is needed for a GET.

Update Repository — POST

Changing existing values

Create another message, rename it 'Update Repository', set Method to POST, and reuse the same Endpoint (repository path + the specific repository name to update). Paste the same standard JSON format onto the Payload tab, this time editing the values you want to change. The Content-Type header is required again.

Verifying it worked

Run the message, then refresh the Tosca Server landing page — the updated repository details are now reflected there.

Delete Repository — DELETE

Removing a repository

Create a message named 'Delete Repository', set Method to DELETE, and set the Endpoint to the same repository path used for creation, followed by the name of the repository to delete. Running it removes that specific repository.

Verifying it worked

Refresh the Test Data Management page — the deleted repository (e.g. 'DemoWebShop') no longer appears among the tiles.

Saving your work

Use 'Save As' from the menu bar to save these API artifacts in .tsu format — the same subset format used throughout the course — so they can be re-imported into any Tosca workspace later.
