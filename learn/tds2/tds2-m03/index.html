Creating records with a TDS Standard Module

Where the module lives

Use TestData - Create & provide new item from the Standard subset's Test Data Management → Test Data Service folder to add an item to an existing or new type. Security-enabled installations may restrict access by user group.

Using the module

Specify Existing or new TDS type and define the needed attributes under Data structure with ActionMode Input. Supply an alias when later operations need to identify this item.

Alias name

What it's for

An alias identifies an item available during the TestCase; it is not a repository column or a search condition. The documented Find workflow uses the type name as the default when its alias is omitted. Use an explicit alias for later update, move or delete operations.

When it actually matters

Independent example: find sender and recipient items using appropriate selection criteria, then assign distinct aliases so subsequent steps address each known item. An alias alone does not choose the correct role or replace those criteria.

Do not infer which aliases an inaccessible Academy exercise used; the example here is independent and uses explicit aliases.

Quick self-check

Check both selection and identity: Find criteria determine the intended item; its alias addresses the retrieved item in later steps. A default type-name alias is not the name of its first attribute.

Viewing records and understanding the lock

Finding your data

Use Test Data Management to inspect the intended repository, type and item attributes. Its lock controls indicate reservation; a manually locked item is not editable in the Web UI. Interface colors and layout may vary with the installed version.

Find reserves the retrieved item. Automatic release is documented after execution or a new loop iteration, including failure. ReadOnly does not acquire that lock; explicit release is a separate operation.

Independent synthetic customer example

Inputs and initial state

Create an item of type CustomerDetails with alias customer. Set a synthetic Email and Status = New using Input. These are example attributes, not a built-in customer schema or a verified Academy registration walkthrough.

For repeated execution, link the configured TestCase in an ExecutionList and inspect results for each run. No Tosca execution has been performed as part of this editorial example.

Generating multiple records at once

Repetitions

Set the ExecutionEntry's Repetitions property to run its TestCase multiple times with the same values. If each successful run creates one item, five successful runs add five items. Repetitions alone does not generate unique data or guarantee successful creation; check each result.
