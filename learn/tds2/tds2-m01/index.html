Core TDS terminology

Test Data Service

TDS manages test data in distributed environments. Its web interface shows the types in a selected repository and the items in a selected type; access may be restricted by authorization.

How Tosca Commander and TDS talk to each other

Explicit operations

Standard Modules create, find, update, move and delete test items. The test configuration selects the service and repository. API Scan can also manage test data using the installed service definition.

Application state is separate

An application action does not automatically synchronize a TDS property. Model the application action, verify its result, and explicitly write the needed test-data state. The web data view is not a test execution report.

Independent example: profile → file → upload

Suppose one test creates a practice user, another prepares a file, and a third uploads it. Record the actual identifiers needed by later steps. For a focused upload test, provide a suitable user and file during setup rather than assuming the whole journey must always run first.

Selection and ownership

Find & provide item selects a matching item and locks it for the test. ReadOnly in the Expert Module reads without acquiring that lock; it is not an unlock operation.

Find releases its lock after execution, on failure or at a new loop iteration. A lock coordinates TDS item access; it is not proof of an application-level database transaction or permanent consumption.

Independent order-process example

This is a Quilyn teaching example, not a verified Academy video transcript or executed DemoWebShop walkthrough. Status, OrderStatus and Used are example names rather than automatic TDS lifecycle rules.

Explicit purchase-state assumption

Suppose the purchase test has successfully obtained an order identifier and its next TDS Update step is configured to add OrderNumber and set OrderStatus to Pending. That step writes those properties. The application purchase alone does not do it, and completion does not automatically move the item.
