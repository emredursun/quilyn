Installing Tosca Server with TDS

Version matching

Tosca Server must be downloaded in the same version as your Tosca Commander (e.g. Commander 12.0 needs Server 12.0). Get it from the Support Portal, then launch the InstallShield Wizard and select Test Data Service as a feature to install — it's part of the standard Tosca Server installation.

Also download the course's Base structure subset (.tsu file) and save it locally — it gets imported into your new Tosca project workspace in a later step.

After installation

The Tosca Server webpage launches automatically once setup completes, showing the Test Data Object Viewer icon — the single entry point to every TDS feature.

Accessing the Test Data Management page

The endpoint URL

To reach the Tosca Server webpage, enter http://<server address>:<port> in a browser. <server address> is the host name or IP (e.g. localhost), and <port> is whatever was set during installation (e.g. 81). The port only needs to be typed if it was changed from the default.

Reaching the repositories view

Clicking the Test Data Object Viewer icon navigates to the Test Data Management page, at http://<SERVER IP or localhost>:<port>/TestDataObjectViewer. This page lists every configured repository as a tile.

Creating a TDS repository

Create Repository dialog

On the Test Data Management page, click 'Create Repository' and define four properties.

TDS type names cannot contain any of these characters: / ? # [ ] @ ! $ & ' ( ) * + , ; = \ :

Clicking Save creates the database repository immediately — it's then ready to receive test records.

Connecting Tosca Commander to the repository

Step 1 — import the Base subset

Import the course's Base structure .tsu subset into your new project workspace. This brings in the TestDataService Configurations object you'll need next.

Step 2 — define the TestDataService Configurations

In the Configurations folder, open the TestDataService configurations and set two test configuration parameters: TestDataEndpoint (the http location to retrieve test records from) and TestDataRepository (which TDS repository to query).

Step 3 — drag and drop onto the right folders

The Configurations only take effect where they're attached. Drag and drop them onto your TestCase root folder and the relevant Execution List folder(s) — or, for convenience, onto the Component Folder if the same configuration should apply to every TestCase.

Best practice for real projects: if different TestCases need to talk to different repositories, don't apply one global configuration everywhere. Instead, drag empty configuration parameters onto the individual TestCase and Execution List folders that need them, and define each one's values separately.
