Installing Tosca Server with TDS

Version and prerequisites

Use matching Tosca and Tosca Server versions. Before installing, check administrator rights, the current system requirements and available service ports. Test Data Service is included in Tosca Server.

This guide uses current documentation rather than an unverified Academy installation video or downloadable exercise subset.

Configure the services

Install through the setup dialog or unattended mode, then configure the required services with Tricentis Service Configuration. Do not assume setup automatically opens every service page.

Accessing the Test Data Management page

Gateway landing page

Open http(s)://<DNS name of the Tosca Server machine>:<Tosca Gateway port>. In HTTPS setups use the certificate name and sign in with Tricentis User Administration credentials.

Repository access

Open Test Data Management from the server interface and select a repository tile. Repository access may depend on your user groups when authorization is enabled. A visible tile does not grant unrestricted administration rights.

Creating a TDS repository

Repository configuration

Create Repository defines a unique name and database settings. InMemory, SQLite, MSSQL and Oracle are supported; the available connection fields depend on the selected type.

A repository and a TDS type inside it are different objects. The Standard Modules document forbidden characters for TDS type names; do not present that rule as a verified repository-name rule.

Creation requires the relevant service and database permissions. Test the connection and verify the saved configuration before writing practice data.

Connecting Tosca Commander to the repository

Use the Standard subset

The documented prerequisites use Standard.tsu. In its Configurations folder, select TestDataService. Set TestDataEndpoint to the service location and TestDataRepository to the intended repository.

Assign the configuration

Drop the configuration onto an object that supports TCPs, such as a TestCase, a TestCase folder or a ComponentFolder. Check the execution-side scope too; placing a configuration under one branch does not configure unrelated branches.

Inheritance and overrides

Children inherit TCPs from their parent. A lower-level value can override an inherited value. Use a shared configuration for a shared environment and scoped values where repositories differ.

For HTTPS setups, follow the documented authentication procedure, including AuthenticationAccessKey and the Gateway endpoint. Where repository authorization is enabled, verify the required access. Endpoint and repository values alone are not an access grant.

Hands-on

Independent practice: create a disposable SQLite repository, assign its TestDataService configuration to a sample TestCase, and inspect the effective TCP values before running it. Academy exercises and a Tosca runtime execution have not been verified here.
