Performing Calculated Values

Calculated value field

A field computed AUTOMATICALLY from an expression or formula referencing other fields. The system owns the value; users cannot edit it directly and it recalculates as input fields change.

When the calculation runs

You configure when a calculated value recalculates — for example each time the underlying data changes — so the result stays current as users edit inputs. Calculated fields are typically presented as read-only because the system maintains them.

A calculated field is a spreadsheet cell with a formula: you don't type the total, you type the inputs and the cell recomputes itself the moment any input changes.

Calculations with Decision Tables

Decision Table

A rule returning a value based on conditions arranged in rows. It evaluates rows TOP TO BOTTOM and returns the first matching row's result, with an 'otherwise' default for non-matching cases.

When to use one for calculations

Use a Decision Table to compute a value that depends on combinations of conditions — for example a shipping cost by region and weight, or a discount tier by order total — instead of writing complex nested logic.

A Decision Table is a pricing chart on the wall: the clerk scans rows from the top and charges the rate from the first row your order matches — no hand calculation needed.

Setting Default Property Values

Default value

A starting value pre-populated into a field when a Case is created, so users don't have to enter commonly-used values (e.g., default Country = 'USA', default Date = today). This reduces Case processing time and improves consistency.

Business value

Defaults speed data entry, reduce errors, and standardize commonly-used values across Cases — improving efficiency and the user experience.

Default values are the pre-filled fields on a web form (country already set to your locale): you only change them when needed, saving time on the common case.

Manipulating Application Data with Data Transforms

Data Transform

A rule that manipulates data — it SETS, COPIES, and TRANSFORMS values between pages/fields. Data Transforms ensure values are consistent between Views and between related (parent/child) Cases without manual re-entry.

Common uses

Common Data Transform use cases:

  • Initialize/seed values on Case creation
  • Copy data from one Case or page to another (e.g., copy billing address to shipping address)
  • Keep parent and child Case data synchronized

A Data Transform is a mail-merge macro: it takes values from one place and writes them consistently into others, so you never retype the same data twice.

Validation of Data (Business Logic Validation)

Business logic validation

Rules that check entered data against business requirements before the Case proceeds — ensuring accuracy and completeness. They block Case advancement until all conditions are satisfied.

When validation helps

Use business-logic validation whenever invalid or inconsistent data could cause downstream errors or rework — it enforces data integrity at the point of entry rather than failing later.

Validation is the bouncer at the door: it checks each value against the rules and blocks bad data from entering the Case, preventing problems deeper inside the workflow.
