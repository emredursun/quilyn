Assignment Routing

Assignment routing

Routing sends each Assignment to the best-available user so work reaches the right person/team at the right time. It orchestrates workflow across functional teams and improves operational efficiency and customer experience.

Worklist vs. Work Queue

Two types of Assignment containers:

  • WORKLIST — Assignments routed to a SPECIFIC user (operator) to work individually
  • WORK QUEUE — a SHARED queue for a team/Work Group; any qualified member can pull and complete the work

Routing options

In App Studio an Assignment Step can route to the current user, a specific named user, or a Work Queue. Routing decisions depend on whether work is personal or shared across a team.

A Worklist is your personal inbox (addressed to you); a Work Queue is a shared team inbox (anyone on the team can grab the next item). Routing is the mailroom deciding which inbox each task goes to.

Cross-functional Work Groups

Work Group

A Work Group associates a set of users and Work Queues under a manager, organizing who collaborates on work. Cross-functional Work Groups bring members from different teams together to complete work that spans functions, improving process efficiency.

A Work Group is a project team roster; a cross-functional Work Group is a task force pulled from multiple departments so the whole Case can be handled without hand-off delays.

Approving Work

Approval Step

An approval routes a Case to a user to approve or reject; the outcome determines the path (approved continues the primary path; rejected branches to rework or rejection handling). Approvals are a key OOTB workflow-automation feature.

Single vs. Cascading approval

Two approval scopes:

  • SINGLE — one approver only
  • CASCADING — MULTIPLE approvers in sequence (e.g., up a reporting hierarchy or via an authority matrix for higher amounts)

Single approval is one signature on the form; cascading approval is a signature chain that climbs the org chart until the amount is fully authorized.

Managing Work Deadlines: SLAs and Urgency

Service-Level Agreement (SLA)

An SLA defines time targets for completing an Assignment or Case. App Studio exposes a GOAL interval and a DEADLINE interval (Dev Studio adds advanced options). In Dev Studio terms, a goal/deadline IS the Service-Level Agreement rule.

Goal vs. Deadline

Two SLA time thresholds on an Assignment or Case:

  • GOAL — the EARLIER target; work SHOULD be completed by this time
  • DEADLINE — the LATER limit; work MUST be completed by this time

Case Urgency

A numeric priority value that ensures work is completed on time. Urgency starts at an initial value and increases automatically as the SLA's Goal and Deadline thresholds pass.

Goal vs. deadline is a 'please reply by Friday' (goal) versus 'absolutely no later than Monday' (deadline). Urgency is the volume knob — it gets louder at the goal and louder still at the deadline so the task can't be ignored.
