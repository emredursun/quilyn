Pega Blueprint Overview

Pega Blueprint

Blueprint combines templates and generative AI to propose application workflows. Stakeholders review and refine the proposed design before implementation.

Standalone SaaS tool

Blueprint is SaaS, separate from a Pega Platform development instance and Operator login. Follow the SaaS service’s sign-in and collaboration access requirements.

Augments, not replaces

Blueprint helps teams start design; the implementation team uses App Studio and Dev Studio after import to configure, test and extend the application.

Blueprint is a collaborative draft plan. Review it with stakeholders, then use the import file as a starting point for implementation. The draft does not guarantee production readiness or a fixed delivery time.

Generating a Pega Blueprint

Describe in business terms

Choose industry, sub-industry and department, or Other with a detailed functional description. Select a template or GenAI, provide organization and language details, and add supporting requirements assets.

Generate and modify

Review and edit Case Types, Primary/Alternate Stages, Processes and Steps. Use Notes to capture routing, SLA and conditions; Preview my app helps review flow. Check data field types, descriptions, primary fields, single/multiple values and user-input/calculated sources.

Best-practice templates

Templates provide a starting design that still needs review. Validate Personas, access needs, Channels and release effort, then check the summary for workflow, Data Model and integration completeness.

Generating a Blueprint is like giving a skilled drafter a paragraph about your business: they hand back a labeled floor plan (Case Types, Life Cycles, Data Model, Personas) that you then mark up together until it's right.

Importing a Pega Blueprint into Pega Platform

Export and import

Download the technical .blueprint file and a PDF reference. In App Studio, create an application with Build from a Blueprint, upload the technical file and review its details and built-on stack. An existing application must be saved as a template to use it through this New Application wizard.

Who imports it

The authorized implementation team performs import and configuration. Project responsibilities can assign an LSA; the source does not require an exclusive LSA permission.

What import creates (and the exception)

In the documented new-application workflow, created assets except Access Roles go into a Branch. The exception concerns branch placement, not whether Access Roles are created. Base Rulesets are locked and merges require the appropriate password.

PremBridge not required

Pega GenAI PremBridge is NOT required to import Pega Blueprints into a new or existing application.

Think of the Branch as a review area for generated rules. Access Roles are placed outside it; their location alone does not tell you whether they were created.

Build, inherit and reuse choices

Inheritance creates a new Case Type or data object based on one in the built-on application. Reusing a data object links to the existing built-on object without its own class in the new app. Skip a proposed asset when it does not fit the business design.

Validate after import

Check existing-app overlaps, merge the appropriate branch Rules, and refine Decision shapes, Flow Actions, locking and the Data Model. Review database mapping, Data Pages and properties, and test approvals, alternate paths, automation and child Cases.

Using Blueprint for an Industry App (Customer Service for Insurance)

Industry templates

In the insurance example, start from the Customer Service template and add a golf-cart Case. Inherit existing Case Types and build the new one. Add a weather Step and field; after import, change the field to Picklist and add it to a View. Configure data, integrations, Channels and users, then simulate an interaction.

Industry templates are pre-fab housing kits: instead of designing an insurance service app from scratch, you start from a kit tuned for that industry and customize the rooms (Case Types/workflows).
