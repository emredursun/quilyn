Generative AI — Design-Time Tools

Pega GenAI

A suite of generative AI-powered features integrated across Pega Platform, available beginning with Pega Infinity '23. It helps developers, learners, and users build applications, enhance learning, improve operational efficiency, and stay aligned with best practices.

Pega Blueprint

Blueprint is a separate SaaS application-design tool. A business description leads to proposals for workflow, data and Personas that the team reviews before implementation. A proposal is not proof of production readiness or a guaranteed delivery time.

Pega GenAI Autopilot

Autopilot assists application authors with suggestions for workflow, data and Personas. The reviewed curriculum describes it as a design-time accelerator; speed improvements depend on the actual work and are not a measured guarantee for every project.

Pega GenAI Connect

Lets you develop custom Pega GenAI-powered capabilities using the Pega GenAI gateway; an add-on compatible with Pega Platform, Customer Service, or Sales Automation.

Pega GenAI Coach

Provides expert advice and feedback on END-USER tasks at application RUNTIME — ideal for task-specific guidance relevant to a Pega Case.

The suite's introduction in Infinity '23 does not date every feature. Availability, configuration, licensing, and collaboration requirements vary by feature and release; check the target release's documentation.

Generative AI — Run-Time Tools and Custom AI

Pega GenAI Agent and Tool Rules

Configured Agents support automated Case actions and runtime conversations. Tool Rules describe available actions and their constraints; permissions, review and configuration are still required.

Pega GenAI Knowledge Buddy

Gives employees, agents, and sellers instant answers and real-time guidance via a conversation interface, combining Pega GenAI with the organization's own procedural documents and knowledge bases.

Search Assistant & OpenAI search

The reviewed topic describes Search Assistant as Community search backed by Knowledge Buddy. Its historical documentation-search example uses a trailing question mark for AI answers; that example does not establish the only supported trigger in every later interface.

Think of Pega GenAI as a crew: Blueprint is the architect (designs before build), Autopilot is the master builder's assistant (helps at design time), Coach and Agents are the on-site supervisors (help at run time), and Knowledge Buddy/Search Assistant are the reference librarians (answer questions on demand).

Pega GenAI Autopilot at Design Time

What Autopilot accelerates

Autopilot delivers real-time, context-aware guidance and task prioritization during development. For a loan app, it suggests application components including Case Types, fields in the Data Model, and Personas — and developers can review and modify any recommendation before generating it.

The Autopilot workflow

When you create a Case Type, Autopilot suggests names, a workflow, data objects, and Personas — accelerating design-time setup with AI-generated proposals the architect reviews and accepts.

Human-in-the-loop responsibility

Review generated recommendations against the application requirements before accepting them. AI output can contain mistakes; the topic explicitly calls for review.

Autopilot is a GPS co-pilot: it proposes a fast route (Case Types, fields, Personas, sample data), but you keep your hands on the wheel — reviewing and modifying every suggestion before committing.

Pega Blueprint (within the GenAI suite)

Blueprint as a SaaS design tool

Blueprint operates independently of a Pega Platform instance and supplements the studios. Do not confuse independence from a Platform instance with unrestricted anonymous access: follow the current Blueprint account, invitation and collaboration requirements.

What Blueprint proposes

From a business-terms description, Blueprint proposes Case Types, Case Life Cycles, Data Models, data objects, and Personas, plus best-practice application templates, enabling quick design edits to fit requirements.

Blueprint proposes a design that the team can refine and import as a starting point. Imported assets still need review, configuration and testing.

GenAI Connect Step

Connect Generative AI automation Step

A Step (available since Pega Infinity '24) that calls a configured GenAI Connect Rule from App Studio to send a prompt to an LLM and receive a response in one of three structures.

Three response structures

GenAI response types and their Data Model mapping:

  • Structured-Single: one object mapped to a Data Model field
  • Structured-List: multiple objects mapped to a page list
  • Unstructured: raw text mapped to a Text (paragraph) field

Target field requirement

You must identify a target field to write the response into, and add that target field to the application UI so the response can be displayed to the user.

A Connect Step is like sending a structured form letter to an AI clerk: your Prompt is the request, you specify how the reply should be shaped (single, list, or freeform), and you reserve a mailbox (target field) on the UI to receive it.

Pega GenAI Agent and Tool Rules

Agents

Configurable AI assistants that automate Case processing and provide run-time guidance. Governed by Tool Rules, they can run automations, start Cases, call other agents, and converse with users.

Guardrails via Tool Rules

Detailed tool descriptions and constraints help guide agent actions. Runtime conversations can include extraction from uploaded documents. These features support the workflow but do not guarantee correct responses or replace access controls.

An Agent is a capable digital teammate; Tool Rules are its job description and rulebook — defining exactly what it may do and the guardrails it must respect.

Generate and review a Case Type

Choose the Case Type

In App Studio, start Case Type creation. Autopilot proposes names from the application name and metadata; choose a proposal or enter your own name.

Review lifecycle and fields

Select Use Autopilot to suggest a Life Cycle and Data Model. Review and edit the proposed Stages and Steps, then click Next to review fields. Each field has a Name, Type and technical ID; edit, add or remove fields as needed.

Create and inspect

After reviewing the proposals, Submit creates the Case Type. Inspect Workflow and Data model. Embedded Data and Data reference proposals can also create associated data objects; review those relationships.

Generate Personas

Review the proposed users

The Persona topic uses Users > User management in App Studio. Autopilot proposes names and descriptions from application metadata. Choose a suggestion or enter a custom Persona name.

Associate with the workflow

After creating the Persona, add it in Personas & Channels in the Case Life Cycle. This models user roles in the workflow; it is not proof that a specific account has all required runtime permissions.

Generate sample records and fill forms

Sample data-object records

Select a data object and its Records tab, then Generate sample records with Autopilot. Review the requested record count and the generated field values. These samples can support testing before an external source integration exists.

Form data affects the Case

While testing a Case, Fill form with AI populates the form fields. Those values become part of the Case data used by the application. Inspect them before continuing; filling a form is different from generating data-object records.
