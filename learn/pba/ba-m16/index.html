Identifying Portals and Landing Pages

Portal

A portal is the user's workspace — the overall interface a user sees when they log in. Tailoring portals by CHANNEL and PERSONA lets each type of user perform their job efficiently with the right tools and information front-and-center.

Business benefit of portals

Portals deliver a role-appropriate, branded, productive experience: each Persona gets a workspace suited to their tasks, improving efficiency and the user experience while keeping branding consistent.

Elements of a portal

A portal is composed of regions such as a HEADER (logo, search, utilities), NAVIGATION (menu to move between areas), and LANDING PAGES / dashboards that present content and work in the main area.

Landing pages

Landing pages are configurable pages within a portal (e.g., dashboards, reports, custom content). You can UPDATE a portal by adding new landing pages and corresponding navigation entries so users reach the information they need.

A portal is a customized cockpit: the header is the dashboard frame, the navigation is the control panel, and landing pages are the gauges/screens. Each role (pilot vs. engineer) gets a cockpit laid out for their job.

User Interface Controls and Presentation

Control styling at runtime

Style formats and conditional formatting change how a control is displayed at run time — for example, highlighting overdue values — without altering the underlying field value.

Presentation vs. data

Styling is separate from stored data:

  • PRESENTATION (styling) — affects only HOW information is DISPLAYED; does not change the stored value
  • DATA (value) — the actual stored information, independent of visual appearance

Styling a control is like highlighting text in a document: the words (data) are unchanged, but the highlight (style) draws the reader's eye to what matters.

Dynamic Functionality on UI Elements

Dynamic visibility

You can control the VISIBILITY of fields and UI elements dynamically — showing or hiding them based on conditions (for example, show the 'Reason for rejection' field only when the decision is 'Rejected'). This tailors the View to the context.

Attributes used to dynamically display information

Visibility and dynamic behavior are driven by conditions/attributes such as 'visible when' a condition (When rule) is true, or comparisons against field values — so the UI adapts to the data and the user's situation in real time.

Dynamic visibility is a smart form that reveals follow-up questions only when relevant: tick 'Other' and a text box appears; otherwise it stays hidden — the form adapts to your answers.
