Low-code Application Development

Low-code development

Products and cloud services that use visual, declarative techniques instead of programming. As you manipulate the visual model, tools generate the underlying code — Pega has done this for 30 years.

Value of low-code

Low-code bridges business stakeholders and skilled developers with a common visual language, enabling teams to deliver faster, collaborate better, and focus on business logic rather than code.

Omnichannel reach

The same Pega application can serve as a web page, mobile app, or chatbot; data can arrive via email or a robot. Organizations unify all channels without maintaining disparate code lines.

Low-code AND professional developers

Visual, end-to-end tools make everyone more productive. Citizen developers create application code; experienced developers extend robust applications more rapidly, hide implementation, and build patterns once to reuse many times across the ecosystem.

LEGO vs. injection-molding: traditional coding molds every brick from raw resin each time; low-code hands you pre-made, snap-together bricks (visual components). You assemble robust structures fast — and an expert can still craft a custom brick when the kit doesn't have one.

The Four Studios

App Studio

A low-code authoring space providing CORE features: Case design, data management, and user experience (UI). Users: citizen developers plus technical staff — application developers, front-end developers, data engineers, business analysts, and System Architects. The place to get applications operating quickly.

Dev Studio

A low-code authoring space with ADVANCED features. Technical users: full-stack developers, System Architects, and database/security administrators. Used for complex Rule configuration, security/access control, reuse management, and performance.

Prediction Studio

An ANALYTICS space for data scientists and business decision-makers, providing features to build machine-learning models for adaptive, predictive, and text analytics. Access requires pxPredictionStudio among the Portals on the user's access group.

Admin Studio

A software ADMINISTRATION space managed by IT for system administration — runtime information and configuration options for monitoring and debugging system resources.

Four workbenches in one workshop: App Studio is the assembly bench (build fast), Dev Studio is the precision-tooling bench (deep config), Prediction Studio is the R&D lab (models), Admin Studio is the control room (monitoring). Pick the bench that matches the task and your expertise.

Studio Navigation

Three areas of every studio

Every studio has three regions:

  • A Header (menus and the upper-left studio-switcher)
  • A Navigation pane (explorers like Case Type and Data)
  • An Authoring space where you configure behavior

Depending on screen size, icons replace text-based menu options; hover over an icon to view the menu name.

Inside App Studio

Support for agile development

App Studio supports agile best practices and REAL-TIME UI design while processing work. A team testing an online-shopping UI can add fields and change controls (e.g., drop-downs) live — ideal for stakeholder reviews where feedback is implemented in real time.

Application profile

Captures and presents user stories, bugs, and feedback items to support agile best practices and collaboration across technical and business members. Provides traceability from objectives to development tasks to implementation.

Rules

Instructions that govern application behavior (like the rules of chess govern the pieces). As you build visually, Pega auto-generates Rules in the background using the SAME names you choose — which is why business-friendly names matter.

Layers & Rulesets

Rules are organized into reusable Layers; each Layer is a unique application built on one or more others. Rulesets store, manage, and identify Rules that can be shared and reused as a whole unit.

Application Layers Widget & OOTB architectures

The App Studio overview's Application Layers Widget visualizes your Rulesets and identifies the application type. Two OOTB architectures: Constellation architecture (Constellation Ruleset, new View-based UI) and Traditional UI architecture (Theme Cosmos Ruleset, Section-based UI).

Dev Studio: Co-development, Reuse, and Naming

Domain vs. Implementation experts

Two groups defined by Pega for co-development:

  • DOMAIN experts (Business Analysts, Citizen Developers, front-end developers) — provide process/user insight; primarily work in App Studio
  • IMPLEMENTATION experts (System Architects, full-stack/DB/security admins) — handle complex configuration; primarily work in Dev Studio

Co-development

Business and IT work together: a Business Analyst designs Views in App Studio while a System Architect adds advanced logic in Dev Studio, combining domain insight with implementation expertise.

Promote reuse by extending Rule scope

In Dev Studio, developers access all layers and extend a rule's scope from one Case Type to an application, division, or whole organization, creating a reusable library that cuts future development time.

Advanced SLA options in Dev Studio

Beyond App Studio's basic goal/deadline, Dev Studio exposes:

  • Initialization behavior (custom initial urgency, delayed timer start)
  • Variable interval length (programmatic durations per Case)
  • Account-for-business-days (exclude holidays/weekends)
  • Additional escalation actions (reassign a task or resolve a Case)

Naming differences are a passport stamp: the SAME record crosses the border between studios but gets a different name. A 'Field' in App Studio is a 'Property' in Dev Studio — same traveler, different stamp.

Integrating with External Applications

Integration connectors

Pega supports many integration standards and protocols so you focus on business requirements. A standard API connector exchanges data in real time when both systems support a common protocol.

Robotic Process Automation (RPA)

Used when no other integration is feasible — typically legacy systems with no usable API. A robot interacts with the system's UI to perform the same steps a person would, but far faster.

Attended RPA

Automation that works ALONGSIDE a human in the process, in real time. Example: a CSR triggers a robot mid-call to update an address by driving the legacy system's UI while the customer waits.

Unattended RPA

The request is placed in a QUEUE for later background processing. Advantages: optimizes system resources, reduces peak loads, and lets the CSR keep serving the customer instead of waiting for the update to finish.

Pega Robot Manager

A control-tower application that lets you monitor and schedule RPA robots and provides performance analytics for all robots.

Connector vs. RPA: a connector is a direct phone line between two systems that speak the same language; RPA hires a very fast assistant to physically type into an old system's screen because that system never got a phone line (API).
