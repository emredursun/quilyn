Personas, Operators, and Work Access

User vs. Persona

Two levels of identity in Pega access control:

  • USER (operator) — an individual person who interacts with the application
  • PERSONA — a CATEGORY (role) grouping users with similar access needs, goals, and channels

Operator record (Operator ID)

An Operator ID identifies an individual with profile, skills, substitutions and access context. Authentication may use external SSO/token services; an operator profile is not a reason to share accounts or assume plaintext passwords are stored there.

Access Group

An Access Group supplies application/ruleset, portal, work-pool and Access Role context. An operator can have multiple groups but one is active at a time. Creating a Persona generates a corresponding group; the user-needs Persona and technical permissions group are not identical.

Access Role

Defines WHAT a user is permitted to do — the permissions to classes and actions (role-based access control, RBAC). Access Roles are granted via the Access Group.

Think of a building: the Persona is the job title (e.g., 'Nurse'), the Operator record is your personal employee badge, the Access Group is the badge's programmed profile (which building/app and which doors), and Access Roles are the specific doors (permissions) the badge can open.

Authentication and Authorization

Authentication

Authentication verifies an identity using the configured credentials or SSO/token/MFA service. In the signed-in flow described here, identity verification precedes authorization of protected operations.

Authorization

Authorization determines permitted runtime data/actions and design-time rule/tool access. Roles/groups support RBAC; Pega also describes complementary ABAC object/user attribute checks and CBAC personal-data request handling.

Authentication is showing your passport at the airport (proving who you are); authorization is your boarding pass deciding which gate/seat you may enter (what you're allowed to do). You authenticate first, then you're authorized.

Complementary access controls

RBAC organizes role permissions. ABAC considers user and object attributes. CBAC concerns personal-data access/change/removal requests. Selecting a Persona or routing work does not replace these configured controls.
