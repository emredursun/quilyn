Release Management with Pega (CI/CD)

DevOps & CI/CD

Pega Platform uses DevOps best practices — Continuous Integration and Continuous Delivery (CI/CD) — to quickly and reliably move application changes from development, through testing, to deployment on the production system.

Continuous Integration (CI)

Frequent integration with automated verification exposes issues earlier; CI alone does not guarantee a consistently working application or adequate test coverage.

Continuous Delivery (CD)

Uses repeatable testing and staged promotion to keep changes ready for release. Production deployment may still require approval; Continuous Deployment additionally automates shipping validated changes.

Pega Deployment Manager

Deployment Manager orchestrates configured branch merging, packaging, testing and environment promotion. Install and integrate it with candidate environments and the orchestrator before publishing; a diagram or selected tool alone does not create an operational pipeline.

The CI/CD pipeline is an automated assembly line for software: changes enter at development and move station-by-station (build, test, stage, production) with automatic quality checks, instead of being hand-carried between environments.

Release Management Best Practices

Branch-based parallel development

Teams develop features in Branches and merge them into the target application Ruleset when stable, conflict-free, and approved — keeping parallel work isolated until ready (ties back to Branches from earlier modules).

Small iterations and continuous quality checks

Deliver small changes, continuously test, and use the Application Quality dashboard to monitor configuration quality. Review/versioning policies depend on the application architecture; testing must occur before sharing as well as after integration.

Automated testing & governance

Use automated tests (e.g., unit/scenario tests) within the pipeline and enforce governance/approval gates so only validated changes promote toward production.

Release guardrails combine isolated changes with appropriate tests, review and promotion checks.

Application Deployment with Pega Cloud

Pega Cloud

Managed Pega Cloud supplies infrastructure and operational services under a shared responsibility model. Clients retain application monitoring/performance, business-data lifecycle and user identity/access responsibilities; managed hosting is not the transfer of every operational obligation.

Pega Cloud Choice

Offers deployment models suited to organizational needs. Pega Cloud provides managed operations; client-managed cloud leaves infrastructure operations with the client and provides Pega platform support. Responsibility depends on the selected model.

Choosing a deployment model is like choosing serviced accommodation or managing your own property: the choice changes who handles daily operations.
