Processes and Process Flows

Process

A building block of the Case Life Cycle (within a Stage) that groups a series of Steps users complete. In App Studio you design Processes visually as part of the Life Cycle.

Process Flow

The underlying Flow Rule that Pega generates for a Process — the detailed flow diagram (seen in the Dev Studio process modeler) made of shapes and connectors that defines exactly how the Process executes.

The Process is the chapter title in the App Studio table of contents; the Process Flow is the detailed storyboard (the Flow Rule) showing every shape and connector behind that chapter.

Automation Shapes in the Process Flow

Automation shapes

Shapes in the Process Flow that execute system actions WITHOUT user interaction — yellow-coded steps such as Send Email, Create PDF, Create Case, Wait, and Change Stage.

Automation shapes are the robots on the assembly line: they perform set tasks (send, create, wait, change stage) the moment the Case reaches them, with no human touch.

Automating Decisions in the Process Flow

Decision shapes

Shapes that branch the Process Flow along different paths based on evaluating conditions, so the Case follows the correct route automatically rather than a single fixed path.

Two-way vs. multi-way decisions

Choose the decision type based on outcome count:

  • Two-way (true/false) branch → use a When Condition
  • Multi-way (multiple outcomes) → use a Decision Table or Decision Tree

A When-condition decision is a fork in the road (left/right = true/false); a Decision Table is a multi-lane interchange routing each car to the correct exit based on several inputs.

Conditional Execution: The When Condition Rule

When Condition Rule

A rule that evaluates a Boolean (true/false) statement comparing field values. The result drives conditional logic — skipping Stages, Processes, or controlling which Steps execute.

The three elements of a When Condition

Every When Condition has three parts:

  • (1) an INPUT VALUE (a field or another condition)
  • (2) a COMPARATOR (equals, greater than, contains, etc.)
  • (3) a VALUE to compare against

App Studio vs. Dev Studio When Conditions

Scope of When Conditions differs by studio:

  • APP STUDIO — single context within one Case Type
  • DEV STUDIO — reusable; available across the entire application Ruleset stack

A When Condition is an 'IF' sentence with three slots: [input] [comparator] [value] — e.g., [credit score] [is greater than] [700]. Fill the three slots and Pega returns true or false to steer the Case.

Skipping a Stage or Process

Skip with a When Condition

A Stage or Process can be configured to skip when a When Condition evaluates to true, or to start only when the condition is true — enabling conditional path control.

Skipping is an express lane: if the condition says 'this traveler has no checked bags' (When = true), the Case skips the baggage Stage entirely and moves on.

Optional Actions in the Workflow

Optional actions

Actions a user can take OUTSIDE the sequential Step flow, available on demand from the Case actions menu rather than required at a specific point in the process.

Case-wide vs. Stage-wide

Scope of an optional action:

  • CASE-WIDE — available throughout the ENTIRE Case Life Cycle
  • STAGE-WIDE — available only while the Case is in a specific Stage

Optional actions are the menu's à la carte items: not part of the set sequence of courses, but available to order whenever appropriate — some all evening (Case-wide), some only during a particular course (Stage-wide).
