The problem self-healing addresses

Controls change; tests break

An application under active development changes its controls constantly — an id gets renamed, a class is restructured, a button moves into a different container. Nothing about the business behaviour changed, but the automation can no longer find the control and the TestCase fails. Investigating and repairing these false failures is one of the biggest ongoing maintenance costs in test automation.

Self-healing Mode

If ordinary identification fails, enabled self-healing attempts an alternative based on stored properties. A suitable match allows the current action to continue; no match, a wrong match or a failed later assertion can still make the test fail. Review healed actions before accepting their results.

Successful identification recovery is not a guarantee that the entire TestCase passes. Check the execution result and healed object details; later actions and assertions still apply.

Turning it on: the SelfHealing TCP

A test configuration parameter, not a checkbox

Self-healing is activated by creating a test configuration parameter named SelfHealing. Because it is a TCP, it inherits the usual scoping rules — set it high in the folder structure to apply broadly, or on a specific TestCase to limit it.

SelfHealingWeightThreshold

For Weighted mode, SelfHealingWeightThreshold defaults to 0.75. Candidate combinations below the accumulated-weight cutoff are ignored; this is not a calibrated probability that a match is correct. Use the decimal separator required by regional settings.

Self-Healing Properties

Where the technical data lives

Self-Healing Properties are the technical attributes of a control that give Tosca something to match against when the primary identification fails. They sit on the Self-Healing Properties tab of the ModuleAttribute — one level deeper than the identification you normally work with.

They are created for you

Tosca adds these properties automatically when a Module is created through XScan, Tosca Rescan, Salesforce Scan, or the Tricentis Automation Recording Assistant. You do not have to author them by hand — though you can edit, delete, or add properties manually after scanning if the automatic set is not right.

Properties can be collected by ARA, but rescan is required to calculate weights for Weighted mode. Newly added properties default to Weight -1 and are disregarded by weighting until recalculated through rescan.

Seeing and keeping the results

Spotting a self-healed run

An icon on ExecutionEntries and the ExecutionLog Detail column identify healed objects. Inspect those details alongside assertions and the final result instead of interpreting every healed run as a clean pass.

Apply Self-Healing properties

Review the replacement control and its assertions first. If the change is correct, use Apply Self-Healing properties on the ExecutionLog to update the Module. This commits identification changes; it does not prove the chosen control or business behavior is correct.

Self-healing can affect execution performance. Investigate repeated recovery and validate the target before applying its properties; do not accept a replacement merely because execution continued.

Which engines support it

UIA is included in the documented support list. Excel, PDF and Mail are not listed for this feature; do not infer their resilience merely from enabling the SelfHealing TCP.
