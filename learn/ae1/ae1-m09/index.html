Image-Based Test Automation (IBTA)

Identifying by what it looks like

XScan can pair a selected control with one or more screenshot identifiers. Image matching provides appearance-based identification when that fits the target, but still requires a visible, sufficiently distinctive identifier.

How to create one

In XScan Advanced View, select the control and choose ADVANCED IDENTIFICATION → IMAGE. Add an identifier image, capture its region and inspect uniqueness. Set Accuracy and choose Method Fullscreen, Controlbased or Auto as appropriate.

Evaluate properties, index and anchors alongside image identification. The current public image guide describes alternatives rather than prescribing a universal five-step order. Image matching is sensitive to design, resolution, color depth and scrolling; structural identification can also fail after UI changes.

Making image identification as reliable as it can be

Use more than one screenshot

Capture necessary variants when a control’s appearance changes. Tosca tries identifiers sequentially until it finds a match, so additional images increase execution time. Limit them to what is needed, and verify that each identifier selects the intended control.

What still breaks it

Keep scan and execution display settings consistent. Multiple identifiers can cover known variants; they do not guarantee tolerance of arbitrary redesigns, scaling or rendering changes. A non-unique identifier remains unreliable even if Module creation is permitted.

The other Advanced Identification method: Anchor

Identify by anchor

In XScan Advanced View, select the target and choose ADVANCED IDENTIFICATION → ANCHOR. Assign a reference control from the tree, screen or Auto Select. This establishes an anchor context for locating the target; it is not the PDF Scan’s text/image/same-page rule set.

PDF and XScan anchors share the idea of a reference but have different documented identification mechanisms. Do not transfer the PDF-specific three conditions into a universal XScan rule.

Where this sits in the escalation path

Self-healing is an execution-time recovery feature for documented supported engines. The support list alone does not establish that every identification mode is covered. Validate the actual control/engine combination; do not assume that it will repair an image mismatch.

Original example: standalone image control and OCR

Two workflows, not two names for the same step

XScan IMAGE identification pairs an already selected control with identifier screenshots. The original lesson also creates a standalone image-based control from a Module folder. Its first capture defines the control region; at least one identifying image is then needed for locating it. A surrounding identifying region describes relative position, while using the control’s own image supports appearance-based location. Validate the actual result rather than assuming either choice is always reliable.

The original theory suggests F12 when clicking the capture control would dismiss a dropdown, shows 95 as its source-era default accuracy, and warns about zoom, color and resolution. Treat these as course-version details. Broadening accuracy can match unintended regions; it does not fix OCR language/rendering or missing text.
