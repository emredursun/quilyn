Why mail automation matters

Mail as part of the business process

Very few end-to-end processes finish inside the application. Register an account and a confirmation email arrives; place an order and an order confirmation follows; reset a password and the whole flow depends on a link that only exists in an inbox. If the test stops at the web page, the part the customer actually receives goes untested.

Mail Engine 3.0

Mail Engine 3.0 is part of the standard Tosca installation. Current Standard subset location: Standard modules → Engines → Mail.

Connecting to the mail server

Connect to Mail Server

Connect to Mail Server defines a named server configuration. Network use occurs during sending or receiving, so this configuration step alone does not prove delivery or retrieval.

Connect to Exchange Server

Connect to Exchange Server configures an EWS endpoint. Current Authentication Type values are Basic (legacy) and OAuth, selected with ActionMode Select. OAuth uses App Id and Tenant Id from a Microsoft identity registration; token-acquisition failure can fail this step, unlike the legacy configuration path.

OAuth 2.0 for Exchange Online / Microsoft 365

Connect to Cloud Mail Server has a separate Microsoft Office 365 integration with Tenant Id, Application Id, Client Secret and Mailbox. Its documented prerequisites include a registered Entra application and Graph mail permissions. Google Workspace uses a service-account JSON key and domain-wide delegation. These integrations are not interchangeable with a generic SMTP server or a personal Gmail login.

Use the integration supported by your installed Tosca version and the tenant’s approved authentication configuration. Exchange Online EWS disablement starts in October 2026 and completes in April 2027; an EWS OAuth token does not guarantee continued endpoint availability. Check current provider guidance before running an exercise.

Real-world setup notes: Gmail and corporate mailboxes

An EWS endpoint is not a Gmail IMAP or SMTP endpoint. Select the provider-compatible connection Module rather than substituting a Gmail address in Exchange Web Services Url.

Provider server settings

Google documents imap.gmail.com:993 with SSL and smtp.gmail.com:587 with TLS (or 465 with SSL). Configure receiving and sending separately with their corresponding protocols and security enabled; successful use still depends on account policy and supported authentication.

Use unique Connection Name values for separately configured SMTP and IMAP resources so later steps reference the intended protocol. Do not depend on an undocumented last-definition-wins behavior.

Authentication failures depend on the protocol, tenant and provider. A personal Outlook.com or Gmail account is not a universal bypass. Check approved account access, permissions and the installed Module’s requirements.

Sending mail

Send Mail

The Send Mail Module sends — or replies to — an email message via SMTP. Typical uses in a test are triggering an inbound process (a system that acts on incoming mail), or generating a message the test will later verify was received and correctly handled.

Receiving mail: Simple vs Expert

Receive Mail Simple

Checks whether you received one specific, single email. This is the right choice for the common case: 'after registering, did the confirmation email arrive?' One expected message, one check.

Receive Mail Expert

Receive Mail Expert searches a set of messages and exposes a ResultCount plus individual Mail nodes. Use it when the test needs to assert the number of matches or inspect multiple results.

The 2026.1 Module reference states POP3/IMAP for both receive Modules, even though the engine overview also lists EWS. Simple can filter and verify a single message; Expert adds explicit result count and multiple-result handling. Inspect the installed Module and cloud integration guidance for other connections.
