Two different ways to reach Excel

Excel Standard Modules (file-level, background)

Excel Standard Modules work with a workbook in the background without steering its visible window. Prefer data-level operations when the test concerns workbook data; inspect current engine prerequisites, including the executing user’s valid Office license.

Excel UI Engine 3.0 (application-level)

The Excel UI Engine 3.0 scans and steers the Microsoft Excel user interface itself — the main application window, its dialogs, and the worksheets with embedded controls currently loaded by the application. Use it when the thing under test genuinely is the Excel UI: a dialog that must appear, a ribbon interaction, an embedded control a user would click.

The choice matters for reliability. If you only need a cell's value, do not open Excel's window to read it — use the Standard Modules. Drive the UI only when the UI is the thing being tested.

The mandatory open/close pattern

Open Excel Workbook

The mandatory first step of any Excel Standard Module sequence. It opens the workbook in the background and can handle password-protected files and read-only access. Nothing else in the Excel Module family works until the workbook has been opened.

Close/Save Excel Workbook

Close/Save Excel Workbook supports Save, Save & Close, or Close. Save Path controls the destination; Save As Type only applies with Save Path, and its type must match the file extension. Choose an operation that saves changes when required and closes resources at the end.

Leaving a workbook open can retain resources or a file lock, and unsaved changes may be lost. Close deliberately and investigate actual save/lock errors; later failure is not guaranteed solely by a missing Close step.

Working with data: Ranges

Define Excel Range

Define a named range for manipulation. Choose Explicit start/end cells or Used Range; the selected range affects row/column counts and indexing.

Manipulate Excel Range

The workhorse Module. It reads and writes cell data, and it also reaches the technical properties of cells — formulas, formatting, colors, fonts, and comments. Because it supports verification as well as input, this is the Module that satisfies the course objective 'verify Microsoft Excel cell special properties': you are not just checking the displayed value, you are checking that the underlying formula, the fill colour, or the font is what it should be.

Clear Excel Range

Removes content from a range — and selectively, not just the values: formatting, notes, comments, hyperlinks, or outlines can each be cleared. Useful for resetting a sheet between test runs.

Worksheet-level structure has its own Modules: Create Excel Worksheet (add a sheet, positioned first, last, or at a specific index), Delete Excel Worksheet, and Update Excel Worksheet (rename a sheet and move it within the workbook).

Technical cell properties include Formula and BackgroundColor. NumberFormat syntax can vary with the Office language setting; a correct displayed value does not prove the formula is correct.

Comparing workbooks and running macros

Excel 1:1 File Compare

Excel 1:1 File Compare can check data, formatting and objects. Formatting and object comparisons are off by default; enable Include Formats and Include Objects when required. Select the relevant sheets and an Output Path for evidence.

Run Excel Macro

Executes an existing Microsoft Excel macro from a TestStep, with a configurable timeout. Note the word existing — this Module runs a macro that already lives in the workbook; it is not a way to write VBA from Tosca. The timeout matters because a long-running macro would otherwise hang the TestCase.

Original optional exercise: write a web table to Excel

Source-era web-to-file flow

The supplied Obstacle Course example buffers the HTML table row count, creates a timestamped workbook, defines PersonTable from A1 to C{B[RowCount]}, and writes FirstName, LastName and Email headers. A repeating folder buffers each web row and writes it into the workbook.

The source uses {MATH[{B[RowCount]}-1]} because its count includes the header, and ${REPETITION} for data-row selection. Confirm that counting model before subtracting one; it is not a rule for every range. The source uses the older Close Excel Workbook with Save=True; current Close/Save Module operations are documented separately. Verify the saved file rather than assuming success from execution alone.

Original optional exercise: read Excel and verify the web table

Source-era file-to-web verification

The second scenario reopens the first workbook. It inspects a provisional A1:Z100 range with $lastContentRow, then narrows PersonTable to the recorded extent. Repeated steps buffer the three Excel fields and verify their corresponding web values before closing workbook and browser.

Keep the same generated file, timestamp buffer and web-page data for the dependent second scenario. Recreating the page may change the dataset. A1:Z100 is a training bound, not complete coverage of arbitrary files. Independently use a filename-safe timestamp, consistent buffer names and explicit boundary/mismatch checks; these safeguards are not certified by the source expected-result screenshot.
