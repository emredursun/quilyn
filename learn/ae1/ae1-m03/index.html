Scanning a PDF

The PDF Scan

The PDF Scan defines document regions for testing. Unlike HTML scanning, this workflow selects text, image or table areas in the document. Start Scan → PDF from a Module folder or use Ctrl+Shift+P, choose a file, then inspect the selected content before saving the Module.

Use Content Preview to check text and table recognition, including spaces. Force optical recognition is an alternative when the extracted content is wrong; choose the document language for OCR. Scanning an exclusion region alone does not configure a comparison.

Anchor controls: the core concept of this lesson

Why anchors exist

A target may move when document content changes. Absolute coordinates can still be used for fixed layouts. Use an anchor when the target retains a stable position relative to a distinctive element on the same page.

How it works at runtime

At runtime the engine finds the anchor, then calculates the target region from its recorded offset. Both may move together; if the distance between them changes, anchor identification alone does not guarantee the correct target.

Repeated labels can make an anchor ambiguous. Inspect its uniqueness after redraw or rescan; the scan highlights ambiguous anchors in orange. Select a distinctive same-page landmark.

Anchor accuracy

Type-specific defaults

The dedicated Tosca 2026.1 anchor configuration page specifies 100% matching accuracy for text anchors and 99% for image anchors. The scan overview describes exact matching more generally; use the type-specific guidance when configuring the Module.

Lowering accuracy

For a problematic anchor, select its ModuleAttribute and add the transition parameter Accuracy in the Properties pane. Use an integer from 0 to 100. This setting controls anchor matching; it is different from the comparison Module’s Accuracy [%] and from forcing OCR during scanning.

Treat lowered accuracy as a targeted fix for a specific problematic anchor, not as a default to apply everywhere. A too-forgiving match can silently anchor to the wrong element and produce a test that passes against the wrong region of the document.

Comparing PDF files

PDF 1:1 Compare

PDF 1:1 Compare compares a reference PDF with one or more targets using a configured minimum similarity, Accuracy [%]. Page by Page Image is the default. Full Text Content ignores text position and does not support OCR text recognition; Page by Page Text compares corresponding pages. Choose the mode that matches the assertion.

Current location: Standard modules → Engines → Pdf → PDF 1:1 Compare. Do not infer the Module inventory or shortened names of an inaccessible older course subset from the current documentation.

Combining compare with exclusions

Scan the variable region, save the Module, and use Copy Dimensions on its ModuleAttribute. In the comparison TestStep, populate the excluded area’s Dimensions and Page(s). This explicitly connects the scanned region to the exclusion; verify that the chosen region does not hide meaningful defects.

Excluded Pages and Excluded Text provide additional targeted exclusions; text patterns can be literal or regex. For link checks, the Standard subset includes Check PDF for Broken Links and Extract Links; link extraction does not require scanning.
