Inspect the generated test structure

API TestCases have request and response XTestStep types. Execution modifies and sends a request, then transfers response data to response Module Attributes. Inspect the generated structure and configure meaningful assertions; an observed response alone is not proof of correctness.

Independent guidance: avoid relying on a universal two-Modules/two-steps rule across every export mode and message type. Verify actual artifacts and references before execution.

Export targets and destinations

API Scan offers API TestCase, OSV Scenario and XML/JSON Test Case exports. Select messages or containers including subordinate messages. Choose the target that matches the intended test.

Selecting an existing ComponentFolder exports into it without creating another. Otherwise a new ComponentFolder is created. Export to Component Folders mirrors the project-tree structure using multiple folders.

Standalone API Scan exports a separate subset with a chosen path and name. This differs from saving the API Scan project. Current documentation does not establish the former fixed default-folder name or exclusive Ctrl-versus-Shift shortcut claim.

Independent export inspection

Export disposable messages to a selected folder; inspect generated artifacts, references and expected assertions. Repeat with structured-folder export. Academy exercise files were not accessed; this is an independent verification task.

Exercises, diagrams and practice feedback are available in the interactive lesson.
