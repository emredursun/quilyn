One Message In, Two Modules and Two TestSteps Out

Request/Response pairing

Every Message exported from the API Scan becomes TWO Modules and TWO TestSteps: one pair for the Request, one pair for the Response. This lets Tosca both steer the SUT (send the request) and set/verify dynamic parameters (read the response). The Modules hold the technical information needed to steer the system under test.

This Request+Response pairing is the single biggest structural difference between an API TestCase and a UI TestCase — every function-performing Message needs both halves present to be complete.
