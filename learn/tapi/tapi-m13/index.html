Load, modify and save

Open/Create XML file loads data into a resource. Use its name consistently for each step operating on that resource. Select the intended existing container; Insert creates the new element and its structure. Input can modify existing XML elements; it is not restricted to configuration fields such as Filepath.

Save XML file writes a resource to disk. Its optional Filepath selects a different destination from the connected source; if omitted for a resource loaded from a file, saving targets that connected file. For a newly created resource without a connected file, do not assume there is an original path to overwrite.

Independent guidance: use a full disposable output path and inspect the intended destination, permissions and overwrite risk. A different filename is not an absolute preservation guarantee if another file already occupies that destination. Do not infer directory-creation behavior from an unverified claim.

Identify and verify intended data

Independent example: among repeated Product elements, select the intended parent and use a unique Id constraint to identify Product 635 before checking its expected fields. Inspect uniqueness; a Constraint is not guaranteed to make duplicate IDs unique. Other supported selection mechanisms may also apply.

Verify XML can check resource content with XPath and explicit expected results. Configure namespaces when the expression needs them. A resource check proves the current resource state; to check persistence, save to a disposable output and reload that file into a separately named resource before asserting.

Independent insertion exercise

Independent verification exercise

Reload the saved output, locate the intended unique record and assert independent expected values. Add checks for duplicates, namespaces and malformed input appropriate to the contract. Academy Exercise 12b and course examination coverage are not certified.
