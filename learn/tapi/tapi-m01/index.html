What is an API?

API (Application Programming Interface)

The messenger program used to interact with an application. Unlike a UI, which is designed to be human-readable, an API is machine-readable — it speaks the language of the software directly.

A computer mouse is a physical API: clicking left or right is a physical action, but the interaction with the computer happens through an API, and the response appears on screen — even though you never touched the underlying code.

Webservice

A service offered by one electronic device to enable communication with other electronic devices via the World Wide Web. When a social media platform shows a map or an ad without writing that code itself, it has outsourced the job to a Webservice via an API request.

APIs are broader than Webservices: a Webservice is specifically the network-dependent subset of APIs (it requires a network to operate), while APIs in general can also be local/native and not require a network at all.

SOAP vs. REST and HTTP Methods

SOAP and REST

The two main Webservice implementation methods covered in this course. Both use the same underlying protocol, HTTP, but leverage it differently and support different message formats.

HTTP MethodPurpose
GETRequests data from a specified resource
POSTSubmits data to be processed to a specified resource
HEADSame as GET but returns only HTTP headers and no document body
PUTUploads a representation of the specified URI (updates an existing entry)
DELETEDeletes the specified resource

SOAP (Simple Object Access Protocol) uses only the POST method — every action, whatever it needs to do, must be translated into a POST. REST (Representational State Transfer) can leverage all conventional HTTP methods directly (GET, POST, PUT, DELETE, ...).

Message format is another key difference: SOAP uses only XML, while REST can work with a wider array of formats (XML, JSON, plain text). This makes REST more flexible, though SOAP remains extremely widespread in enterprise systems.

What is XML?

XML (Extensible Markup Language)

A markup language, much like HTML, that defines a set of rules for encoding documents in a format that is both human-readable and machine-readable. XML is self-descriptive and designed to store and transport data, and it simplifies data sharing and platform changes.

The Systems Under Test (SUTs) for This Course

Two SUTs, one per Webservice method

This course needs two Systems Under Test — one for each Webservice implementation method being tested.

SUTUsed forNotes
DemoWebShop (demowebshop.tricentis.com)SOAPThe same SUT used in Automation Specialist Level 1 & 2.
Coffeeshop (webservice.toscacloud.com/training)RESTAn in-development app for designing and ordering a custom coffee. Requires a Service Access Key/token to access.

Service Access Key

A token required to authenticate against the Coffeeshop REST service, generated at http://webservice.toscacloud.com/training. The key creates a temporary (24-hour) profile pre-loaded with basic data that you can freely add to and edit without disrupting other users.

The Service Access Key expires after 24 hours. If more than 24 hours pass while working through the REST section, generate a new key — and watch for accidentally copying a stray space along with the key, which causes a 'Key not recognized' error in Swagger, the API Scan, and Tosca Commander alike.
