Local XML data and export

API Scan File supports local message/definition files; the documented XSD workflow scans a schema and exports XML/JSON TestCases. Inspect whether your input is a data document or a schema; XML is hierarchical data, not inherently a relational database table.

Loading local XML does not by itself configure a network endpoint. Do not infer that every XML message must always fail or have an empty response: XML can also be used as a network API payload when transport is configured. A local file workflow and sending an HTTP request are different operations.

XML resources and structures

Open/Create XML file loads a file into a named resource. XML operations modify resources; Save XML file persists changes. Independent guidance: inspect the complete test, because a Save step can write to disk and resource-based editing is not a universal guarantee against data loss. Work with disposable copies and an explicit output path.

XML TestCases expose document, element, attribute, value, comment, declaration and CDATA control types. Insert adds new elements, Input changes existing ones and Verify checks values. Inspect generated structure and references rather than rely on an unverified universal Technical View absence claim.

Independent guidance: removing a Module element can affect its existing TestSteps. Inspect and synchronize affected references, then execute the relevant assertions.

Independent exercise

Scan a disposable schema or file and inspect exported structure. Load a copy into a named resource and modify it without saving; separately test an explicit save to a disposable destination. Original Academy exercise files were inaccessible and no Tosca execution was performed.
