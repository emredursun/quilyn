Independent organization and test intent

Name steps to distinguish operation, input and expected response; inspect actual Module references rather than depending on an unverified universal suffix rule. Names do not define execution ordering.

Independent example: create a disposable shop, retain its identifier, retrieve it and assert expected fields, then clean it up. A returned list is not automatically complete or ordered; follow the sandbox contract. Agree on maintainable names early, without treating one convention as a product prerequisite.

Default and clipboard values

Auto fill Values accepts an initial XTestStepValue, an XTestStep or a whole API TestCase. It generates the selected scope using linked Module defaults. The former claim that a TestCase cannot be selected is incorrect for current documentation.

For clipboard filling, define attributes, copy an XML, JSON or text message, select an XTestStep and choose API Testing > Auto fill Values > From Clipboard. Matching values are filled; structure and other nodes remain intact. Values absent from the copied message retain their existing values.

Independent guidance: inspect populated defaults and retained values before execution. A suggestion or observed server value is not automatically the correct expected assertion; avoid inadvertently reusing stale data.

Independent recap

Defaults reduce repetitive typing, while expected outcomes still need independent definition. Clipboard filling is selective and is not a complete replacement of the message or all existing values. These notes are not a verified transcription of Academy slides.

Independent exercise

Use a disposable step with several attributes. Fill defaults; then paste a message containing only some fields and inspect which values changed and which stayed. Academy exercise files were not accessed.
