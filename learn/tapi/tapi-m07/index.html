Naming Conventions and Organization

Request/Response naming

Request Modules and TestCases keep the same name as the original Message in the API Scan. Tosca automatically appends "Response" to the Response Module/TestCase name.

Numerical prefixes (01, 02...) applied earlier in the API Scan still matter after import — you can drag and drop Modules/TestCases into your preferred order in Tosca, but keeping the prefix makes it easy to identify matching Request/Response pairs at a glance.

The running example for this lesson: add a new coffee shop to the SUT, verify it exists, then delete it — a single TestCase spanning Create, Verify, and Delete.

Official Best Practice: it's best practice to determine a structure and naming convention at the beginning of the project to avoid misunderstandings during testing.

Default Value and Value Range

Value Range

When multiple values exist for the same Business Parameter (e.g. multiple cities across multiple shops in a Response), highlighting them in the Payload and clicking Add populates the ValueRange column on the corresponding TestCase. This lets you pick any one of those real values from a drop-down in the Value column.

Auto fill Values ("from Default")

Clicking Auto fill Values on the ribbon, then "from Default", populates the Value field with the Module's default value. It works when either only TestSteps, or only TestStepValues, are selected — not when a TestCase or a mix of TestSteps/TestStepValues is selected.

For TestCases with many TestSteps, hold Ctrl to select several TestSteps at once, then click Auto fill Values once to populate them all together.

Values from Clipboard

If an XML or JSON file already contains the parameters and values you need in a readable format, select the TestStepValues in Tosca, click "Values", then "from Clipboard" to populate them directly from whatever was copied to the clipboard.
