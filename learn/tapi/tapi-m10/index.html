SOAP Export Is (Almost) Identical to REST

Business context for this TestCase: place an order for BlueJeans in the DemoWebShop from start to finish, entirely through the API — get the current user's address, add BlueJeans to the cart, check out using that buffered address for both billing and shipping, then confirm the order appears in this month's order list and verify its pricing.

Because SOAP and REST behave so similarly in the API Scan, exporting a SOAP scan into Tosca — and building value ranges from the technical view — follows exactly the same process already learned for REST. This lesson is as much a recap as it is new material.

Buffering: Request vs. Response

Buffer behaves differently depending on direction

Selecting a payload line and clicking Buffer creates and buffers a Business Parameter from that element — but what gets stored differs by direction. For a REQUEST parameter, Tosca creates a modifiable EXPRESSION. For a RESPONSE parameter, Tosca records the actual returned VALUE. This is the one meaningful difference between buffering in UI testing and buffering in API testing.

The Buffer ActionMode, like any other ActionMode, can always be changed afterward if needed.
