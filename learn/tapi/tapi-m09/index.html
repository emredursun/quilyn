SOAP vs. REST, Recap and Reinforcement

SOAPREST
HTTP methods usedPOST onlyAll conventional methods (GET, POST, PUT, DELETE...)
Message formatsXML onlyXML, JSON, TEXT, and more
ProtocolHTTPUsually HTTP, though REST can in principle use a different protocol (uncommon)
FlexibilityLess flexibleMore flexible, though still less wide-spread than SOAP overall

Both SOAP and REST are Web Services implementation methods riding on the same underlying protocol (HTTP) — they differ in how they leverage that protocol and which formats they support, not in the transport layer itself.

Switching SUT: Scanning the DemoWebShop (SOAP)

Why switch SUTs here

The Coffeeshop used so far is a REST implementation. To explore SOAP, the course switches to the DemoWebShop — the same SUT used in AS1/AS2 — scanning its SOAP endpoint instead of a REST URI.

Renaming Operations and Messages doesn't change their functionality at all — it's purely an organizational best practice, identical in spirit to the numbering convention already used for REST.
