Why Create a SOAP Message Without Scanning

Shift-left scenario

Sometimes an API is fully specified — the business knows exactly what it needs to do, how, and for whom — but it isn't hosted anywhere yet. Rather than wait for hosting, the API Scan lets you manually create the message structure from the technical specification alone, so testing can begin immediately (shifting testing further left in the development cycle).

Worked example: create a message that would get the list of all available addresses saved in the DemoWebShop for a given user account — useful if the business were completely rewriting its shopping portal and this data existed but wasn't yet exposed through the website.

Manually Building the Message

Pretty Print

Self-created SOAP payloads may not arrive formatted into separate, readable lines — the content still functions correctly either way, but it's hard for a human to read. Pretty Print reformats the payload into readable, indented lines without changing the message itself in any way.

Pretty Print is purely cosmetic — it never alters what gets sent, only how it's displayed for editing.

Exporting a Self-Created Message

Exporting a self-created Message to Tosca uses exactly the same API Test Case export button as a scanned URI — the relevant Business Parameters are then created the same way as always.
