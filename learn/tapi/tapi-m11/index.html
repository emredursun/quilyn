Preparation before deployment

Independent shift-left guidance: prepare an operation payload and expected assertions from an agreed specification before implementation. Live behavior cannot be tested without an available endpoint; a simulator only tests its configured model. Record that distinction explicitly.

Create and inspect a message

API Scan supports creating a message in a project folder and editing its payload and endpoint. Set the method, authentication and headers from the actual binding; manual preparation does not prove the service accepts them.

SOAP 1.2 HTTP uses application/soap+xml, with an optional action parameter. Do not assume the SOAP 1.1 SOAPAction header is universally required for SOAP 1.2. Keep the envelope namespace and binding consistent with the contract.

Pretty Print formats the visible payload; it is not schema validation, a server request or a repair of business errors. Independent guidance: inspect whitespace-sensitive content and signed XML rather than promise all formatting is semantically harmless.

Export and verify readiness

Use the documented API TestCase export for selected messages, then define attributes and assertions. Generate defaults, inspect references and configure input values. Do not infer that every manually prepared message has the same response artifacts or valid selectors as a live scan.

Independent readiness checklist: confirm endpoint access, binding, credentials, payload schema, returned identity and positive/negative assertions. Only execute when an authorized endpoint or documented simulation exists.

Independent exercise

Prepare a disposable SOAP operation from a contract and document which checks are static preparation, simulated execution and actual service execution. Academy video/exercise material was inaccessible.
