A practical learning sequence

StagePractice
FoundationsRead the API contract, message format and transport semantics.
ScanImport a supported definition or file and inspect its operations/messages.
SendConfigure authorized credentials and valid data; inspect request and response.
AutomateExport selected messages and maintain mappings and assertions.
ReviewCheck negative behavior and business results, not only an HTTP status.

Prepare access and tooling

Practical preparation

Understand basic API and HTTP concepts and Tosca Modules/TestCases. Use a permitted test environment and the access and licenses required by your organization; exact Academy prerequisites were not accessible.

Launch outside Commander

Current Tosca 2026.1 docs name ApiScan.exe in %COMMANDER_HOME% as the filesystem launch entry. Running independently of Commander does not establish that an arbitrary copied executable needs no installation, license or supporting files.

In Commander, select API Testing > API Scan; the Modules menu also offers Scan Application > Non UI > API Scan.

Cloud-license connection

Check organization access

Confirm with your administrator that your account belongs to the cloud license server. This connection workflow is documented; a pop-up alone does not prove a single root cause.

Why test at the API boundary

Software interface

API requests can exercise a service without driving a graphical interface. A callable interface and usable test environment can permit testing before a UI is ready.
