API Modules and TestSteps

Export generates API Modules used by TestSteps. Request steps supply values; response steps expose received data for assertions or reuse. Independent guidance: inspect references rather than assuming every exported artifact becomes unrelated.

Module Attributes

Current documentation calls these Module Attributes. They expose business-relevant message elements, including payload, headers, parameters, authentication, attachments, method/endpoint/resource, status code and response time. Do not confuse this API mechanism with Reusable TestStepBlock Business Parameters.

Independent guidance: use a descriptive name and confirm the selected element before configuring a TestStep. A bare closing brace is not a reliable specification of an intended business element.

Defaults depend on direction and creation method

Add uses Insert for request attributes and Verify for response attributes. Add and buffer on a request uses Insert with a DefaultValue buffer reference such as {B[name]}; on a response it uses Buffer with the element name as DefaultValue. It is incorrect to say the request workflow is unavailable.

Insert supplies a message value; whether that creates a server object depends on the operation contract. Independently inspect Value and ActionMode before execution and ensure a referenced buffer exists.

Two update operations

To refresh a Module from API Scan: select it in Commander, use API Scan > Open selected Modules, modify messages and click Update. An attribute for a changed element also needs its mapping updated.

For a ModuleAttribute mapping: select the attribute, highlight the new or changed payload element and use API Testing > Update. Check the resulting XPath; a body attribute update changes DefaultValue. Module edits are automatically applied to corresponding messages, so a blanket no-auto-update rule is wrong.

Validate mappings after changes

Select attributes, a Module, a containing folder, ComponentFolder or project root; run API Testing > Module Attribute > Validate. The dialog identifies invalid attributes and allows navigation to them. Validation is not proof of server behavior or all business assertions.

Independent guidance: inspect renamed elements and affected TestSteps, then execute targeted tests. A rename can leave a stale XPath; failure is a risk to investigate rather than a guaranteed outcome for every edit. This recap is independent, not a verified transcription of Academy slides.

Independent mapping exercise

Use a disposable request and response: insert input, verify an expected output, capture a returned identifier and reuse it in a later request. Change one payload element, update the mapping, validate and execute. Academy exercises and videos were not accessed.
