API Modules and the Technical View

API Module

Contains the technical information imported from the API Scan. Every exported Message produces two Modules (Request + Response) because the two views hold different technical information — even though they were linked together in the API Scan, they become fully independent once in Tosca.

Technical View tab

A tab on the Module — new compared to the Details and Test Configuration tabs you know from UI Modules — that mirrors the Message section of the API Scan exactly. This is where Business Parameters are created.

Because Request and Response Modules are independent in Tosca (unlike in the API Scan, where they're linked), different Business Parameters can be added to each one freely.

Business Parameters

Business Parameter

A business-relevant element of a message — such as a name, ID, or address — added from the Technical View so a non-technical reader can understand what a TestStep does without looking at raw API code. When added, it acts as a ModuleAttribute that Tosca uses to execute the TestCase.

Business Parameters here are Module Attributes derived from the API Scan payload — they are NOT the same concept as the Business Parameters used in Reusable TestStepBlocks (covered in the AS1 course). Don't conflate the two.

DefaultActionMode: How Tosca Chooses

Official Best Practice — Insert: If the Module was created from a Request in the API Scan, the default ActionMode will be Insert when a Value is filled in. Insert allows Tosca to create objects in the SUT using the API and write a new value.

Official Best Practice — Verify: If the linked Module was created from a Response in the API Scan, the default ActionMode will be Verify when a Value is filled in. Verify compares the value in the TestStep with that in the API — the text entered in the Value column is case sensitive.

Official Best Practice — Buffer: If the Buffer button was clicked instead of the Add button when creating the Business Parameter, the default ActionMode will be set to Buffer when a Value is entered. Buffer only applies for a Response Module, not a Request Module — a Response will return the Value, whereas a Request is, by definition, inputting data.

Updating Modules When the API Changes

Official course Best Practice: Any changes made in the API Scan will NOT synchronize with the Modules or TestCases imported into Tosca, after they have been exported. Changes will need to be updated manually, or using the Update button in the API Home Menu.

Update Button (API Home Menu)

Updates changes made to the API Scan after it has been exported to Tricentis Tosca. It is the ribbon counterpart to editing a Business Parameter manually — either approach pushes a change through, but only the Update button does it for every reference to that element at once.

This same Update button can also be triggered from inside the API Scan itself (select the Modules in Tosca > Open Selected Modules > edit > Update) — covered again in Lesson 7, useful when many server-side changes have accumulated at once.
