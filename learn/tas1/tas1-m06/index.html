What is an ExecutionList?

ExecutionList

A structured list in the Execution section of Tosca Commander that runs TestCases and stores their results. Its key job is to execute TestCases AND keep a permanent record of every result.

Execution hierarchy (ExecutionFolder → ExecutionList → ExecutionEntry)

The Execution section is organized in three levels:

  • ExecutionFolder — a container that groups ExecutionLists (e.g., 'Exercise 21 - Create an ExecutionList').
  • ExecutionList — the actual runnable list (e.g., 'Web Shop'). This is what you Run.
  • ExecutionEntry — a single TestCase placed inside an ExecutionList. Dragging a TestCase in creates an ExecutionEntry.
  • ActualLog — the result record created inside the ExecutionList after a run, timestamped (e.g., 'created: 8/11/2021 11:28 AM').

ExecutionList vs. ScratchBook — results persistence (confirmed exam point)

The defining difference is what happens to the results:

  • ExecutionList — stores ALL historic results permanently (via the ActualLog). You can consult past runs any time.
  • ScratchBook — results are TEMPORARY. Each new run overwrites the previous one; nothing is kept.
  • Use the ScratchBook for quick trial/debug runs; use an ExecutionList for formal, recorded execution.

TestCase reuse (confirmed exam question)

The same TestCase can be added to an ExecutionList an UNLIMITED number of times. Each entry runs independently — enabling the same test to run with different data sets or configurations.

An ExecutionList is like a playlist: select your songs (TestCases), arrange them in order, and hit play. The same song can appear multiple times in the playlist, and each play is independent.

Creating and Running an ExecutionList

Drop target matters: drop TestCases ONTO the ExecutionList (green flag) to add them as ExecutionEntries. If you drop them onto an ExecutionFolder instead, Tosca creates a SEPARATE new ExecutionList for each TestCase (named <New ExecutionList>, <New ExecutionList>_1, ...).
