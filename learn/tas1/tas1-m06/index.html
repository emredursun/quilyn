Execution entries and recorded results

ExecutionLists organize TestCase references in the Execution tab. Drag a TestCase onto an existing list to create an ExecutionEntry; dragging a TestCase folder can create a linked entry folder. The structure can contain further folders, rather than exactly three universal levels.

By default, the same TestCase can be dragged onto the same list only once. Repetitions can repeat an entry with the same values. For multiple references with differing values, configure MultipleReferencesToIdenticalTestCaseAllowed and the entry TCPs deliberately.

ActualLog summarizes the latest run and is overwritten on rerun. Each executed entry gets a new TestCaseLog; ArchivedLog captures a snapshot when created. This is recorded history, not a guarantee of undeletable permanent retention. ScratchBook trials are temporary.

Passed, Failed, Error and No result are distinct. An environment/test problem can produce Error; missing results do not prove a preceding test blocked execution. The documented Skipped result is specific to SeaLights integration. Inspect the actual log detail.

Create, run and inspect

Create a folder and an empty ExecutionList in the Execution tab, then drop the intended TestCases directly on the list. Inspect the created references, effective parameter values and prepared SUT state. Independent team readiness checks may include completion/review; WorkState is not a universal creation prerequisite.

Run selected execution objects through the context menu or F6. Rearrange entries to change order; disabled entries are omitted. Run from here starts at the chosen entry. Execution behavior and dependencies must be configured rather than assumed from a prior failure.

Independent inspection exercise: run a disposable case twice and compare latest summary versus per-entry logs. Prepare and review the SUT prerequisites. Original Academy Exercise 21 was inaccessible and was not executed.
