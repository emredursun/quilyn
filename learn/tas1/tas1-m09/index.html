The Big Picture — How Tosca Sections Connect (Mindmap)

The five Tosca Commander sections

Each section owns one job; together they form the automation workflow.

  • Modules — the technical map of the SUT, collected via XScan. To steer a control it must be uniquely identifiable (properties, anchor, parent).
  • TestCases — a sequence of actions (the path through the application) built from Modules.
  • Execution — runs TestCases/folders; organize with ExecutionLists; drag a TestCase onto an ExecutionList to create an ExecutionEntry; add Recovery Scenarios to keep runs going.
  • Requirements — plan test processes and monitor risk coverage (functional & non-functional); TestCases link here.
  • TestCaseDesign — models test data and combinations; consult its current documentation separately.

Syntax Cheat Sheet — Text Expressions & Random Values

General syntax

Parameterized expressions use braces around the command and brackets around arguments. Some expressions, such as {DATE}, need no arguments; check each command separately.

ExpressionSyntaxExample / Note
Buffer (recall){B[Name]}{B[Automobile]} — re-enters the saved value
XBuffer{XB[Name]}Reads/buffers the DYNAMIC part of a string. Name may include numbers but must NOT be only numbers
Test Config Parameter{CP[Name]}{CP[Browser]} — reuse a central config value
Random integer (length){RND[n]}{RND[7]} = 7-digit number. Max 18 digits
Random integer (range){RND[min][max]}{RND[-789][123]} — negatives allowed
Random decimal (length){RNDDECIMAL[len][dec]}{RNDDECIMAL[5][2]} = 5-digit, 2 decimals
Random decimal (range){RNDDECIMAL[dec][min][max]}{RNDDECIMAL[4][130][200]}
Random text{RANDOMTEXT[n]}n-char letters+numbers. Max length 1024
Random regex{RANDOMREGEX["pattern"]}{RANDOMREGEX["^[A-Z][a-z]+[0-9]{4}$"]}

Taught in depth in Section 03 (Buffer/MATH/Random), Section 05 (TCP), and Section 08 (XBuffer). This is your one-stop syntax lookup.

Dynamic Date & Time — Quick Reference

Use {DATE} for the current date or {DATE[][][dd.MM.yyyy]} for explicit formatting. In parameterized unprefixed expressions retain all three slots; prefixed forms omit the format slot. Offset w means workdays, excluding weekends and configured holidays; M means months and m minutes. ADAY and AMONTH return three characters. With a 15 June 2025 base, {MONTHLAST[][-3y][ddMMMyyyy]} displays 30Jun2022. TIME and DATETIME output follows configured formats, not a universal AM/PM layout. Explicit format takes priority over the matching TCP and Settings format.

RowCount & ColumnCount — Quick Reference

For table counts, use RowCount->RowNum with ActionMode Buffer, then recall {B[RowNum]}. ColumnCount similarly buffers the column count. Verify the actual table/header representation before subtracting anything. If the measured row count is 5 and exactly one counted row is a header, {MATH[{B[RowNum]}-1]} gives 4 data rows. This subtraction is conditional, not a universal rule for every engine or table.

Resolve the Reference — Quick Reference

A Library block reference receives changes from the shared block. Resolve Reference replaces that reference with locally editable TestSteps, so later Library edits no longer change that local copy. Module references and TCP dependencies remain. Resolve only when a deliberate local variation is needed; do not assume a particular save boundary makes Undo available or unavailable.

What Makes a Good TestCase — Best-Practice Job Aid

Build a focused, readable test with controlled preconditions, purposeful actions and assertions that establish the expected outcome. WorkState supports planning; Requirement and ExecutionList links provide traceability and execution organization, without requiring Completed before linking. IF and loops are supported: use them deliberately with bounded conditions rather than hiding failures. Scan the controls needed for the intended scope; a valid Module can contain one control or several. Prefer stable, unique identification and descriptive names. These are independent maintenance recommendations, not a verified original Academy job aid.

Troubleshooting — Diagnose Before Changing the Model

Error messages are evidence to investigate, not a unique diagnosis. Inspect the log, current SUT state, engine and affected references before changing the model.

SymptomInvestigationControlled action
Multiple matching tabs or controlsCheck the active browser, parent scope and identification propertiesUse stable discriminators; a wildcard may broaden matches. Close only surplus test tabs intentionally.
No match or a control cannot be steeredCheck navigation, visibility, enabled state and current propertiesWait for the expected state within a bounded timeout; rescan only when identification has changed.
Hidden valuesInspect ActionMode and View filtersUse F9 in the appropriate context or configure displayed ActionModes.
Expression cannot be resolvedCheck command syntax, argument types, escaping and referenced valuesUse that command’s documented format; no-argument DATE is valid.
Buffer not foundCheck exact name and initialization pathInitialize before recall. Buffer Viewer also permits design-time creation/editing.
Unknown Browser TCP valueCompare the value with the documented browser listUse the supported spelling, for example Edge; a browser choice must suit the installed environment.
Missing ModuleAttribute or TestCase referenceInspect the affected link and available compatible objectRepair or reassign the reference; do not routinely delete the TestCase or Module.
Executor, GenericGui or object-reference errorInspect engine compatibility, control property, log and referenced objectsUse the documented engine/control procedure; a generic exception alone does not identify the cause.
Requirement values outdatedInspect AutoCalculateRequirements and the blue outdated-values indicatorSelect the RequirementSet and Update Outdated Values when calculation is manual.
