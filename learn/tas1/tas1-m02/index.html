Separate models and test intent

Modules store technical information; TestSteps supply actions and values. Reusing models can reduce duplicated maintenance, while meaningful naming makes tests easier to read. Scanning alone does not create business expectations, select all test data or guarantee working tests after an application change.

Independent guidance: update a shared model deliberately, inspect dependent TestSteps and rerun affected assertions. A reference update is not proof of application correctness.

Modules and ModuleAttributes

Modules can come from scanning, the Standard subset, recording or manual creation. In scanned Modules, ModuleAttributes represent selected controls; in Standard Modules they can be execution-task parameters. A ModuleAttribute is not merely a property such as the Module name.

Creating a TestStep creates TestStepValues from those ModuleAttributes. Fill the values and action modes to express test intent. Model properties identify and steer supported objects; not every automation operation imitates a human UI interaction.

Use appropriate Standard Modules

Standard.tsu provides ready-made XModules, sample TestCases/ExecutionLists, virtual folders and report templates. Import it during workspace creation or into an existing workspace using the supported procedure.

Independent guidance: choose a compatible utility or engine operation and configure its parameters. A pre-built Module does not make every action independent of the application or guarantee unrestricted use across versions.

Scan a supported local browser

For local XBrowser scanning, prepare the target browser extension. Start from a Module folder with Scan → Application or Ctrl+Shift+A, then choose the application in Select Application and scan it.

Select controls in the scan result or use Select on Screen. Review uniqueness, rename models and save the scan results. Use Advanced View when accessibility features are needed; Basic/Condensed View do not support them.

Use descriptive Module names; the naming guide suggests application | general section | coverage. Independent example: WebShop | Checkout | Payment. A naming separator is not an identifier.

A wildcard can tolerate a dynamic suffix in an identification property. Independent example: Demo Web Shop* may match related titles, but also multiple windows; inspect uniqueness and actual controls rather than assuming one broad title makes every page compatible.

Choose unique and stable identification

Properties are the default identification method. Try a stable unique combination first; Make Unique can add identifying properties. Parent context can disambiguate repeated controls and is not necessarily the immediate parent. Index and image identification are additional options, but ordering or appearance changes can affect them.

Anchors identify a target relative to another identifiable control. The current best-practice guide recommends anchors only for non-web applications because stable anchors can be difficult in modern web UIs. A dynamic web ID alone is not a reason to skip stable properties and parent context.

ShortestPath searches outward through tree levels from the anchor’s children. Coordinate uses the anchor position and a search angle. Auto is the default: it tries ShortestPath, then Coordinate on failure. None of these names guarantees stability under every DOM, layout or resolution change.

Convert eligible controls to a ControlGroup

Select eligible ModuleAttributes and choose Convert to ControlGroup. Only controls of the same type can be grouped; the documented eligible types are radio buttons, buttons and links. Existing TestCase use or unavailable checkout can prevent conversion.

Grouped TestStepValues offer controls through a dropdown. This simplifies choosing a member; it does not automatically execute every grouped control with one action.

Independent identification exercise

Compare stable properties and parent scoping on a disposable page. Separately inspect anchor algorithms where appropriate and group eligible same-type controls. Original Academy Exercise 04 was inaccessible; no browser scanning or group conversion was executed.
