Configuration inheritance and matching

Custom TCP reference syntax is {CP[Name]}: CP is outside square brackets. Inherited values can be overridden lower in the hierarchy. Built-in Browser configuration and custom data parameters have different roles; both use the documented configuration scope.

Independent example: configure BaseURL on the common parent and replace hard-coded uses with {CP[BaseURL]}. A child override can intentionally use another environment. This is not restricted to technical audiences or exclusively technical data.

Wildcard * can match varying text in supported values, table names and identification parameters. Independent example: Discount* tolerates a suffix; it can also match multiple labels. Inspect uniqueness and escape a literal asterisk. Adding a column or a wildcard does not create missing application controls.

Reusable-block data per reference

Business parameters summarize selected reusable-block data. Create a Business Parameter Container on the RTSB, add a parameter and link the relevant TestStepValue with {PL[Name]}. Set the concrete value in the consuming block reference. Names must not contain dots.

CP reads configuration; PL links a business parameter; B recalls a buffer. Business parameters can include URL data, so the prefix choice is about scope and linkage, not whether a value sounds technical.

Independent example: two references can supply different Email values while sharing the same block. Editing a reference value is separate from editing the reusable definition; definition changes can still affect consumers.
