Self-Defined Test Configuration Parameters

Self-Defined Test Configuration Parameter (TCP)

A custom parameter defined by the tester at the TestCase or TestFolder level. Stores a reusable value referenced across multiple TestSteps using {CP[ParameterName]}.

TCP Scope

Where you define a TCP determines how widely it is accessible:

  • TestFolder level — inherited by ALL TestCases within that folder
  • TestCase level — available to THAT TestCase only
  • Best practice: define at the highest appropriate level to maximize reuse

TCP Syntax (confirmed exam question)

Reference a TCP in a TestStep value field using exactly: {CP[NameOfTheTCP]}

  • Outer curly braces { } — mandatory
  • CP in square brackets [ ] — mandatory prefix
  • Parameter name in square brackets — e.g., {CP[BaseURL]}

Wrong syntax variants on the exam: CP[Name] (missing braces), {TCP[Name]} (wrong prefix), [CP{Name}] (brackets/braces swapped). Only {CP[NameOfTheTCP]} is valid.

Self-Defined TCP example (Exercise 19)

Three TCPs defined on the TestCase, then referenced in TestSteps:

  • Browser = Chrome — sets the browser for the run
  • DiscountName = AutomationDiscount2 — referenced as {CP[DiscountName]} in the 'Enter discount code' Input step
  • DiscountPercentage = 0.20 — referenced inside a MATH formula: {MATH[({B[SubTotal]}+10)*{CP[DiscountPercentage]}]}
  • TCPs combine freely with Buffers and MATH inside the same expression

Wildcards

A stand-in character for other characters, used to simplify a search or a data match. The asterisk * matches any sequence of characters.

  • Example: Discount* matches 'Discount', 'Discount:', 'Discount Amount', etc.
  • Useful when a Control's exact label varies or contains extra characters.
  • Exercise 19 tip: if the 'Discount' option is missing from a dropdown, manually add a column and use the wildcard Discount* to match it.

Business Parameters

Business Parameters

Parameters created on a Reusable TestStepBlock (RTSB) in a Library. They let you change the VALUES used by an RTSB Reference in a specific TestCase WITHOUT modifying the RTSB in the Library. They are the business-relevant elements of your TestSteps whose values you want to steer per TestCase.

{PL} Parameter Link Syntax (confirmed exercise detail)

Dragging a Business Parameter onto a TestStepValue field creates a Parameter Link: {PL[ParameterName]}

  • PL = Parameter Link — connects the TestStepValue to the Business Parameter.
  • {PL[URL]}, {PL[Email]}, {PL[Password]} — the value is supplied at the RTSB Reference level in each TestCase.
  • Do NOT confuse with {CP[...]} (Test Configuration Parameter) — different prefix, different purpose.

Business Parameters are defined in the LIBRARY (on the RTSB), but their VALUES are entered at the RTSB Reference inside each TestCase. Changing a value at the Reference does NOT change the Library — that is the whole point.
