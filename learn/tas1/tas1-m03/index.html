TestCase structure

A TestCase expresses a sequence. A Module-based TestStep uses TestStepValues corresponding to its ModuleAttributes; it is not limited to exactly one control interaction. TestCase folders organize cases; folders inside a case organize its steps.

Independent design guidance: separate setup, business actions and cleanup where helpful. Keep expected outcomes explicit rather than assuming a technical model determines correct behavior.

Create Module-based TestSteps

Drag a Module onto an existing TestCase. Alternatively, select a supported object such as a TestCase or a folder within it and use Ctrl+T or Search and Add TestStep. Choose the search result to create a step. These are examples, not an exhaustive count of all creation routes.

Independent guidance: choose a method that fits your task and inspect the resulting step. Double-clicking a Module in the Modules tree is not the same as double-clicking a Fuzzy Search result.

WorkState describes progress

PLANNED is the initial state for newly created TestCases; IN_WORK indicates progress and COMPLETED indicates completion. The documented states can be selected freely, so the illustrated sequence is an example rather than an enforced workflow.

Independent team policy: a team may request review after completion, but WorkState alone does not prove approval or passing execution.

Configure tests and columns

Reference a custom parameter as {CP[BaseURL]}: CP is outside the square brackets; the name is inside them, enclosed by outer braces. TCPs can describe environment settings or reusable values. Child objects inherit them and can override values locally.

Use the header context menu or View → Add column to open Column Chooser; drag the available column onto the details header. Available columns depend on the selected object.

ActionMode intent

Input changes a control; Verify checks an expected value; Buffer captures data for later use. Available modes depend on the interface. WaitOn waits for a condition, bounded by Synchronization Timeout during WaitOn; it does not wait forever or guarantee every timing issue is solved.

TestStepValues and DataType

A TestStepValue defines how its value is used. Current documented types include String, Date, Numeric, Boolean, Password, Secret and RawString. Password values are masked and stored encrypted; Secret is specific to key-vault retrieval. RawString skips parsing and cannot evaluate dynamic expressions.

For numerical comparison, select Numeric and check number-format configuration. Independent example: 10 and 10.00 can represent the same number but differ as exact strings. F9 is a context-dependent show/hide shortcut, not a universal value editor.

Trial runs in ScratchBook

Run selected objects with F6 or arrange them in ScratchBook and run there. Its structure and results are not retained like ExecutionList history. Repeating a trial can replace the earlier result. Prepare the SUT state required by the selected steps before starting.

Dynamic expressions

Recall stored data with {B[ItemPrice]}; it can be set through test actions or Buffer Viewer. If translation reports a missing buffer, inspect the available value and execution order rather than assuming every buffer exists only at runtime.

Independent arithmetic example: {MATH[{B[ItemPrice]}*3+5.00]} calculates three items plus shipping. Normalize incompatible operand formats before calculating. Translate Value can help inspect expressions that have the required data.

{RND[10]} produces a ten-digit integer; {RND[3][9]} uses inclusive boundaries. {RANDOMTEXT[10]} generates ten letters/numbers, not guaranteed globally unique data. RANDOMREGEX can constrain generated strings.

Date expressions use {FUNCTION[start][offset][format]}. Empty start uses the current date. Offset w means workdays, not weeks; M means months and m minutes. Independent examples: {DATE[][+4M][MM]} and {MONTHLAST[][-3y][ddMMMyyyy]}. Include the day when checking month-end.

Formatting is separate from calculating the date. MM is a two-digit month, MMM a culture-dependent abbreviated month and yyyy the year. {YEAR} normally returns two digits; time/date defaults depend on configuration.

Shared sequences and resolved copies

TestStepLibraries hold reusable blocks in TestCases. References let consumers share maintained steps. An RTSB and its reference can be renamed; a visible suffix is not proof of the actual link.

Resolve Reference produces an editable copy that stops following that block. Independent caution: it does not remove Module references, TCP lookups or other dependencies. No universal save-based Undo deadline is asserted here.

Independent reuse exercise

Create a suitable reusable block, add its reference to a disposable case and inspect the setup/action/cleanup ordering. Where different data is needed, inspect business parameters before duplicating a flow. Check how changes affect consumers.
