Commander workspace and navigation

Commander organizes models, TestCases, execution objects and requirements in workspace tabs. This guide focuses on those areas without claiming a fixed total number of sections. Modules are reusable models, not exclusively UI models.

The project tree shows object hierarchy; Details supports editing the selected object. Open sections from Home → Section. To compare tabs side by side, drag a tab onto the docking element. Do not assume the historical New Vertical Tab Group label exists in every release.

Save stores project changes; Undo/Redo and navigation shortcuts are separate functions. Independent guidance: inspect the available undo and recovery commands for your version and context rather than assuming Save permanently disables every recovery method.

Workspace types and collaboration

Single-user workspaces have a local database for individual work. Multi-user collaboration uses a separate workspace per user and machine, connected to a common repository. A local workspace path alone does not determine the repository type or prove who can access its files.

Checkout reserves an object for editing; another ordinary user cannot edit that checked-out object. Checkin publishes changes and frees objects. Checkout updates the selected objects; use Update all for unrelated repository changes.

Administrators can revoke checkouts in the primary repository, rejecting the holder’s unpublished changes and new objects. This is not a simultaneous merge or ordinary tester lock override. Coordinate with the owner before administrative recovery.

Exchange subsets deliberately

Export Subset packages selected objects and linked dependencies; authorized users can import it into another repository. Import does not keep the two copies synchronized. Project-root definitions and ViewingGroupName/OwningGroupName access rights are not exported; review destination configuration and rights.

Import targets the project root or a ComponentFolder; multi-user checkout applies. Inspect duplicate-Module import/merge decisions rather than treating import as an unrestricted copy.

The Standard subset includes ready-made Modules. A version migration does not automatically add every new Standard subset Module; import the applicable release subset and inspect affected tests.

Independent team organization example

Independent guidance: use descriptive names and separate shared resources from project-specific artifacts. A possible structure has templates/references, reusable cross-project resources and one folder per project. This is an example, not a mandatory three-folder repository rule certified from the gated Academy video.

Independent peer-review workflow: a tester moves work from In Work to Ready for Approval; a second reviewer records approval or returns changes. These labels illustrate your team process; they are not a universal built-in Tosca enforcement or an unskippable product state machine.

Independent workspace exercise

Create a disposable single-user workspace and inspect its repository type. Identify models, TestCases and execution areas; arrange two tabs using docking. Academy Exercise 01 was inaccessible, so this is independent practice guidance and no Commander execution was performed.

Inspect an authorized application

For local Chrome XBrowser/XScan automation, prepare the Tricentis Automation Extension in the actual target browser. This does not claim every supported remote or alternative-engine workflow uses the same setup.

Independent guidance: explore an authorized disposable application, document the intended flow and expected results, then identify controls to model. Manual exploration helps understanding but does not guarantee complete coverage.

Independent application exercise

Choose an authorized sandbox with suitable test data, map a reversible user journey and its expected outcome. Academy Exercise 02 and its original target were inaccessible; no original course completion or live application execution is certified.
