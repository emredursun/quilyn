Tosca Architecture at a Glance

Tricentis Tosca

A Model-Based Test Automation platform that enables codeless end-to-end testing by scanning the SUT to generate reusable test models.

Tosca Commander

The central IDE of Tricentis Tosca. Contains 9 sections in total; this course focuses on four core sections:

  • Modules — UI element models captured from the SUT
  • TestCases — ordered sequences of test steps
  • ExecutionLists — collections of TestCases to run
  • Requirements — business/technical requirements linked to tests

System Under Test (SUT)

The application being tested. In this course the SUT is the Tricentis Demo Web Shop at https://demowebshop.tricentis.com.

Tosca Commander is like an aircraft cockpit: each instrument panel (section) gives you a different view of the same flight (project). You can rearrange panels to suit your workflow, but they all control the same aircraft.

Single-User Access Rule

Access is granted to whoever has the local workspace file. No administrator role is required — only local file access matters.

Multi-User Check-out / Check-in

In a Multi-User workspace, objects must be checked out before editing. This locks them for other users until the editor checks them back in.

  • Check Out — marks the object as in-use; locked (read-only) for all other users
  • Check In — saves edits to the shared repository and releases the lock

Single-User = a private notebook only you can read. Multi-User = a shared Google Doc that anyone on the team can edit simultaneously.

Subsets

Subset

A file containing Tosca artifacts (Modules, TestCases, etc.) that can be exported from one workspace and imported into another — the primary mechanism for sharing test assets between projects.

Tricentis Standard Subset

A subset provided by Tricentis containing pre-built Standard Modules, predefined virtual folders, and standard reports. Import it into any workspace to use ready-made assets immediately — no SUT scanning required for these modules.

Workspace Best Practices

4-Eye Principle

A quality-control workflow ensuring a second reviewer validates all work before it is finalized.

  • In Work — tester is actively building/modifying the artifact
  • Ready for Approval — tester signals the work is complete and ready for review
  • Approved/Completed — reviewer confirms and closes the item

Component Folder Structure

Tricentis recommends three types of top-level Component folders in every repository:

  • Templates and references — reusable naming templates and sample structures shared across all projects
  • Relevant for all projects — shared Libraries and Standard Modules used by every project
  • Per-project folder — one per project, containing: Requirements, TestCaseDesign, TestCases, Execution, and Module sub-sections

Naming Conventions

Apply consistent, descriptive names across all folders, modules, and test cases. Practical rule: choose the name first, then add a more granular description — not the other way around.

Tricentis Automation Extension & SUT Navigation

Tricentis Automation Extension

A Chrome browser extension required for Tosca to scan and interact with web applications. Must be installed and enabled before any web-based scanning or automation.

SUT Navigation

Before automating, manually explore the SUT to understand user flows and identify which elements need to be scanned. This step prevents coverage gaps.
