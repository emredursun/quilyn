Test Library: folders, labels, and test status

Folders and labels

Folders (create via + → New Folder) give tests a single-location home in the Test Library. Labels are applied/removed via Edit Labels (or right-click → Edit Labels) and, unlike folders, a test can carry several at once — better suited to cross-cutting groupings like 'smoke' or 'checkout'. Search the library with label:<name> to filter by a label.

Test status

Testim's built-in test statuses are Draft (not ready to be used yet — still in progress), Active (automatically applied to tests that ran in the last 30 days), Evaluating (ready, but stability still needs to be examined), and Quarantine (unstable — generating errors, waiting to be fixed). 'Failed' and 'Archived' are NOT Testim test statuses — 'Failed' describes a run's result, not the test's lifecycle status, and there is no 'Archived' status.

Shared Steps Library and Revisions

Filtering the Shared Steps Library

Clicking Advanced filters opens the Filter Shared Steps pane, letting you filter by step category (Groups, Actions, Validations, Wait for) — the same filtering pattern used elsewhere in Testim's library views, including surfacing steps that are otherwise hidden from the default view so they can be selected and unhidden.

Revisions

Every time a test with changes is saved, the version before the change is automatically stored as a revision — no action is required to create one; it happens by itself on every save. After saving, a dialog optionally prompts for a change message describing the purpose of the change. The revision list (change message, user, date) lets you always look back and revert to an older revision.

Test Plans and Test Suites

Test Plans - Web

Test Plans model genuine environment setup/teardown around a run — preparing the environment before tests start, and cleaning up after. A Test Plan can be integrated with a CI tool by picking the specific CI tool your team uses and executing the test plan through that tool's pipeline, rather than being limited to local-only execution or manual copying of test cases.

Test Suites

Test Suites group tests into a collection and let you control the order they run in — the two core benefits: organizing tests into collections, and running multiple tests in sequence in a defined order. (Order is only guaranteed for non-parallel runs — passing --parallel to a suite run no longer guarantees the sequence.) Test Suites do not automatically delete unused tests, and executing directly from CI tools is a separate CLI/CI-integration concern, not a Test Suite feature itself.

Locators: Auto Improve and Smart Locator confidence

Locators: Auto Improve

If a locator's score drops below 70%, Testim automatically attempts to improve that locator to enhance the test's stability. If the improvement succeeds, Testim replaces the degraded locator with the improved one and creates a test revision labeled 'Testim auto improve' — so the change is tracked, not silent.

Smart Locator confidence and changed attributes

Smart Locators weight potentially hundreds of attributes per element. When an element's attributes change during a test run, the test can still pass — Smart Locators can typically still identify the element using its other, unchanged attributes — but the confidence score for that locator may decrease. A page-change warning is shown specifically when that confidence level varies by more than 20% compared to the originally recorded test.

Bug Reporting with the Testim Extension

Capture Video & Bug Scenario

The Testim (Chrome) Extension's Capture feature records a video of a bug scenario, generates a screenshot per step, and can publish it straight to a connected bug tracker (e.g. Jira, Trello). Before any of that is possible, the prerequisite is installing the Testim browser extension for Chrome — the capture/video functionality lives inside the extension, not the web editor itself.
