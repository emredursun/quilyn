Test Library: folders, labels, and test status

Folders and labels

Folders (create via + → New Folder) give tests a single-location home in the Test Library. Labels are applied/removed via Edit Labels (or right-click → Edit Labels) and, unlike folders, a test can carry several at once — better suited to cross-cutting groupings like 'smoke' or 'checkout'. Search the library with label:<name> to filter by a label.

Test status

The documented lifecycle statuses are Draft, Active, Evaluating and Quarantine; Failed is a run result. The status feature is professional-plan functionality and documents CLI 3.135.0 or later. At feature enablement, tests run within the preceding 30 days are identified as Active; this does not promise perpetual rolling automatic promotion. Evaluating failures do not fail CI/Scheduler; quarantined tests normally do not run, with an explicit CLI bypass available.

Shared Steps Library and Revisions

Filtering the Shared Steps Library

Clicking Advanced filters opens the Filter Shared Steps pane, letting you filter by step category (Groups, Actions, Validations, Wait for) — the same filtering pattern used elsewhere in Testim's library views, including surfacing steps that are otherwise hidden from the default view so they can be selected and unhidden.

Revisions

Saving a changed test stores the previous version as a revision with author/date and an optional message. Reverting shared content can affect other instances; inspect the shared references before restoring. A save with no change is not a promise of a new revision.

Test Plans and Test Suites

Test Plans - Web

A web plan selects labels/suites, optional Before All/After All tests and run configuration. Before/after phases use parallel level 1; a failing Before All stops the main list. After All is documented to run when main-list tests fail, but that does not certify successful cleanup after every abort/infrastructure failure. CI invokes the plan through the supported CLI workflow.

Test Suites

Suites collect tests and set an intended order. Parallel execution does not guarantee that order. CLI/Scheduler can run suites; suite creation alone does not provision a CI pipeline or delete unused tests.

Locators: Auto Improve and Smart Locator confidence

Locators: Auto Improve

The documentation describes an Auto Improve attempt below 70% locator score, with replacement and a revision after successful improvement. It applies automatically to writable master, can be enabled on read-only master, and does not run on other branches. Manual locator editing disables future Auto Improve for that locator. An attempt is not guaranteed repair or outcome correctness.

Smart Locator confidence and changed attributes

Changed attributes may reduce confidence while other weighted attributes still permit matching. A documented page-change warning is associated with a variation greater than 20% from the recorded confidence. Verify the actual target and asserted result; confidence alone does not establish correctness.

Bug Reporting with the Testim Extension

Capture Video & Bug Scenario

The Chrome extension offers Capture Video & Bug Scenario with screen recording and per-step screenshots. Publishing requires a connected tracker. Bug Reporting also supports reporting a tagged test failure; not all reporting requires a new video capture.
