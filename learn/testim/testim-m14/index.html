Two types of API steps: Add API Action vs. Validate API

Add API Action

Used to get data returned from an API call — the data it retrieves can simply be used to check that something was returned (or extracted and used later), rather than asserting a specific value on the spot.

Validate API

Used to validate data returned from an API call — usually validating data directly against the backend, asserting the response matches an expected value rather than just retrieving it.

Although the two can be used interchangeably in many cases, Add API Action is the recommended default because it allows passing parameters when performing the API call — something that matters as soon as the call needs to vary per test run rather than always hitting the exact same fixed request.

Configuring an API step

Adding an API validation step

Hover over the arrow where the step should go, click the predefined-steps icon ('M'), then choose Validations to add an API validation step to a test.

URL and request method

In the URL field, you select the desired HTTP request method and enter the root endpoint and path, then configure what should happen on failure — for example, throwing an error message following a failed validation.

Validating API responses against the UI

The Validate API feature lets you validate API response values against what's shown in the UI — cross-checking backend data against rendered content, not just asserting the response in isolation. You can also configure whether to retry the request if it fails, or run the step's validations even when the status code itself is an error.

Send via web page

Send via web page (checked = default)

Keep this checked when the API call should also carry browser information such as cookies — they're sent automatically, useful for endpoints that require the same session as the UI.

Send via web page (unchecked)

Deselect it to send the API call outside the browser context, so browser restrictions don't apply — for example, when the target API doesn't support CORS and would otherwise reject an in-browser request.
