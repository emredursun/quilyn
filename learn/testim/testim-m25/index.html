What the CLI needs to run

Node.js requirement

Running Testim via the CLI requires Node.js to be installed on the machine — the CLI is itself an npm package and runs in the Node.js runtime.

Supported versions

Testim supports all LTS (Long-Term Support) / supported versions of Node.js — not just one specific pinned version — giving teams flexibility in which supported Node.js release they standardize on.

Local vs. remote runs

Once the prerequisites are met, the Testim CLI can run commands either locally on that machine or remotely — the prerequisite (Node.js) is what makes the CLI itself runnable in the first place, independent of where the test execution actually happens.

The Testim CLI package itself also has a version-support policy

It isn't only Node.js that has a version policy — the Testim CLI npm package does too: the latest version is supported, with backward compatibility maintained for the previous two versions. The same 'latest + previous two' backward-compatibility window applies on the Node.js side as well.

For the exact current list of Node.js LTS/supported versions, Testim's documentation points to the official Node.js Release repository on GitHub (nodejs/Release) rather than pinning a static list in its own docs.
