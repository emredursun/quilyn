What the CLI needs to run

Node.js requirement

Running Testim via the CLI requires Node.js to be installed on the machine — the CLI is itself an npm package and runs in the Node.js runtime.

Supported versions

Testim supports all LTS (Long-Term Support) / supported versions of Node.js — not just one specific pinned version — giving teams flexibility in which supported Node.js release they standardize on.

Local vs. remote runs

The CLI requires its installed package and supported Node.js on the initiating machine. Local/grid execution additionally needs its own browser/device infrastructure, credentials and connectivity; runtime prerequisites alone do not establish readiness.

The Testim CLI package itself also has a version-support policy

The CLI prerequisites table specifies latest CLI with backward compatibility for the previous two versions. It also lists a Node.js supported-runtime requirement with a previous-two compatibility comment. The table does not define those as previous major releases or guarantee end-of-life Node.js security/support.

Check upstream Node.js release status and the installed CLI’s compatibility. Current, Active LTS, Maintenance LTS and End-of-Life are different statuses; a previously LTS line can be end-of-life today.
