The Testim visual editor

Visual, codeless-first editing

Testim's visual test editor has features built directly into the UI so that customizing a test — reordering steps, editing properties, adding validations — does not require writing code, while still allowing custom JavaScript steps for advanced cases (covered later in this learning path).

Base URL

Each project/test has a base URL — the starting address the AUT browser opens before a recording or run begins. Getting the base URL right (and open) is a prerequisite for actions like Reassign and Improve on a target element, which need the AUT browser open at that URL to let you re-select an element.

Running tests: editor vs. Test List

Running from the editor

Clicking Play in the editor's toolbar opens a new browser and runs the currently open test's actions against the AUT. This is the fastest feedback loop while actively building or editing a single test.

Running from the Test List

One or more tests can be selected in the Test List (Ctrl/Cmd-click for multiple) and run together with the Play button. Tests run this way execute locally, which is useful for quickly re-checking a batch of related tests without leaving the Test List view.

Local runs are limited to the Chrome browser. Running on other browsers (Firefox, Safari, Edge) or in parallel requires the CLI or Scheduler rather than a plain editor/Test List run — this becomes important later in the 'Executing tests across multiple browsers' module.

From actions to assertions: basic validations

Why validations matter

A recording by itself only proves the AUT can be clicked through without crashing — it does not verify the application behaved correctly. Validation steps turn a recording into a real test by asserting specific, expected outcomes.

Core validation types

Validate element visible checks that an expected element is present on the page. Validate element text checks that a specific text value appears in a specified element (Testim supports Regex in the Expected Value field). Validate element not visible checks the opposite — that an element has disappeared, e.g. after closing a modal.
