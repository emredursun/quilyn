The Testim visual editor

Visual, codeless-first editing

Testim's visual test editor has features built directly into the UI so that customizing a test — reordering steps, editing properties, adding validations — does not require writing code, while still allowing custom JavaScript steps for advanced cases (covered later in this learning path).

Base URL

The project default base URL initializes new tests; an individual test can use another URL. It is the starting AUT address, not the editor address. For target editing, open the AUT and reach the relevant test state; opening only the initial page may not expose a later target.

Running tests: editor vs. Test List

Running from the editor

The editor runs the open test locally or on a configured remote grid. Use the Play dropdown for Run on grid and choose the applicable configuration. Local editor playback uses Chrome; a single grid run is distinct from a cross-browser matrix.

Running from the Test List

One or more tests can be selected in the Test List (Ctrl/Cmd-click for multiple) and run together with the Play button. Tests run this way execute locally, which is useful for quickly re-checking a batch of related tests without leaving the Test List view.

Local web playback uses Chrome. The editor also supports a single remote grid run. Use the documented CLI or Scheduler workflow for a cross-browser matrix with suitable grid configurations.

From actions to assertions: basic validations

Why validations matter

Successful action replay establishes that those steps executed, not every business outcome or overall application health. Add assertions at meaningful outcomes; a click-through recording alone does not establish correctness.

Core validation types

Visible checks element existence and visibility, not its specific content. Text checks the chosen element’s expected content and supports Regex in Expected Value. The documented not-visible step is web-only: it asserts absence from view, not necessarily removal from the DOM.
