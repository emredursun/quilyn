What Testim's email service is

Testim's own email service

Testim’s managed email feature creates permanent inbox addresses in Settings > Email Service or temporary addresses through Generate email address. Third-party providers are not used to generate these managed addresses; that is not a ban on all external-service integrations.

Email validation and exports

Validate email reads managed-inbox messages for coded checks or codeless filters. The codeless mode can extract text/links and exposes emailData, emailExtractedText and emailExtractedLinks. Generic DOM Extract Value is not required to read that inbox.

Email and SMS are separate retrieval paths

Direct email flows

Use the managed inbox for supported email flows. Match the intended message and required outcome rather than assuming any message proves the current request succeeded.

Direct SMS retrieval

The official Extract SMS message example uses a CLI action with Twilio, sender/recipient filters, recent-message checks and a returned Promise. It exports the code from the selected message. This is an SMS-provider path, not the managed email inbox.

Forwarding SMS content into email is an independent environment-specific alternative only if explicitly configured and verified. It does not prove SMS delivery to a phone and is not certified here as the original Academy workflow.

Selecting and reusing the required message value

The extraction pattern

Filter for the intended message, verify required content and export the code/link with supported scope. Extracting one value does not replace message assertions or prove phone delivery. Avoid assuming the first old mailbox message belongs to the current test.

Choosing permanent vs. temporary for this scenario

Use a reusable permanent inbox or per-run temporary inbox according to the email scenario. A fresh inbox does not create a fresh phone number or guarantee a newly registered backend account.
