What Testim's email service is

Testim's own email service

Testim generates email addresses exclusively through its own built-in email service — there's no option to plug in a third-party email provider for this. Two address types are available: a permanent address, created once from Settings → Email Service → Generate Email Address; and a temporary address, generated fresh on every run via a Generate email address step in the test itself (shown as 'Temporary' in its title).

Validate email and Extract Value together

Validate email fetches the content of a Testim inbox (for a permanent or temporary address) as an array of all messages in that mailbox — confirming a message arrived. Extract Value then pulls just the specific, stable content needed out of that message (a code, a link) into a variable for later steps to use.

When to use Testim's email service

Direct email flows

The obvious case: any flow where the AUT itself sends an email — signup confirmation, password reset, order confirmation — and the test needs to receive and act on that email's content.

SMS content routed through email

The less obvious, but exactly what this module is about: many applications and SMS/OTP providers can be configured to forward SMS content (like a one-time verification code) to an email address instead of, or in addition to, a phone number. When the AUT or its SMS provider is set up that way, Testim doesn't need any separate SMS API integration — the SMS content simply arrives as a message in a Testim email inbox, and it's read and extracted using the exact same Validate email / Extract Value mechanism as a normal email.

This is the core idea behind the module's title: it's not that Testim has a dedicated SMS-reading feature — it's that routing SMS through email lets the email service double as the SMS-reading mechanism, avoiding the need for a separate SMS testing integration.

Extracting an SMS-forwarded value from a test

The extraction pattern

Rather than asserting on an entire forwarded-SMS message body, the recommended pattern is to extract only the specific, stable value needed — an OTP code, a verification link, a short confirmation phrase — and save it to a Testim variable so a later step (entering the code into the AUT, for example) can use it directly.

Choosing permanent vs. temporary for this scenario

A permanent address suits a recurring flow you test repeatedly (e.g. re-verifying the same test account's phone number). A temporary, freshly-generated address suits a scenario that needs a brand-new, never-before-used contact point on every run — such as testing that a new-user SMS-verification flow works for a genuinely new signup each time.
