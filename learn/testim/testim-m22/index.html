CI integration recap: the CLI is the universal connector

One CLI, every major CI

Testim CLI is installed with `npm i -g @testim/testim-cli` and, because it's a simple shell command, it can be wired into any CI platform capable of running one — Jenkins, GitHub Actions, GitLab CI, Azure DevOps, and more — without needing a bespoke plugin per platform.

This is the same underlying mechanism covered for Jenkins earlier in this path — Azure DevOps integration (next section) uses the identical CLI, just wired into Azure Pipelines' own YAML syntax instead of a Jenkinsfile/build step.

Setting up Azure DevOps integration

Azure Pipelines setup

Testim provides a ready-to-use YAML code snippet for Azure Pipelines that installs Node.js and the Testim CLI, then runs the same kind of `testim --token ... --project ...` command used for any other CI — added as a step (or a full pipeline stage) in the Azure DevOps pipeline definition.

Azure DevOps integration here is specifically about triggering Testim runs from an Azure Pipeline — it is a CI trigger mechanism, not the same thing as linking individual test cases to Azure DevOps work items (that kind of test-management-level linking is what the TTM for Jira integration provides, for Jira specifically — not Azure DevOps).

Linking a test to TTM for Jira and viewing results

Finding the integration

Testim's integrations live under the Integration settings, where a Test Management section lists modules including TTM for Jira and Xray. Within TTM for Jira's module, you provide the required Jira API token and Jira domain information to connect the two systems.

Linking a test to a TTM for Jira test case

Once connected, an existing Testim test can be linked (one-to-many) to a TTM for Jira test case — and a bulk create-and-map option lets you select multiple Testim tests and create their corresponding TTM for Jira test cases in one action, instead of mapping them individually.

Viewing results in TTM for Jira

After running a mapped test in Testim using a Remote Grid (not a local editor run), the result is automatically pushed to TTM for Jira and appears under that project's Test Execution tab — giving a single place to see both Testim's own results and TTM for Jira's execution history. The name and pass/fail status are the details pushed from Testim to TTM for Jira.

The Remote Grid requirement matters: a test run directly from the local editor will NOT be reflected in TTM for Jira's Test Execution tab — only remote/grid-based runs (the same 'counted runs' distinction covered in the results-management module) sync back.
