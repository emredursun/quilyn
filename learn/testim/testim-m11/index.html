CLI actions vs. custom (browser) actions

CLI actions and validations

Custom Node.js scripts executed in the CLI environment (not inside the browser), initiated from inside a test the same way a standard custom action is. Because they run outside the browser sandbox, CLI actions/validations can do things a browser-side custom action cannot — like database validation and manipulation, or image and PDF validations.

The distinction to hold onto: a regular custom action/validation runs in the browser's JavaScript context; a CLI action/validation runs in Node.js in the CLI environment, which is why it can reach things (a database connection, the filesystem, a PDF parser) the browser sandbox can't.

Using Copilot to generate a CLI action's code

Generate applies to CLI actions too

The same Testim Copilot Coding Assistant used for regular custom steps also works inside a CLI action step: create the CLI action, click 'Write code with AI', and use the Generate command with a plain-text description of what the Node.js code should do (e.g. 'query this database table and return the row count'). The generated JavaScript appears in the chat pane, ready to use as the CLI action's implementation — the tester doesn't need to hand-write the Node.js from scratch.

This is the same Generate/Explain/Fix workflow covered for ordinary custom action steps — the only difference here is that the target step type is a CLI action, so the generated code runs in the CLI's Node.js context instead of the browser.
