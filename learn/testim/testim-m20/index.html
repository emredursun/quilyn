Why CI integration is CLI-first

The CLI as the integration point

CI can invoke the npm-based Testim CLI when its runner has a supported Node.js environment, configured credentials/project/grid and required network access. Shell capability alone does not guarantee a working integration.

Named integrations

The CI documentation links platform-specific runner guides such as Jenkins, Azure Pipelines, GitLab and others. A guide listing does not establish universal out-of-box branch mirroring or automatic pipeline provisioning.

Setting up and monitoring a CI integration

Generating the CI command

Settings > CLI > CI provides a platform-specific starting command. Adapt it to the runner and actual selection/configuration; configure safe credential handling and a JUnit report path that the CI collector also reads.

Monitoring CI runs from Testim

Inspect the applicable test/execution result and time-filtered history. Correlate them with the actual CI build; a chart or copied command does not by itself prove the pipeline completed or identify every failure cause.
