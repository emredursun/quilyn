Why CI integration is CLI-first

The CLI as the integration point

Tricentis built the Testim CLI, installable via npm, specifically so tests can be integrated with CI systems. Because it's a simple shell command, it can be invoked from all major CI tools that can run a shell command — the CLI is what makes the integration broadly tool-agnostic rather than requiring a bespoke plugin for every CI system.

Named integrations

Testim integrates with Jenkins and other third-party tools including GitHub, GitLab, and Azure DevOps — some with dedicated, deeper integrations (branch mirroring, pipeline triggers) beyond just 'the CLI can be called from anywhere'.

Setting up and monitoring a CI integration

Generating the CI command

The setup path is Settings > CLI > CI — from there, select your CI platform from a dropdown menu and copy the generated, ready-to-use command for that platform.

Monitoring CI runs from Testim

Once integrated, you can monitor test execution across builds from Testim and open the relevant test result with one click to diagnose a failure, plus review historical pass/fail analytics filterable by time period.
