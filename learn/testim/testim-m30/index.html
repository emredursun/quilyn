Reusable, parameterized login groups

Grouping login steps

Create and save a shared login group with a meaningful name so other tests can reuse its steps; ordinary grouping alone does not establish cross-test reuse.

Parameterizing credentials

Define username/password group parameters and replace the constants inside its entry steps with those parameter references. Caller values can differ. Parameterization alone is not secret encryption or an access-control mechanism.

Cleaning up recorded noise

Remove a recorded Tab/focus step only after checking its effects. It may trigger blur validation or other application behavior. Replay the entire flow and save after confirming needed behavior remains.

Handling browser/session state around login

Incognito mode

A new incognito session reduces inherited browser cookies/storage when testing login. This does not clear server-side account state or guarantee isolation from SSO and other environmental authentication.

Conditional login execution

When testing a flow that allows an existing session, use a runtime condition such as login-button visibility or login-page URL. Verify the expected authenticated state afterwards; a skipped login group alone does not prove authentication. When login itself is the test objective, establish a logged-out state instead.
