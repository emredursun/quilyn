Reusable, parameterized login groups

Grouping login steps

Grouping login steps allows reuse of those steps across other tests — give the group a meaningful name so its purpose is clear to anyone browsing the project's groups later.

Parameterizing credentials

To make the group generic across different accounts, add JavaScript parameters for username and password in the group's properties panel. Every time the group is used, different credentials can be supplied without duplicating the underlying steps.

Cleaning up recorded noise

Steps recorded as a manual user — like pressing Tab to move between fields — often aren't relevant to the automated test and can simply be deleted, keeping the login group lean and focused on what actually matters.

Handling browser/session state around login

Incognito mode

Running in incognito mode is useful specifically while building the login process: each run starts with a clean browser — no cookies, no local storage, nothing remembered — so the test reliably exercises the actual login flow instead of skipping it because a previous session is still active.

Conditional login execution

Adding a condition that checks, at runtime, whether login is actually needed (e.g. an element condition on whether a login button is visible) lets the same test work whether the session starts logged in or logged out — rather than assuming one state and breaking under the other.
