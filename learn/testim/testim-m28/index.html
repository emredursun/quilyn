Generating base test code with the CLI

Settings > CLI: CI vs. Local

Settings > CLI generates a base command with token/project ID for a CI integration or local shell. Select platform/grid where applicable. CLI access depends on the subscription; a local initiating shell is distinct from the target execution infrastructure.

Using the generated code

Copy the base command, then configure a supported runtime, connectivity, selected tests/grid and appropriate secret handling. Generated text alone does not establish execution readiness.

Managing project users and roles

Project teammates

The Project teammates screen (via the Users icon in the main navigation) lists everyone currently assigned to the project. Inviting is done by entering each teammate's work email (followed by space or Enter), then clicking Invite.

Roles: member vs. owner

Project members can invite teammates; project owners can remove teammates and change project ownership. Removing a teammate from a project does not remove them from the company. The sole project owner cannot be removed.

Overseeing projects and users at the company level

Membership versus activity

Company administration lists projects and teammates; invitations grant access only to projects the inviter can access. Membership does not describe every action. The professional-plan Audit Log, restricted to project/company owners, records user, action and time and offers project/member/action filters.

Dashboard Recent Activity can also expose events within its scope. External issue/TMS integrations are not a required substitute for the built-in Audit Log. Company owners manage company ownership, and the last company owner must remain.

Protecting branches: pull request settings

Protect branches from changes

A toggle in the project's pull request settings that prevents writing directly to the Master branch and/or other selected branches (making them read-only) — changes must go through a pull request instead of a direct commit.

Related settings

If Master is protected, 'Allow Auto-improve on master' can still be enabled so the Auto-improve locator feature keeps working even on a protected branch. 'Require approving reviewer' can be turned on per-branch to mandate a review before a pull request merges. Only the project owner or company owner can change these settings, and they're a professional-plan-only feature.
