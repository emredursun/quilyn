Uploading and structuring test data

Supported formats and limits

Test data files can be uploaded in CSV, JSON, or Excel, each up to 2 MB. When uploaded via the Excel/CSV route specifically, each row of the file is converted into a single data set, with a maximum of 1200 rows.

Multiple ordered data sets

A single file can define multiple ordered data sets, letting one test run repeatedly against a whole matrix of input combinations instead of a single hardcoded scenario.

Each column in the file becomes a parameterized variable a step can reference (the same Parameters mechanism covered earlier in this path) — a row is really just one full set of parameter values, and running the test 'with' a row means running it with those parameters substituted in.

Config File vs. Params File for data-driven CLI runs

Config File overrides

A Config File can override the Visual Editor's test data at either the execution level or a specific test level (via overrideTestData) — and it's also how an external data source (like a linked CSV file, or a database) is supplied instead of an uploaded file.

Params File

A Params File (JSON) is execution-level only — it applies the same set of parameters across every test in the CLI run, rather than being scoped to one specific test the way a Config File's overrideTestData can be.

Where the multiple data sets actually run

Editor run vs. CLI/Scheduler run

Running the test from the Testim Visual Editor only executes the FIRST data set in the file, even if the Excel/CSV has several. Only when the test is run from the Testim CLI, the Scheduler, or a local suite run does it actually execute multiple times, in order, once per data set.

This is a common trap: seeing a single successful editor run and assuming the whole data set matrix has been exercised, when only row one has actually been used.
