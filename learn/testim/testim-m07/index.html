Validating CSS properties

Validate CSS property

Checks any CSS property of an element. Property name takes a valid CSS property for the selected element (e.g. color, display, font-weight); Expected value is what that property should equal. The expected value can be a hardcoded literal (wrapped in quotes, e.g. 'red') or a parameter (entered by name, without quotes) — the same pattern used across other validation types.

Editing after creation

The property name and/or expected value can be changed later without re-selecting the element. If the element itself needs to change, hover the target element thumbnail and click Reassign, then click the new element in the AUT window — the same Reassign mechanism used on any other step.

Validating data-driven actions

Data-driven validation in a real flow

Independent signup example: assert the required heading and resulting registered account using supported text/visibility/custom checks. Add intermediate assertions where they establish meaningful requirements or help diagnosis; asserting every typed value is not a universal Testim requirement. Generating a string does not create a working email inbox or prove a password was accepted.

This ties together earlier modules directly: Generate random value/date for the dynamic data, Validate element text/visible for the resulting UI state, and Parameters to carry the generated value between steps.

Custom validations for actions beyond the predefined menu

Custom validations and custom actions

Browser custom steps can inspect DOM/HTML parameters. Node.js CLI steps are a separate execution path with their own runtime and supported package setup; local execution requires the connected Testim CLI and documented entitlement.

Pass/fail contract for custom validations

For a synchronous browser custom validation, return an explicit boolean. False or a thrown error can fail the check; timeout and failure handling also matter. Supported asynchronous examples return a Promise that resolves/rejects. The final synchronous true/false value is not the entire contract for every custom or CLI step.

Extracting a user-defined value for custom checks

Extract selected AUT text into a variable and reference it in a supported later validation or custom-code scope. Numeric/date matches can remain strings and require deliberate conversion; not every field accepts parameter references.

Verifying whether a validation succeeded

Reading the step's status

After a run, a passed validation step shows its icon (upper-left corner of the step) in green, with a confirming message in the Properties panel. A failed validation step shows that same icon in red, with a failure message in the Properties panel — the same visual pattern applies to custom validation steps as to any predefined validation.
