The TestOps Dashboard: reading project health

TestOps Dashboard

Provides quick-access statistics on tests, remote execution runs, and other project activity — the go-to place to analyze overall project health and quickly identify which tests need attention, without digging through individual runs.

Duplication Level pane

Shows the project's auto-grouping duplication score — identifying step sequences that are duplicated across tests but haven't yet been consolidated into shared groups. The lower the score, the healthier the project (same scoring/Green-Yellow-Red concept covered in the Auto Grouping module).

Recent Activity pane

An activity log of recent events in the project — filterable to 'Assigned to me' to show just your own recent activity — with each entry linking directly to the associated test or object, so you can jump straight to what changed.

Together these panes give quick access to prioritize work, identify tests that need updating, review recent changes, and see open pull requests — all without navigating away from a single dashboard view.

Turbo Mode: faster feedback

What Turbo Mode does

Runs Testim tests up to 30% faster by ignoring step delays and only saving test artifacts (screenshots, logs) for failed runs rather than every run — trading some artifact detail on passing runs for materially faster feedback.

Enabling Turbo Mode

Can be turned on two ways: via the CLI with the --turbo-mode flag, or for scheduled runs, by sliding the 'Run in turbo mode' toggle in the Scheduler. Turbo Mode runs execute in extension mode only, on Chrome and Edge Chromium.

Capturing a video for a bug scenario

Prerequisite: the Testim Chrome Extension

Capture Video & Bug Scenario is a feature of the Testim Chrome Extension — it must be installed before any video capture is possible. Once installed, you can capture an issue as a Screenshot or as a Video & Bug Scenario directly from the browser.

Publishing the capture

After capturing, clicking Publish sends the video/screenshot — along with an automatically-generated 'steps to reproduce' description — to a connected bug tracker (Jira, Slack, Trello, GitHub, etc.). Within Testim itself, the captured video is saved to the test results section of the relevant test run, keeping the artifact attached to the context it was captured in.

Quarantine and CI/CD: what actually happens to a quarantined test

Quarantined tests are skipped in CI/CD, not run

A test marked Quarantine (unstable/flaky, generating errors) does NOT run as part of a normal CI/CD execution — it still appears in the suite run with a quarantine indication, and is recorded in the run's result XML with a 'Skipped' flag, rather than being executed.

Why quarantine this way

This lets a team quarantine a flaky/failing test without removing it from the CI/suite entirely — the test stays visible (so it's not forgotten), doesn't fail the overall build, and can be gradually re-added to real execution once fixed. A CLI override, --run-quarantined-tests, exists for the rare case where you deliberately want quarantined tests to run anyway.
