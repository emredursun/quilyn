Loops in Testim: six repeat-group types

Where a loop lives

A loop is a setting on a group step (folder icon) — the group's contained steps are what gets repeated. The loop type is chosen from a radio-button list on that group, and the default is Don't repeat: the group's steps run exactly once, with no repetition at all.

For each item, in depth

'For each item' loop

Runs the same set of actions/validations against similar, repeating elements — the canonical use case being a table with multiple rows where every row needs the same check applied. Rather than writing one validation step per row, a single group of steps is looped. Configure it by selecting 'For each item', clicking the first repeating element, and optionally adjusting the item limit (default 99).

TESTIM_ITERATOR

An out-of-the-box parameter that tracks the current loop iteration's value. Each time the loop runs, TESTIM_ITERATOR increases by one, letting steps inside the loop reference 'which iteration am I on' — for example, to build a row-specific selector or to log progress. This applies across loop types, not just For each item.

Condition-based and fixed-count loops

While element / While element text is

While element repeats the group only as long as a chosen element is (or isn't) present — set via the Visible/Not visible condition. While element text is is the same idea, but the condition is a text match against the element (Expected value field, with regex/JS support) rather than plain visibility. Both are configured by selecting the loop type, clicking the target element, then setting the condition.

Loop for

Runs the group a fixed number of times — either a literal number typed in directly, or a parameter holding a number, capped at a maximum of 99. Unlike For each item, this doesn't depend on matching elements on the page at all; it's a pure iteration count.

Custom

For loop conditions that don't fit any of the built-in types, Custom lets you define the condition as a JavaScript function — with optional JS/HTML parameters passed in, and its own timeout override separate from the test's general settings.
