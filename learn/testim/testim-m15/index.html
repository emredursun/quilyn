Hooks: running a shared step/group before or after something

Hook

Test Configuration hooks call an existing shared step/group at configured step/test boundaries. Create or edit the configuration and apply it to the relevant tests; creating a configuration alone does not attach it to every test.

Before each step / After each step

Per-step handlers attach before/after steps. After handlers have Run on choices (Always, Success, Failure), so they are not unconditional in every configuration. Hooks can still run around a step skipped by its own condition; distinguish that condition from the hook’s Run on selection.

Configuration File run hooks

A separate, CLI/config-level mechanism: the Configuration File can define run hooks used to set up the application backend and define parameters before/after a single test or before/after all tests in a run — useful for environment-level setup/teardown that isn't tied to any one specific step.

Editor-level Hooks operate at the step/test granularity inside the visual editor; Configuration File hooks operate at the run/suite granularity from the CLI config — both exist so setup/teardown logic doesn't have to be manually duplicated at the start/end of every test.

When to recognize a hook is the right tool

Choose the mechanism for its runtime and lifecycle scope. Shared code reduces duplication, but the hook still requires applicable configuration, dependencies and outcome checks.
