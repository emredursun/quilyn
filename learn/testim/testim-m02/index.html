The target element and its Properties panel

Target element

The target element is the element that was selected in the AUT (Application Under Test) browser as the main element for a step. It is shown as a thumbnail image in the step's Properties panel, and it is fully editable after the step has been recorded.

Opening the Properties panel

Hovering over any step in the test and clicking Show Properties opens the Properties panel on the right-hand side. From there, hovering over the target element thumbnail reveals four options: Highlight, Reassign, Improve, and View locators.

Editing step properties (not just the target element) is also how you rename a step, edit the value a step enters, or adjust timing/behavior settings — all part of what 'editing tests' covers beyond re-recording from scratch.

The four Target Element options

Highlight

Opens the AUT browser with the target element momentarily highlighted in pink. It changes nothing — it exists purely so you can visually confirm, during editing, that the correct element is targeted for a step.

Reassign

Replaces the target element with a completely different element from the AUT: the system removes and overrides all existing locators for that step. Use it when the original element no longer exists at all — for example, a blue 'Login' button was removed and replaced by an entirely different control.

Improve

Used when the SAME target element still exists but the DOM around it changed. Testim compares the existing locators to newly collected ones and updates (merges into) them rather than overriding them — examining which selectors changed, which stayed the same, and which disappeared. Example: the 'Login' button is still the same button, but its text changed from 'login' to 'LOG-IN' and its color changed. Improve — not Reassign — is the correct choice here, because it is the same element, not a different one.

View locators

Opens the Locators panel, showing exactly how Testim's Smart Locators identify the target element and its parent elements. Testim's algorithm inspects potentially hundreds of attributes on an element, assigns each a weight, and uses the highest-weighted ones to find the element on future runs — so if some attributes change, the Smart Locator can still find the element using the others.

Specialized step properties

Expected value

The value Testim checks for when the step runs (used by Validate element text, Validate CSS property, Validate HTML attribute, Wait for element text). It's editable after the step is created, and — importantly — it isn't limited to a literal string: Parameters, regular expressions, and JavaScript expressions can all be used in the Expected value field.

Expected status (checkboxes / radio buttons)

Used by Validate checkbox and Validate radio button to set whether the step expects Checked (the default) or Unchecked. These validations only work on native checkbox/radio input elements — a custom checkbox implementation that doesn't use an underlying native input isn't supported.

Add Prefix / Add Suffix / String type / Length

Properties of a Generate random value step. Add Prefix/Suffix attach a fixed string to every generated value (e.g. prefix 'User' → User47, User65, User32). String type controls whether the generated value uses letters only, numbers only, or both. Length sets how long the generated value is.

Date format / Time difference / Use UTC

Properties of a Generate date step. The default date format is 'YYYY-MM-DD', but it can be changed to any JS date format. Time difference offsets the generated date/time before or after the current browser time (or UTC). Use UTC switches the reference time zone from the browser's local time to UTC.

Extract Mode

On an Add extract value step, Extract Mode controls what data type is pulled from the matched text — by default the entire string, but it can be narrowed to a number, a date, or a regular-expression match for just part of the text. Even when extracting a Number/Date/Regular-Exp, the resulting extracted value is still stored as a string.

Variable name and Variable scope

Add extract value step, Get cookie, Generate random value, and Generate date steps all store their result in a variable — Variable name sets what that variable is called (subject to JavaScript naming rules: no spaces or special characters). Variable scope controls where it can be referenced: Local (within the same group, or the same test if declared at test level), Test (the default — across steps and groups in the same test), or Suite (across tests in the same test suite).

Native events (Click step)

A Click step can be configured, at the project level, to fire as a Native event (the browser's real, built-in click-handling pipeline — what happens on an actual mouse click or tap) or a Non-Native event (a synthetic/programmatic click dispatched via JavaScript, simulating the interaction). If a Click step reports as passed but the click visibly didn't do anything in the AUT, toggling the Native events checkbox is a standard troubleshooting step.

Pre-step delay (ms)

Available on Validate element not visible and Wait for element not visible. By default there's no delay, but you can set one (in milliseconds) to first wait before checking that an element is absent — useful when you want to make sure an element doesn't suddenly appear a moment later, not just that it's absent right now.

Sleep duration

The property of a Sleep step — how long (in ms) the test pauses before the next step. The default is 1 second (1,000 ms), and it's directly editable.

+PARAMS

Available on custom/API/network steps (Add custom action, Add API action, Add custom validation, Validate API, Add network validation, Add custom wait for). Clicking the + next to PARAMS lets you define HTML and JS parameters for the step, so it can be reused to test different scenarios without hardcoding the values in advance.

Auto complete

While recording a test, Testim watches for a match against your existing Shared Groups and suggests them as the next steps — a pop-up labeled 'Auto record your steps' appears above the steps counter listing the matching suggestions. Clicking a suggestion has Testim automatically perform and save those steps in the test being recorded, instead of you re-recording a sequence you've already built elsewhere. If the matched group has parameters, you're prompted to name them and supply values before the steps are added. This feature is available on the professional plan.

Replace with a clone / See old revisions

Replace with a clone detaches a step from a Shared Step so an edit affects only this one test, instead of every test using that shared step. See old revisions opens the list of automatically-saved prior versions of the test (change message, user, date) whenever a change is saved — including changes to a shared step — letting you inspect or revert to an earlier revision.

Reusable editing: groups and Shared Steps

Groups

Steps can be grouped together, and groups can be nested inside other groups. A group is identified in the test by a folder icon in its upper-left corner.

Shared Steps / Shared Group

Selecting the Shared Group checkbox on a group makes it callable from other tests in the project — not just copy-pasted, but referenced, so a single edit to the shared group propagates to every test that uses it. This is the core mechanism for reusable, maintainable test authoring (e.g. a login sequence built once and reused everywhere).

Groups can take parameters (variables). When a group is shared across multiple tests, those parameters stay available in every test that calls it — each caller just supplies its own values instead of duplicating the underlying steps.

Shared Steps Library

A dedicated library view listing every shared step, group, and folder in the project, with four columns: Name, Date Modified, Kind (shared step / group / folder, plus the underlying step type), and Used by (a clickable count of how many tests reference that item — clicking it navigates to the Test Library filtered to just those tests). The library can be filtered by category: Groups, Actions, Validations, and Wait for.

Labels

A lightweight organizational tool applied to tests in the Test Library, letting you categorize and quickly find tests without moving them between folders. A test can carry multiple labels at once (e.g. 'smoke', 'checkout'), and the library can be filtered or searched by label — useful once a project's test count grows past what folders alone can keep navigable. (Covered in more depth, alongside folders and dependencies, in the 'Advanced test management' module.)
