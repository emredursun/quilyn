Creating a basic test by recording

The AUT browser

Creating a test starts by navigating to the relevant website inside the Application Under Test (AUT) browser window and recording the series of actions you want tested — clicks, text entry, scrolling, navigation. Testim captures each action as a step.

Steps

Recorded actions appear as individual steps with action-type icons. Execution follows the configured sequence; edit the test as needed rather than assuming the original recording order is permanent.

The basic recording workflow needs no user-written script. Add outcome validations and edit supported step properties or sequence when the test requires them.

Smart Locators and identification resilience

Smart Locators

Testim identifies targets using many weighted attributes and can improve identification across runs. Other useful attributes may preserve a match after a change, but resilience does not guarantee success or the correct target in every changed UI.

Inspect the actual target and asserted outcome after UI changes. Improve updates identification of the existing target; Reassign selects a different target and replaces its locators. Neither replaces business-result validations.

Saving a test and viewing results

Saving

Save the named test in the project library. Editor, CLI and scheduling provide different execution paths; available configuration and permissions still govern a run.

Viewing results

Inspect executed-step statuses and available error details, including expected and actual validation values. Failure evidence supports diagnosis but is not a guarantee that the root cause is already identified.
