Keyboard Shortcut steps

Add Keyboard Shortcut step

Add Keyboard Shortcut sends a supported combination to the AUT. Windows/Mac fields synchronize equivalent shortcuts by default; Unsync Fields permits separate combinations. Inspect the effective test configuration OS rather than assuming the host OS always wins.

Setting the shortcut in Properties

In Properties, press the combination in the applicable Windows or Mac field. The opposite field receives the default translation; use Unsync Fields when the intended combinations differ. A conflicting test-configuration OS governs which command is sent.

Unsupported combinations

Unsupported combinations produce an unsupported keyboard shortcut error. Inspect failure handling rather than inferring that the entire test must always stop or always continue.

Parameters: flexible test step customization

Why parameterize

Parameters let a step or group be customized per use — passing in different information without knowing every value in advance — so the same underlying steps serve multiple scenarios instead of being copy-pasted with small edits each time.

Parameter override rules

Before execution, config-file values override params-file values, which override default test/run data; beforeTest overrides beforeSuite within the config file. During execution, scope and later assignments matter: a more local same-name parameter can shadow a broader one. This is not a universal parameters-always-win rule.

Extract Value: capturing data for later steps

Extract Value step

Extract Value captures selected AUT element text. Extract Mode chooses the whole text or number/date/Regex matches; individual matches remain strings and all-matches modes can return arrays. Selecting a mode does not guarantee a JavaScript number/date type.

Email/SMS retrieval uses its own supported message workflow. Extract Value is not a universal connector to every source. Keep message/content assertions separate from extracting one useful value.

Wait for Events: synchronizing tests with the application

Waiting for an event, not a fixed time

Use the supported wait for readiness such as element visibility, text or a completed download, with a bounded step timeout. Wait for Download uses the documented scripted completion check; adding the step alone does not configure every possible file condition.

Wait for element visible / not visible

Visible waiting is available for web and mobile; documented not-visible waiting is web-only. Prepare the relevant AUT state before targeting. Visibility is not merely DOM presence, and absence from view does not necessarily mean removal.

Changing the element after the fact

Use Reassign when the required target is different. If the same element still exists with changed identification, consider Improve. Validate the wait condition and timeout; extending time alone does not fix a wrong target.
