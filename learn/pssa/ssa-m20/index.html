Activities

Choose the right mechanism

Activities run ordered steps for procedural processing. Prefer a suitable out-of-the-box automation, Data Transform or specialized rule before custom activity code. Activities increase maintenance cost; a requirement for an activity should be explicit rather than a default for every data update.

Worked example: Use a Data Transform for a simple address mapping. Use an appropriate standard automation for a supported case action; justify any custom activity with a missing specialized mechanism.

Activity structure

Choose the right mechanism

An activity step specifies a method, parameters and optional step page. The step page supplies the data context; Pages & Classes declares page/class references. Preconditions, loops and transitions control execution. Call returns to the caller; Branch transfers execution without returning to subsequent caller steps.

Worked example: An activity loops through embedded Item pages, setting the step page to the current item. A Call to validation returns for later processing; a Branch is appropriate only when the caller must not resume.

Declare OnChange Rules

Choose the right mechanism

Declare OnChange watches configured property changes and can execute activities or suspend work through a business-exception condition. Its trigger is a change, unlike a Declare Expression's derived-value dependency. Keep frequently triggered processing small and guard it with suitable conditions.

Worked example: When a RiskScore changes above a threshold, an OnChange condition triggers the appropriate investigation activity. Test repeated changes and ensure the activity does not create an unintended change loop.
