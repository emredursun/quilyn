Parallel processing in Pega applications

Choose the right mechanism

Independent stage processes can run concurrently. Split Join coordinates different subprocesses; Split For Each repeats one subprocess over a page list or page group. A spinoff lets the parent continue without joining back.

Worked example: A facilities request needs a safety assessment and a budget assessment. They are different processes and can run concurrently; the parent joins after both finish.

Running multiple instances of the same subprocess with a Split for Each shape

Choose the right mechanism

Use Split For Each when each eligible list/group item needs the same subprocess. Choose a join rule deliberately: All waits for every branch; Any continues after one completes and cancels remaining open assignments. Iterate processes qualifying pages sequentially.

Worked example: A delivery has a page list of packages. Run one inspection subprocess for each package and wait for All before dispatch.

Running multiple instances of different subprocesses with a Split Join shape

Choose the right mechanism

Split Join starts different subprocesses and resumes according to All, Any or Some join criteria. Some can express a completion count or condition; do not silently assume every branch must finish.

Worked example: Three specialist teams assess one proposal; the business needs two completed assessments. A Some join expresses the threshold.

Adding additional configuration to a subprocess

Choose the right mechanism

Subprocess configuration controls the flow, page context and parameters. Review locking when branches share a case. A subprocess invoked on an embedded page must use that page's class and data rather than an unrelated top-level context.

Worked example: An inspection flow runs on each Package page and receives an inspection-level parameter. Test that edits affect the intended package and that concurrent case saves are handled.
