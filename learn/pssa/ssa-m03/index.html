Application and production Rulesets

Decision rule

Rulesets package related Rules. Application Rulesets define application behavior; organizational Rulesets support reuse. Int conventionally groups integration Rules. Production Rulesets support controlled maintenance in production, including delegation; keep a version unlocked and give intended operators access through their Access Groups.

Worked example: Compliance staff maintain a delegated threshold in PolicyProd. Keep its editable version unlocked and configure the application plus the authorized Access Group.

Ruleset validation

Decision rule

AV validates references against the defining application and its built-on stack. RV uses explicit version prerequisites and their prerequisites; prerequisite cycles are invalid. Validation happens at design time, not as runtime ranking. Use RV for portable shared assets. Revalidate after changes to built-on applications or the Ruleset list.

Worked example: An RV integration module cannot reference a consumer-specific Rule merely because one developer can run that consumer. Its prerequisites must supply the dependency.

The Ruleset list

Decision rule

At login, Pega starts from the Access Group’s versioned application and walks its built-on applications to assemble the runtime stack. Higher entries have precedence within Rule resolution. Eligible developers also get a personal Ruleset for checked-out Rules at the top. Inspect Operator Profile when two users see different behavior.

Worked example: User One checks out a Rule; User Two does not. Compare their stack contexts before blaming the released Rule.
