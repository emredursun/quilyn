Class hierarchy structure

Decision rule

Place assets at their reuse scope: enterprise-wide → Organization; regional or brand-wide → optional Division; unit-wide → optional Unit (requires Division); a specific business application → Implementation. Platform supplies the foundation. Constellation starts with the Data Model and generates a prescribed experience; its design system, architecture, DX API and business engine have distinct roles.

Worked example: Shared address lookup belongs to a reusable scope; a single-brand returns policy belongs to that brand. Decide who consumes an asset before choosing its layer.

Modular architecture and Enterprise reuse

Decision rule

Keep Enterprise lean. Put reusable customer data, single-system integration and utility capabilities in modules; place workflow-specific Cases in business applications. Specialize geographic or segment differences in innovation applications. Reuse modules through built-on applications or the wizard. Prefer parameters, extension points and Configuration Sets to copies; shared changes affect consumers.

Worked example: A document conversion service can be one utility module consumed by Claims and Lending. Put workflow-specific decisions in the consuming business application.

New Pega Platform applications

Decision rule

Blueprint captures a collaborative application design: Case Types, lifecycle, data and Personas. App Studio’s New Application wizard turns an existing or newly created Blueprint into an initial application. Treat generated design as a starting point to review against requirements. Reusable designs speed repeated application creation.

Worked example: A team agrees a Warranty Blueprint, reviews its Case lifecycle and data, then uses the wizard to create the application. A design import still needs implementation and validation.
