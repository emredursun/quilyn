Circumstancing

Decision rule

Keep normal behavior in a base Rule and implement focused exceptions as variants. Rule resolution chooses the applicable behavior without duplicating the whole Process. Use this when the same Rule purpose needs situational differences.

Worked example: A shipping policy needs one exception for a particular service tier. Specialize the policy Rule instead of copying every shipping Step.

Circumstance Rules

Decision rule

Choose by the requirement: one property → single-variable; a combination → multi-variant; a Case date → date-property; today’s date/time → as-of. If no eligible variant matches, normal behavior comes from the base Rule.

Worked example: Choose the clock: an old claim may follow its incident date even today; a seasonal offer follows today’s date.

  • Official topic

Single-variable circumstancing

Decision rule

Specify a property and matching value for one-variable exceptions. A date property evaluates Case data; as-of evaluates system time. A higher accessible Rule marked Base resets earlier instances in the same major with lower minor/patch versions. Withdrawing a circumstanced instance removes that variant, not every sibling. Inspect variants in Application Explorer or the Rule header.

Worked example: To retire one region’s exception, withdraw that variant and test the remaining base. To reset earlier specializations, review the later Base flag and its version scope.

  • Official topic

Multi-variant circumstancing

Decision rule

The template declares the properties to evaluate; a definition supplies conditions for their values. Attach the template/definition to a specialized Rule. A template alone does not provide the exception’s matching values. Test matching and nonmatching combinations.

Worked example: Template: Region and EmploymentType. Definition: Region=NL and EmploymentType=Contractor. A separate definition supplies another exception; unmatched combinations use the base.
