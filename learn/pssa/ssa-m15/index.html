Connectors and services

Choose the right mechanism

A connector lets Pega call an external system; a service lets an external caller invoke Pega. Choose the direction first, then protocol, authentication, mapping and failure behavior. SOAP uses a WSDL contract; REST integrations use HTTP resources and operations.

Worked example: A claim needs a repair estimate from a vendor: Pega calls the vendor with a connector. If the vendor creates a claim in Pega, the inbound request uses a Pega service/API.

External data sources for data types

Choose the right mechanism

A Data Type can use a local Pega system of record, transient case data, or an external source. External-source configuration creates connector and mapping assets. Parameterize requests, map response fields, use authentication profiles and vary endpoints by environment rather than copying hard-coded production URLs.

Worked example: A D_Customer page passes CustomerID to a REST service and maps the returned name and contact fields. Test Dev and Production endpoint settings and reject a mismatched response.
