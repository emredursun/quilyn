Role-based access control (RBAC)

Choose the right mechanism

Authentication establishes identity; authorization determines allowed operations. An Access Group selects application access and roles. RBAC assigns capabilities through roles, Access of Role to Object rules and privileges. Hiding a button alone is not server authorization.

Worked example: A service representative can update customer requests, while a supervisor role has a separate approval privilege. Check direct action calls as well as portal visibility.

Permission inheritance and dependent roles

Choose the right mechanism

Dependent roles reuse standard permissions while allowing targeted overrides. Parent-class permissions can be inherited by child classes. Inspect explicit grants/denials and dependent-role order; do not treat permission inheritance as an unconditional union of all permissions.

Worked example: Start from the standard user role and override only the permission needed for a specialized case class. Test both the explicit override and inherited operations.

Attachment categories

Choose the right mechanism

Attachment categories organize documents and restrict attachment actions through privileges, When conditions and applicable team constraints. All configured When conditions must be true; at least one required privilege must be held. Use When rules for category conditions, not Access When rules.

Worked example: Keep incident photos and restricted financial documents in separate categories. Grant read access to the intended role and verify create/edit/delete independently.

  • Attachment categories

Attribute-based access control (ABAC) security model

Choose the right mechanism

ABAC supplements RBAC by comparing operator and object attributes for granular access. An Access Control Policy identifies the controlled action; an Access Control Policy Condition expresses the decision logic. Evaluate row and property restrictions in every relevant access path.

Worked example: Only investigators whose region matches a case may read it. Compare operator region and case region in a policy condition, then apply the read policy.

  • Attribute-based access control (ABAC) security model

Client-based access control

Choose the right mechanism

CBAC supports client requests to inspect, correct or erase their own personal data through a request-management application and participating repositories. Configure the permitted data and operations; CBAC is not ordinary role authorization or proof of legal compliance by itself.

Worked example: A customer submits a correction request through the designated request-management flow. Validate identity, locate the configured personal data and apply the permitted correction.
