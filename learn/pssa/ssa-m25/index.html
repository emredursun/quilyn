Extensions to the Constellation UI

Choose the right mechanism

Prefer configured Constellation portals and existing view patterns before custom frontend code. Choose the smallest extension that meets the need. A custom portal experience remains governed by the application's case rules and authorization; grouping related information should preserve useful labels and validation.

Worked example: A team needs a task-focused portal and grouped contact details. Start with supported portal/view configuration; do not implement a custom design system solely to rearrange a form.

Constellation Web embed

Choose the right mechanism

Web Embed inserts a Constellation case or page experience into an existing website through generated HTML web-component markup. Configure a Web Embed channel and supported theme options. It uses Constellation rendering rather than giving arbitrary control over every UI implementation detail.

Worked example: A retailer adds a service-request form to its existing website with a Web Embed channel's generated markup and supported branding settings.

Constellation DX Components

Choose the right mechanism

Constellation DX components extend the component library with purpose-specific React components integrated into App Studio view authoring. Use supported APIs and package the component for Pega; only customize when existing patterns do not meet a justified requirement.

Worked example: A specialist visual field cannot be expressed by the existing library. Build a supported DX component, upload/package it and verify authoring plus runtime behavior.

  • Constellation DX Components

Constellation SDKs

Choose the right mechanism

Constellation SDKs connect Constellation orchestration to alternative design systems and supported frontend frameworks. They reduce work compared with hand-building every orchestration step, but a custom presentation still needs development, testing and upgrade maintenance.

Worked example: A company must use its own React design system. Use the appropriate SDK with the Constellation engine, while keeping case workflow and action metadata governed by Pega.

  • Constellation SDKs

The Constellation DX API

Choose the right mechanism

The Constellation DX API is a model-driven REST interface exposing case data and view metadata. It uses OAuth 2.0. Preserve response eTag and send it as If-Match on updates to protect against stale writes. Handle conflicts by refreshing and reconciling; do not bypass concurrency checks.

Worked example: Fetch assignment action details, render the returned metadata, submit content with the last eTag as If-Match, and refresh when an intervening save causes a conflict.
