Application Settings feature

Choose the right mechanism

Application Settings externalize environment-dependent values such as endpoint addresses and resource settings. Configure typed settings and useful categories, reference them from integrations, and resolve the appropriate environment values at runtime. Avoid hard-coded QA URLs in migrated rules; settings are configuration, not permission to expose secrets.

Worked example: A shipping connector uses an endpoint setting with separate Development, Staging and Production values. After migration, verify both the selected environment and the resolved address using a synthetic test request.
