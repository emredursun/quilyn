Performance testing tools

Choose the right mechanism

Measure a reproducible operation before changing configuration. PAL summarizes requestor resource consumption; Database Trace examines SQL; Performance Profiler traces procedural rule execution; PDC aggregates runtime health. Choose the tool for the evidence required.

Worked example: For a slow address form, first capture PAL around opening that form. If database time dominates, narrow the investigation with Database Trace rather than collecting every available trace.

The Performance Analyzer (PAL)

Choose the right mechanism

PAL uses continuously collected statistics with little additional collection cost. Reset before a focused scenario and take incremental readings around individual interactions. DELTA readings isolate changes; TOTAL reflects accumulated work. Compare equivalent warm/cold runs rather than unrelated totals.

Worked example: Reset PAL, open the lookup form, add a reading, submit it and add another reading. Compare the expensive DELTA with the same scenario after optimization.

The Database Trace

Choose the right mechanism

Database Trace records database operations, timings and related details. Use targeted short traces because collection adds overhead. Investigate expensive queries and commits in context; stack traces add further cost and should be collected only when needed.

Worked example: Trace one slow search, stop immediately, sort by elapsed time and inspect the most expensive statement's predicate and execution plan.

Performance Profiler tool

Choose the right mechanism

Performance Profiler records activities, Data Transforms and When rule execution. It adds substantial overhead. Start, reproduce, stop and analyze; separate inclusive time from time excluding called children to avoid double-counting cost.

Worked example: Profile a suspected mapping activity, then compare its own CPU time with the time spent in called processing. Do not add both inclusive totals as if they were independent.

Pega Diagnostic Center introduction

Choose the right mechanism

Pega Diagnostic Center provides aggregated application health, alerts and trends. Correlate events for the same time and interaction, prioritize recurring issues, and confirm improvements after a change. Monitoring evidence supports diagnosis but does not automatically repair every application defect.

Worked example: A deployment increases repeated slow-query alerts. Correlate the deployment time and affected interaction, diagnose the query and verify that the event rate drops after correction.
