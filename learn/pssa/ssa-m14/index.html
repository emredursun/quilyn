Keyed Data Pages

Choose the right mechanism

A keyed Data Page selects embedded records from one cached list using configured keys, reducing repeated source calls for individual items. Keyed access is supported for read-only pages with thread or requestor scope. Define keys, uniqueness and refresh strategy; keyed access is not a guarantee that a stale or incomplete source list contains every current record.

Worked example: A requestor-scoped product list is loaded once, keyed by ProductID, and supplies details for multiple selections. Refresh the list when the business requires newer catalog data; compare connector calls before and after the change.
