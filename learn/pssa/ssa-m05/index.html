Rule resolution

Decision rule

Rule resolution chooses behavior for a purpose in the current requestor context. A Rule being saved in the database does not make it accessible or the winner. Diagnose the class, runtime Ruleset stack, version, circumstance and availability together.

Worked example: A newer Rule that exists only in an inaccessible Ruleset cannot win for this operator. Start with context, not the database’s latest version.

Rule filtering by purpose

Decision rule

Purpose combines Rule name and Rule type. Candidate filtering excludes Not Available instances, inapplicable Rulesets/versions and classes outside the inheritance path. Do not compare version numbers until the candidates are eligible.

Worked example: CalculateFee as a Decision Table is not the same purpose as CalculateFee as an Activity. Match both name and type.

Remaining Rule candidates and ranking

Decision rule

Ranking considers class, Ruleset, circumstance/date qualifiers and version. An unqualified default provides fallback; lower-ranked candidates below it are discarded. Withdrawal removes matching same-class/purpose instances at or below its version in its Ruleset, while eligible other scopes remain. The cache retains candidates for later selection.

Worked example: Two eligible candidates in the same class differ by circumstance and version. A later ordinary base does not automatically erase an older qualifying variant.

The Rule resolution process

Decision rule

Check the cache, build candidates on a miss, find the best matching eligible circumstance or default, then check blocking and authorization. Equally correct matches cause a duplicate-Rule error. A candidate being cached does not guarantee it runs.

Worked example: If two candidates are equally correct, resolve the ambiguity; do not assume the system selects whichever was saved last.

Rule resolution process and Rule availability

Decision rule

Available can run. Final can run but prevents same-name overrides in another Ruleset; a higher version in its own Ruleset is the exception. Not Available is skipped. A selected unqualified Blocked Rule stops execution. Withdrawn suppresses its matching earlier scope and allows other eligible fallback. Circumstanced Blocked/Withdrawn variants are excluded while remaining siblings can be considered.

Worked example: For an ordinary Rule: Not Available skips the instance; Blocked halts if selected; Withdrawn removes the defined earlier scope. Inspect qualifiers before applying the ordinary-rule case.
